프락시움의 첫 알파 사전 릴리스입니다. **운영 환경에서는 쓸 수 없습니다.** 인증은 개발용 토큰뿐이고, API와 데이터 형식은 예고 없이 바뀔 수 있습니다.

## 처음 해 볼 것

1. 아래에서 자기 운영체제에 맞는 파일을 받고 `SHA256SUMS`로 확인한 뒤 압축을 풉니다. 실행 파일 하나에 웹 UI가 들어 있습니다.
2. `praxium demo`를 실행하고, 터미널에 출력된 주소를 브라우저로 엽니다. 합성한 데이터센터를 둘러볼 수 있습니다.
3. 자기 파일(엑셀, CSV, JSON Lines)을 넣어 보려면 `praxium ingest init -out ex`를 실행하고 출력되는 안내를 따릅니다. 예제 정의와 샘플 파일이 만들어지고, `ingest inspect` → `ingest run -data-dir data …` → `praxium local -data-dir data` 순서로 진행합니다.
4. 모든 명령에 `--help`가 있습니다.

실행 파일에는 서명이 없습니다. 맥은 처음 실행할 때 차단될 수 있고(`xattr -d com.apple.quarantine ./praxium`), 윈도우는 SmartScreen 경고가 나올 수 있습니다.

## 들어 있는 것

- 표준 모델(객체·링크·액션 타입)과 합성 데이터센터 생성기
- 데모 모드(`praxium demo`)와 로컬 모드(`praxium local`)
- 엑셀(.xlsx), CSV, JSON Lines 파일 수집(`praxium ingest`)
- 실행 파일에 포함된 읽기 전용 웹 UI: 타입, 객체 테이블, 객체 상세(근거 등급 포함), 이웃
- 조회용 명령줄과 REST API(`kg`, `types`, `query find|get|neighbors`, `object`, `catalog`, `health`)
- 내장 파일 스토어(기본)와 PostgreSQL 스토리지

## 알려진 문제

릴리스 전에 독립 검증에서 확인한 것입니다. 다음 알파에서 고칩니다.

- 소스 정의와 매핑 정의(JSON)의 형식을 설명하는 문서가 릴리스 파일에 없습니다. `ingest init`이 만드는 예제가 출발점입니다. 타입에 허용되는 식별 키와 속성은 `praxium types get <타입> --json`으로 봅니다.
- 소스 정의의 시트 이름이 틀려도 오류가 나지 않고 그 데이터셋이 0행으로 처리됩니다.
- CSV는 UTF-8과 쉼표 구분만 읽습니다. EUC-KR(CP949)로 저장한 CSV는 경고 없이 깨진 글자로 읽힙니다. 엑셀에서 "CSV UTF-8"로 저장하거나 `.xlsx` 파일을 그대로 쓰십시오. 세미콜론·탭 구분 파일은 읽지 못합니다.
- 예제 매핑을 따라 수집한 객체는 화면의 "식별자"가 비어 있습니다.
- 식별 키가 맞지 않을 때의 오류가 허용되는 키를 알려 주지 않습니다.
- `praxium health`, `types get`의 표 출력에서 중첩된 값이 `{...}`로만 나옵니다. `--json`을 쓰면 보입니다.
- 선언하지 않은 컬럼이 있으면 `undeclared_column` 문제로 보고됩니다. 쓰지 않는 컬럼도 소스 정의에 선언해야 조용해집니다.
- 명령줄의 메시지와 도움말은 영어이고 웹 UI는 한국어입니다.
- 맥, 윈도우, arm64 실행 파일은 빌드와 체크섬만 확인했고 실행해 보지는 못했습니다.
