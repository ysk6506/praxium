# 지금의 순서

날짜는 두지 않는다. 모두 되는 대로 빨리 하고, 무엇이 먼저인지만 정한다. 위에서 아래가 순서다.

| 순서 | 무엇 | 상태 |
|---|---|---|
| 1 | **구조 세우기**: 하네스, 문서 뼈대, 바탕 부품, CI (ADR-0002) | 끝 |
| 2 | **저장소 설정**(저장소 밖, 제품 책임자가 한다): main 보호와 `gate` 필수. 저장소는 공개로 둔다(ADR-0004) | 보호 설정 대기 |
| 3 | **제품 목표 굳히기** | 끝 (ADR-0004) |
| 4 | **넘겨받은 쟁점에 답하는 설계**: [테라리움에서 넘겨받은 것](../../references/from-terrarium.md) 6절의 쟁점(일을 어떤 단위로 정하나, 맡기는 범위, 두 가지 맡김, 에이전트를 어떻게 돌리나, 실제 툴의 검증, 무엇을 고가용으로 두나)에 답하고, 넘겨받은 요구사항을 하나씩 다시 정해 요구사항 문서에 더한다 | 다음 |
| 5 | **이음매 맞추기**: 테라리움이 정하는 세계 스냅샷과 판정 기록의 형식을 따라, 내고 받는 시험을 건다 | 테라리움의 형식을 기다림 |
| 6 | **얇게 끝까지 한 줄**: 지어낸 소스 하나 → 운영 세계 → 스냅샷 → 테라리움에서 열기. 테라리움의 읽기 전용 창(넘겨받은 것 5절)을 출발점으로 볼 수 있다 | 대기 |

## 차수마다 지키는 것

- 변경은 풀 리퀘스트로 올리고 `gate`가 초록일 때 합친다.
- 바뀐 코드와 관련된 시험만 로컬에서 돌린다. 전체는 CI가 돌린다.
- 화면이 생기면 UX 측정 하네스를 테라리움에서 가져온다(TD-0002). 화면 변경은 캡처를 본 뒤에 합친다.
- 정리 작업(생성물 다시 만들기, 문서 감사, 작은 정리 하나)을 주기로 돌린다. 예약은 아직 걸지 않았다.
