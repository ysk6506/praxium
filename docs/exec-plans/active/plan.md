# 지금의 순서

날짜는 두지 않는다. 모두 가능한 한 빨리 진행하고, 무엇이 먼저인지만 정한다. 위에서 아래가 순서다.

| 순서 | 무엇 | 상태 |
|---|---|---|
| 1 | **구조 세우기**: 하네스, 문서 뼈대, 공통 기반 코드, CI (ADR-0002) | 끝 |
| 2 | **리포지토리 설정**(리포지토리 밖, 제품 책임자가 한다): main 보호와 `gate` 필수. 리포지토리는 공개로 둔다(ADR-0004) | 보호 설정 대기 |
| 3 | **제품 목표 굳히기** | 끝 (ADR-0004) |
| 4 | **KG 기반 설계**: 별도 제품(ADR-0005), 언어와 구조(ADR-0006), KG의 모델(ADR-0007), 수집(ADR-0008), 저장과 버전(ADR-0009), 질의(ADR-0010), 운영(ADR-0011), 권한(ADR-0012), 데이터 관측성(ADR-0013), 정의의 버전과 브랜치(ADR-0014), 역량 질문(ADR-0015), 화면은 다른 리포지토리(ADR-0016), 프락시움 자신의 관측성과 운영 가능성(ADR-0017), 시크릿과 암호화(ADR-0018). 인계받은 요구사항은 하나씩 다시 정해 [요구사항](../../product-specs/requirements.md)에 추가했다 | 끝 (ADR-0005~0018) |
| 5 | **뼈대와 합성 세계**: Go 백엔드의 구조와 하네스의 Go용 검사(ADR-0019), 타입 레지스트리와 표준 모델의 데이터 파일, 합성 세계 생성기 | 끝. Go 모듈과 `core.kernel`, 빈 `core.contract`, 시작점 `cmd.praxium`, 하네스의 Go 검사는 끝(ADR-0019). 타입 레지스트리 `core.model`과 표준 모델의 데이터 파일도 끝(ADR-0020). 합성 세계 생성기 `core.worldgen`과 `praxium worldgen`도 끝(ADR-0021, [설계](../../design-docs/worldgen.md)). 표준 모델을 영향 범위에 맞게 보강하는 교정도 끝(ADR-0022): 모든 타입에 식별 키(TD-0009 해소), 이중화 그룹을 객체로, `DEPENDS_ON`을 애플리케이션 서비스 사이로. |
| 6 | **계약**: OpenAPI 문서와 계약의 검사(서버와의 일치, 호환성을 깨는 변경, 품질), CLI의 뼈대 | 끝(ADR-0024). 계약 39개 경로(연산 42개) 구현(KG를 읽는 8개 경로가 ADR-0027로, 내장 인증의 관리 경로 7개가 ADR-0044로 옮겨 왔다), 172개 경로는 레지스트리에 단계별로 있다. 서버 골격, 개발용 인증과 내장 인증(TD-0010은 ADR-0044로 닫았다), 클라이언트 명령 `health`, `types`, `catalog`. `API*` 검사 |
| 7 | **수직 슬라이스**: 파일 소스 하나 → 수집 → 정제 → 피드 → 식별 → 링크 → 변경 배치 → KG → `find`/`get`/`neighbors`를 API와 명령줄과 임시 콘솔로. 여기까지가 **알파 1**이고 제품 책임자가 여기서부터 직접 사용해 본다 | 진행 중. KG의 중심(`core.graph`, 스토리지 포트, 적합성 테스트 `adapter.graphcheck`, 메모리 어댑터)이 구축됐다(ADR-0025). 사전 정의 질의의 첫 3종(`find`/`get`/`neighbors`)의 기준 구현이 구축됐다(`core.query`, ADR-0026). 첫 3종이 API(`/v1/kgs/{kg}`의 읽기 경로 5개와 질의 POST 3개)와 명령줄(`kg`, `object`, `query`)로 제공되고, 개발용 적재(`adapter.devload`, `praxium dev load-truth`, `api serve -dev-truth`)와 측정이 있다(ADR-0027). 파일 소스 하나(CSV, JSON Lines)의 수집 파이프라인이 구축됐다(`core.ingest`, `adapter.filesource`, `praxium ingest run`, ADR-0033). 엑셀(.xlsx) 소스와 파일을 살펴보는 `praxium ingest inspect`가 더해졌다(`adapter.xlsx`, ADR-0040). 스토리지 포트의 PostgreSQL 어댑터(`adapter.pgstore`)가 서고 `api serve -store postgres`로 고른다(ADR-0032, TD-0011을 닫았다). PostgreSQL 없이 처음 써 보는 용도로 내장 파일 스토어가 있다(`adapter.filejournal`, `api serve -store file -store-data-dir`, ADR-0034). 남은 것: 계약 검사 `API002`가 `find`/`get`을 차단하고 있어 설정에서 허용해야 한다, 수집의 REST 경로와 소스 레지스트리, 스케줄 |
| 8 | **수집 확장**(알파 2): HTTP JSON과 SQL 어댑터, 스트림 소스로서의 메시지 토픽, 여러 피드의 병합, 안전장치, 스케줄, 라인 템플릿 파서와 YAML과 매핑의 `suggest` | 대기 |
| 9 | **정의의 브랜치, 제안, 리버트와 권한** | 대기 |
| 10 | **영향 범위**: 프로젝션, 질의 엔진. 첫 작업은 설계의 의미를 모두 반영한 기준 구현이고 그것으로 생성기의 정답을 만든다. 합성한 100만 객체로 기능과 결정성을 테스트한다. 3천만 객체로 측정하는 일은 클로즈드 베타에서 한다 | 대기 |
| 11 | **관측성과 역량 질문, 프락시움 자신의 관측성과 운영 액션**(진단, 운영 액션, 설정, 운영 MCP 인터페이스) | 대기 |
| 12 | **알파 2**(확장): 수집 확장, 브랜치와 권한, 영향 범위, 관측성, 역량 질문, 자기 관측성의 핵심. 객체와 링크 100만 개 수준에서 모든 기능이 API와 CLI와 임시 콘솔(ADR-0016)로 돈다. 스토리지는 PostgreSQL이다. 계약의 플레이스홀더(필드, 경로, 코드 목록)만 알파에 두고 구현은 클로즈드 베타로 미루는 것: 목표의 소진율과 이상 탐지의 통계, 알림의 에스컬레이션, 운영 MCP 인터페이스와 `diagnose` 규칙 세트 전부(알파는 핵심 규칙만), 사용에서 올라오는 역량 질문, 비슷한 타입의 주기 계산, 시스템 KG를 운영 KG로 내보내기. 배포 정의 | 대기 |
| 13 | **클로즈드 베타**: 수천만 개 규모의 측정(합성한 3천만 객체, 규모 단계는 [기본값 표](../../design-docs/defaults.md)), 메시지 로그 스토리지 어댑터와 콜드 스토리지, 객체 조건의 읽기 권한, 외부로 내보내는 변경 알림의 메시지 토픽, 버전 관리와 로테이션과 비정규화한 기록, 정책에 의한 자동 병합의 낮은 등급, 수집기와 본체의 상호 인증 연결(실제 소스를 연결하는 때), 위 12번에서 미룬 구현들. 빈 장비 하나가 필요하다(제품 책임자에게 알렸다) | 대기 |
| 14 | **오픈 베타**(프로덕션에 나갈 수 있는 수준): 시크릿과 암호화 전부(ADR-0018), 프락시움 자신의 관측성과 운영(ADR-0017), 에이전트 환경의 정의 버전 관리(ADR-0014), PostgreSQL의 운영 수준(ADR-0009) | 대기 |
| 정식 | 오픈 베타 뒤 | |
| 그 뒤 | **프런트엔드 리포지토리(아직 없다)**, **엔드투엔드(E2E) 프로세스의 구체화**([방향 메모](../../design-docs/process-direction.md)). KG의 한 범위를 파일로 내보내는 일(REQ-136)은 알파 뒤다 | |

## 차수마다 지키는 것

- 변경은 풀 리퀘스트로 올리고 `gate`가 통과하면 병합한다.
- 변경한 코드와 관련된 테스트만 로컬에서 실행한다. 전체는 CI가 실행한다.
- 화면과 UX 측정 하네스는 프런트엔드 리포지토리(아직 없다)의 일이다(ADR-0016, TD-0002). 이 리포지토리의 알파는 모든 기능을 API와 CLI로 사용할 수 있는 것이다. 삭제할 수 있는 임시 콘솔만 이 리포지토리에 두고 클로즈드 베타가 끝나면 지운다(TD-0007).
- Go 코드는 하네스의 Go용 검사(ADR-0019)를 통과해야 병합한다. 유닛을 추가하는 변경은 `go:` 절과 ARCHITECTURE.md를 함께 수정하고, 모듈을 추가하는 변경은 ARCHITECTURE.md의 모듈 테이블도 수정한다. Go 테스트 함수도 보호되고 있고(ADR-0023) 테스트를 수정하려면 결정 기록의 `amends_tests`에 `go:<디렉터리>::<함수>` 키를 적는다.
- 정리 작업(생성물 재생성, 문서 감사, 작은 정리 하나, 테라리움 하네스의 변경 사항 알림)이 하루에 한 번 실행된다. 풀 리퀘스트로 제안만 하고 병합하지 않는다. 제목은 `cleanup:`으로 시작한다.
