# 지금의 순서

날짜는 두지 않는다. 모두 되는 대로 빨리 하고, 무엇이 먼저인지만 정한다. 위에서 아래가 순서다.

| 순서 | 무엇 | 상태 |
|---|---|---|
| 1 | **구조 세우기**: 하네스, 문서 뼈대, 바탕 부품, CI (ADR-0002) | 끝 |
| 2 | **저장소 설정**(저장소 밖, 제품 책임자가 한다): main 보호와 `gate` 필수. 저장소는 공개로 둔다(ADR-0004) | 보호 설정 대기 |
| 3 | **제품 목표 굳히기** | 끝 (ADR-0004) |
| 4 | **KG 기반의 설계**: 별도 제품(ADR-0005), 언어와 구조(ADR-0006), KG의 모델(ADR-0007), 받기(ADR-0008), 저장과 버전(ADR-0009), 질의(ADR-0010), 운영(ADR-0011), 권한(ADR-0012), 데이터 관측성(ADR-0013), 정의의 버전과 브랜치(ADR-0014), 역량 질문(ADR-0015), 화면은 다른 저장소(ADR-0016), 프락시움 자신의 관측성과 운영 가능성(ADR-0017), 비밀 값과 암호화(ADR-0018). 넘겨받은 요구사항은 하나씩 다시 정해 [요구사항](../../product-specs/requirements.md)에 더했다 | 끝 (ADR-0005~0018) |
| 5 | **뼈대와 지어낸 세계**: Go 백엔드의 구조와 하네스의 Go용 검사(ADR-0019), 타입 등록부와 표준 모델의 데이터 파일, 지어낸 세계 생성기 | 끝. Go 모듈과 `core.kernel`, 빈 `core.contract`, 시작점 `cmd.praxium`, 하네스의 Go 검사는 끝(ADR-0019). 타입 등록부 `core.model`과 표준 모델의 데이터 파일도 끝(ADR-0020). 지어낸 세계 생성기 `core.worldgen`과 `praxium worldgen`도 끝(ADR-0021, [설계](../../design-docs/worldgen.md)). 표준 모델을 영향 범위에 맞게 보강하는 교정도 끝(ADR-0022): 모든 타입에 식별 키(TD-0009 해소), 이중화 묶음을 객체로, `DEPENDS_ON`을 응용 서비스 사이로. |
| 6 | **계약**: OpenAPI 문서와 계약의 검사(서버와의 일치, 깨는 변경, 품질), 명령줄 클라이언트의 뼈대 | 대기 |
| 7 | **얇게 끝까지 한 줄**: 파일 소스 하나 → 수집 → 정제 → 공급 → 식별 → 링크 → 변경 묶음 → KG → `find`/`get`/`neighbors`를 API와 명령줄과 임시 콘솔로. 여기까지가 **알파 1**이고 제품 책임자가 여기서부터 눌러 본다 | 대기 |
| 8 | **받기를 넓힌다**(알파 2): HTTP JSON과 SQL 어댑터, 이어서 받는 소스로서의 메시지 주제, 여러 공급의 병합, 안전장치, 일정, 줄 틀 해석기와 YAML과 매핑의 `suggest` | 대기 |
| 9 | **정의의 브랜치와 제안과 되돌리기, 권한** | 대기 |
| 10 | **영향 범위**: 투영, 질의 엔진. 첫 일은 설계의 뜻 전부를 넣은 기준 구현이고 그것으로 생성기의 정답을 만든다. 지어낸 100만 객체로 기능과 결정성을 시험한다. 3천만 객체로 재는 일은 클로즈 베타에서 한다 | 대기 |
| 11 | **관측성과 역량 질문, 프락시움 자신의 관측성과 운영 행위**(진단, 운영 행위, 설정, 운영의 MCP 면) | 대기 |
| 12 | **알파 2**(넓히기): 받기 넓히기, 브랜치와 권한, 영향 범위, 관측성, 역량 질문, 자기 관측성의 핵심. 객체와 링크 100만 개 수준에서 모든 기능이 API와 명령줄 클라이언트와 임시 콘솔(ADR-0016)로 돈다. 저장소는 PostgreSQL이다. 계약의 자리(칸, 길, 코드 목록)만 알파에 두고 구현은 클로즈 베타로 내리는 것: 목표의 소진율과 평소와 다름의 통계, 알림의 넘기기, 운영의 MCP 면과 `diagnose` 규칙 묶음 전부(알파는 핵심 규칙만), 쓰임에서 올라오는 역량 질문, 비슷한 타입의 주기 계산, 시스템 KG를 운영 KG에 내보내기. 배포 정의 | 대기 |
| 13 | **클로즈 베타**: 수천만 개로 재기(지어낸 3천만 객체, 규모의 단계는 [기본값 표](../../design-docs/defaults.md)), 메시지 기록 저장소 어댑터와 오래된 것의 자리, 객체 조건의 읽기 권한, 밖으로 내는 변경 알림의 메시지 주제, 판과 돌려 쓰기와 풀어 쓴 기록, 정책에 의한 자동 병합의 낮은 등급, 수집기와 본체의 서로 확인하는 연결(실제 소스를 붙이는 때), 위 12번에서 내린 구현들. 빈 장비 하나가 필요하다(제품 책임자에게 알렸다) | 대기 |
| 14 | **오픈 베타**(프로덕션에 나갈 수 있는 수준): 비밀 값과 암호화 전부(ADR-0018), 프락시움 자신의 관측성과 운영(ADR-0017), 에이전트 시대의 정의 버전 관리(ADR-0014), PostgreSQL의 운영 수준(ADR-0009) | 대기 |
| 정식 | 오픈 베타 뒤 | |
| 그 뒤 | **프런트엔드 저장소(아직 없다)**, **E2E 프로세스의 구체화**([방향 메모](../../design-docs/process-direction.md)). KG의 한 범위를 파일로 내보내는 일(REQ-136)은 알파 뒤다 | |

## 차수마다 지키는 것

- 변경은 풀 리퀘스트로 올리고 `gate`가 초록일 때 합친다.
- 바뀐 코드와 관련된 시험만 로컬에서 돌린다. 전체는 CI가 돌린다.
- 화면과 UX 측정 하네스는 프런트엔드 저장소(아직 없다)의 일이다(ADR-0016, TD-0002). 이 저장소의 알파는 모든 기능이 API와 명령줄 클라이언트로 되는 것이다. 지울 수 있는 임시 콘솔만 이 저장소에 두고 클로즈 베타가 끝나면 지운다(TD-0007).
- Go 코드는 하네스의 Go용 검사(ADR-0019)를 통과해야 합친다. 단위를 더하는 변경은 `go:` 절과 ARCHITECTURE.md를 함께 고치고, 모듈을 더하는 변경은 ARCHITECTURE.md의 모듈 표도 고친다. Go 시험의 잠금은 아직 없어서(TD-0008) 시험을 고치는 변경은 리뷰가 지킨다.
- 정리 작업(생성물 다시 만들기, 문서 감사, 작은 정리 하나, 테라리움 하네스의 바뀐 것 알리기)이 하루에 한 번 돈다. 풀 리퀘스트로 제안만 하고 합치지 않는다. 제목은 `cleanup:`으로 시작한다.
