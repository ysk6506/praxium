# 지금의 순서

날짜는 두지 않는다. 모두 되는 대로 빨리 하고, 무엇이 먼저인지만 정한다. 위에서 아래가 순서다.

| 순서 | 무엇 | 상태 |
|---|---|---|
| 1 | **구조 세우기**: 하네스, 문서 뼈대, 바탕 부품, CI (ADR-0002) | 이 변경 |
| 2 | **저장소 설정**(저장소 밖, 제품 책임자가 한다): main 보호와 `gate` 필수, 공개 여부 정하기(ADR-0003의 5번) | 대기 |
| 3 | **제품 목표 굳히기**: 초안(ADR-0001)을 제품 책임자가 확인하고 고친다 | 대기 |
| 4 | **테라리움의 설계 가져와 다시 보기**: 보관함의 여섯 문서(현실 데이터와 모델, 소스 관리, 생김새 견본 시험, 파이프라인의 버전과 브랜치, 용어집, 워크플로 자동화)와 현실 연결 코드. 제품 설계 한 장 3절의 숙제부터 푼다 | 대기 |
| 5 | **이음매 맞추기**: 테라리움이 정하는 세계 스냅샷과 판정 기록의 형식을 따라, 내고 받는 시험을 건다 | 테라리움의 형식을 기다림 |
| 6 | **얇게 끝까지 한 줄**: 지어낸 소스 하나 → 운영 세계 → 스냅샷 → 테라리움에서 열기 | 대기 |

## 차수마다 지키는 것

- 변경은 풀 리퀘스트로 올리고 `gate`가 초록일 때 합친다.
- 바뀐 코드와 관련된 시험만 로컬에서 돌린다. 전체는 CI가 돌린다.
- 화면이 생기면 UX 측정 하네스를 테라리움에서 가져온다(TD-0002). 화면 변경은 캡처를 본 뒤에 합친다.
- 정리 작업(생성물 다시 만들기, 문서 감사, 작은 정리 하나)을 주기로 돌린다. 예약은 아직 걸지 않았다.
