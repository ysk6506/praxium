# 요구사항 — 수집

파일 소스 수집(110~129, 170번대와 이어서 정한 것), 엑셀, 식별과 갱신의 의미, DB와 API 소스와 수집 서비스(401, 411~417, 447, 477~494. 예정. 400과 403~410은 다른 변경이 쓴다), 수집의 규모 설계(633~657. 예정, ADR-0086), 어댑터가 쓸 수집 부품(658~660, ADR-0090), 소스에 붙는 연결의 방어(661, ADR-0091), 엑셀 시트를 행마다 읽는 스캐너와 행 파서(800~, ADR-0103, ADR-0104)의 요구사항이다. 목표와 REQ 번호의 규칙은 [요구사항 입구](requirements.md)에 있다. 번호는 모든 요구사항 문서에서 하나뿐이다.

| REQ-115 | **예정(ADR-0008)** 정제는 고정된 14종 연산으로 한다. 새 연산은 결정 기록으로만 추가하고, 사용자가 코드를 넣는 경로는 없다. |
| REQ-116 | **예정(ADR-0008)** 매핑과 링크 정의를 계층으로 나눈다. 링크는 고정된 6종 조건으로 연결되고 사람이 직접 연결하지 않는다. |
| REQ-117 | **예정(ADR-0008)** 원본 레코드는 최종적으로 사용됨, 규칙으로 필터링됨, 문제, 미사용 가운데 하나가 되고 넷의 합이 수집한 수와 같다. 단계마다 입력 수가 출력 수와 탈락 수의 합과 같다. |
| REQ-118 | **예정(ADR-0008)** 자동 적용 전에 안전장치가 중단시킨다: 불완전한 수집, 수신한 스키마 변경, 대량 소실, 첫 적용. 관측되지 않는 것은 바로 삭제하지 않는다. 기준 수치는 측정해서 정한다. 첫 적용, 정의 세트가 바뀐 뒤의 첫 적용, 불완전한 수집, 대량 소실은 REQ-416이 먼저 구현한다(ADR-0058). |
| REQ-120 | **예정(ADR-0008)** 위치·전원·냉방은 엑셀 양식으로, 행 하나에 장비 하나인 목록 형식으로 매핑 없이 수집한다. 격자 형태의 실장도는 읽지 않는다. |
| REQ-121 | **예정(ADR-0008)** 소스마다 스케줄을 관리하고, 동기화 한 번마다 단계별 건수와 시간을 이력으로 남기고, 지표와 로그를 발행한다. 로그에는 시크릿과 행의 내용이 없다. 스케줄은 ADR-0058이 뺀다. 실행 기록은 REQ-418이다. |
| REQ-122 | **예정(ADR-0008)** 객체와 링크의 값 하나가 어느 원본 레코드와 어느 규칙에서 왔는지 추적할 수 있다. |
| REQ-123 | **예정(ADR-0008)** 제품 밖의 수집기가 공개된 수집 엔벨로프로 원본 레코드를 보낼 수 있다. 수신한 뒤는 다른 소스와 똑같이 처리한다. |
| REQ-124 | **예정(ADR-0008)** 수집 방식은 소스마다 전체 수집, 증분 수집, 스트림, 스트림과 정합성 대조 4가지 중에서 선택하고, 소스와 데이터셋마다 스케줄을 관리한다. |
| REQ-125 | **예정(ADR-0008)** 정의 하나가 배치와 스트림에 똑같이 적용된다. 같은 원본을 한 번에 넣은 결과와 나눠서 스트림으로 넣은 결과가 같다. |
| REQ-126 | **예정(ADR-0008)** 객체는 피드가 속성 단위로 구축한다. 객체를 생성하는 피드와 속성을 보강하는 피드를 구분하고, 배치와 스트림으로 오는 속성이 섞여도 서로 덮어쓰지 않는다. |
| REQ-127 | **예정(ADR-0008)** 스트림의 안전장치가 발동하면 그 소스의 적용만 보류하고 수집은 멈추지 않는다. 운영 역할이 확인하고 해제하거나 폐기한다. |
| REQ-170 | **예정(ADR-0008)** 데이터셋과 피드에 고정된 종류의 기대 조건을 붙인다. 위반하면 적용을 중단하거나(`fail`) 문제 목록에 올린다(`warn`). |
| REQ-173 | **예정(ADR-0008)** 민감 등급은 정제를 거치며 함께 전파되고, 속성의 등급은 매핑된 컬럼의 등급보다 낮을 수 없다. 낮추려면 승인을 받는다. |
| REQ-174 | **예정(ADR-0008)** 소스를 읽기 전용으로 탐색하고 미리 볼 수 있다. 아웃바운드 연결은 소스마다 등록한 주소만 허용하고 연결 상태를 주기적으로 점검한다. 첫 구현(ADR-0058)은 `endpoints` 필드 대신 `base_url`(HTTP)과 `host`·`port`(PostgreSQL)가 그 소스의 유일한 주소이고 그 위에 REQ-412와 REQ-487의 거절 목록과 실제 IP 검사를 더하며, 주기적인 점검은 뒤의 일이다. |
| REQ-175 | **예정(ADR-0008)** 소스가 있는 분리망에 수집기를 별도로 기동할 수 있고 아웃바운드 연결만 쓴다. 수집기에 장애가 나도 소스 커서는 본체에 있어 다른 인스턴스가 이어받는다. |
| REQ-224 | **예정(ADR-0008)** 소스마다 정의로 여는 푸시 수집 경로가 있다. 서비스 계정으로 인증하고 같은 이벤트 ID는 한 번만 반영되며 같은 실행기와 안전장치를 거친다. |
| REQ-225 | **예정(ADR-0008)** 객체를 지정해서 그 객체의 데이터만 소스에서 다시 수집해 적용하는 작업이 있다. 소스 보호의 한도 안에서 실행되고 삭제를 만들지 않는다. |
| REQ-227 | **예정(ADR-0008)** 매핑을 만드는 사람을 돕는 API가 있다: 샘플과 컬럼 통계, 고정된 규칙으로 생성하는 매핑과 식별 후보의 제안, 타입 기준으로 보는 피드 목록, 저장 전 미리 보기(첫 구현은 REQ-446). |
| REQ-228 | **예정(ADR-0008)** 테이블 형태가 아닌 소스 데이터는 고정된 파서 목록으로 트리를 만들고 라인 템플릿으로 행을 읽어 데이터셋을 만든다. 읽지 못한 라인은 버리지 않고 센다. |
| REQ-263 | 파일 소스 하나(CSV, JSON Lines)를 소스 정의와 매핑 정의(JSON 데이터)로 받아 수집, 파싱, 원본 레코드의 변경, 정제, 피드, 식별, 링크, 적용 단계를 거쳐 KG에 넣는다. 매핑은 타입 레지스트리로 검증하고, 잘못된 매핑은 실행 전에 거절한다. REQ-110, REQ-113, REQ-126에서 분리한 요구다(ADR-0033).
| REQ-264 | 원본 레코드는 받은 그대로 구간(`from`, `to`)을 붙여 상태에 두고, 행마다 추가·수정·불변·삭제를 센다. 받은 행 수는 읽은 행과 읽지 못한 행의 합이고, 읽은 행은 끝에 사용됨, 규칙이 걸러 냄, 문제, 미사용 중 하나로 분류되며 합계가 맞는다. REQ-114, REQ-117에서 분리한 요구다(ADR-0033). 예정(ADR-0086)에서 바뀐다: 새 흐름은 구간(`from`, `to`)을 붙여 두지 않고 열린 레코드의 현재 판(해시, 선언한 컬럼의 값, 운명)만 둔다. 옛 경로는 그대로이고 행 수의 분류는 같다.
| REQ-265 | 동일 객체 식별은 표준 모델의 식별 키로 결정적으로 한다. 형태가 다른 두 파일에서 온 같은 객체는 하나가 되고, 속성은 순위(`rank`)와 나중 수집 순으로 하나가 이기며 다른 값은 `source_conflict`로 알린다. 병합과 분리는 만들지 않는다. REQ-104, REQ-126에서 분리한 요구다(ADR-0033).
| REQ-266 | 같은 파일을 다시 넣으면 KG가 바뀌지 않고 새 버전도 나오지 않는다. 한 행을 고치면 그 객체만 바뀐다. REQ-131에서 분리한 요구다(ADR-0033).
| REQ-267 | 파일에서 사라진 행은 완전한 수집에서 3번 연속 보이지 않고 처음 보이지 않은 때부터 24시간이 지나야 닫힌다. 닫힌 행의 객체는 `retires_objects` 피드가 본 것일 때만 링크와 함께 폐기한다. 불완전한 수집은 사라짐으로 세지 않는다. REQ-118에서 분리한 요구다(ADR-0033).
| REQ-268 | 식별자가 없거나 타입에 없는 값이 든 행은 사유와 함께 격리해 보고하고 나머지는 계속 적용한다. 받은 형태가 바뀐 데이터셋은 그 수집을 쓰지 않는다. REQ-117, REQ-118에서 분리한 요구다(ADR-0033).
| REQ-269 | `praxium ingest run`은 소스 정의, 매핑 정의, 데이터셋별 파일로 수집을 한 번 실행하고 단계별 건수와 문제를 보여 준다. 파일은 실행 파일의 루트만 열고 소스에는 읽기만 한다. REQ-147에서 분리한 요구다(ADR-0033). 예정(ADR-0086)에서 바뀐다: 새 흐름이 같은 일을 하게 되는 변경부터 수집은 PostgreSQL이 있어야 돌고 파일 상태 저장소 위의 실행은 없어진다.
