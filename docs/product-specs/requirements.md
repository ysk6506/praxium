# 프락시움 요구사항

## 제품 목표 (ADR-0001, ADR-0004)

**현실의 IT 인프라를 데이터로 받아 운영 세계를 짓고, 그 위에서 에이전트가 맡는 E2E 프로세스를 정하고 맡기고 재는 사내 운영 관리 플랫폼.**

제품 책임자가 확인한 목표다(ADR-0004). 설계 결정은 이 목표를 기준으로 내린다.

1. **현실을 받아 운영 세계를 짓는다.** 현실 시스템에서 구성 데이터를 읽어 모델(객체와 링크)에 맞추고, 무엇을 읽었고 무엇을 가정했는지 밝힌다. 현실 시스템에는 읽기만 한다.
2. **일을 E2E 프로세스 단위로 정하고 에이전트에게 맡긴다.** 누가 무엇을 어디까지 해도 되는지, 누가 승인하는지, 무슨 일이 있었는지를 프락시움이 맡는다. 실제 툴은 에이전트가 MCP 게이트웨이를 통해서만 부르고, 그 호출의 인증과 인가는 게이트웨이가 책임진다. 프락시움은 실제 툴을 부르지 않는다.
3. **맡기기 전에 검증하고, 맡긴 뒤에도 잰다.** 검증은 실험장(테라리움)이 한다. 프락시움은 세계 스냅샷을 내주고 판정 기록을 받는다. 맡긴 뒤에는 단계·사람·시간으로 잰다.

**테라리움과의 이음매는 파일 둘이다**(ADR-0001): 세계 스냅샷이 나가고, 판정 기록이 들어온다. 형식은 테라리움이 정한다.

이 문서는 요구사항의 단일 출처다. 모든 요구사항은 `REQ-NNN` ID를 가지며, 테스트는 제목에 `[REQ-NNN]`을 넣어 요구사항을 가리킨다. 테스트가 없는 요구사항은 CI에서 실패한다(`TRACE001`). 결정은 났지만 아직 만들지 않은 요구사항은 본문을 `**예정(ADR-NNNN)**`으로 시작해 표시한다. 요구사항을 바꾸려면 ADR이 필요하다.

번호는 셋으로 나눠 쓴다: 바탕 001~019, 프로세스(하네스) 020~029, 제품 100부터. 제품 요구사항은 아직 없다. 테라리움에서 넘겨받은 요구사항은 [넘겨받은 것](../references/from-terrarium.md) 2절에 있고, 하나씩 다시 정해서 여기에 더한다.

## 바탕

| ID | 요구사항 |
|---|---|
| REQ-001 | 같은 입력이면 같은 결과가 나온다. 시계와 난수는 한 곳(`kernel`)에서만 읽고, 나머지 코드는 주입받는다. ID, 해시, 난수열은 실행할 때마다 같다. |
| REQ-002 | 사람에게 보이는 글은 쉬운 한국어다. 조사는 앞말에 맞게 붙고(이/가, 을/를, 영어 낱말과 따옴표 뒤 포함), 시간은 읽기 쉬운 단위로 적는다. |
| REQ-003 | 화면의 모든 글은 한 가지 뜻에 한 가지 말을 쓴다. 물러난 말이 화면에 돌아오면 검사가 쓸 말과 함께 알린다. |

## 프로세스 (하네스)

| ID | 요구사항 |
|---|---|
| REQ-020 | 문서 품질: 문서는 최신 여부를 기계가 판정할 수 있어야 하고, 오래되거나 코드와 어긋난 문서는 CI에서 실패한다. |
| REQ-021 | 아키텍처 강제: 의존 방향, 공개 API 경계, 형제 격리, 외부 라이브러리 허용 범위를 기계가 검사한다. 결정(ADR)은 강제 장치와 연결된다. |
| REQ-022 | 기술 부채: 부채는 장부에 등록되고, 코드의 TODO는 장부를 가리켜야 하며, 기한이 지나거나 예산을 넘으면 실패한다. 복잡도·크기는 래칫으로 관리한다. 검사 끄기 주석·건너뛴 테스트·CI의 `continue-on-error`는 이유와 근거 번호가 있어야 하고 수는 늘 수 없다. |
| REQ-023 | 테스트: 커버리지 하한을 래칫으로 관리하고, 테스트를 통과시키려고 테스트를 바꾸는 행위(삭제, 약화, 기대값 변경, skip)를 기계가 막는다. |
| REQ-024 | 장기 유지보수: 어떤 코딩 에이전트가 이어받아도 AGENTS.md 하나로 길을 찾고 `pnpm check`만 통과시키면 안전하게 기여할 수 있다. 단위별 건강 상태는 하네스가 만드는 품질 등급표(`docs/generated/quality.md`, 등급 A~D)에서 한눈에 보인다. |
| REQ-025 | 모든 설계 결정은 ADR에 이유와 함께 남긴다. 제품 목표와 요구사항은 제품 책임자가 정하고, 설계는 그것을 기준으로 정한다. |

## 범위 밖

- 에이전트와 하네스를 가상 세계에서 평가하는 일. 그것은 테라리움의 일이다.
- 실제 툴을 부르는 일과 그 호출의 인증·인가. 에이전트와 MCP 게이트웨이의 일이다.
