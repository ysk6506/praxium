# 요구사항 — MCP 게이트웨이

게이트웨이(450~469)의 요구사항이다. 목표와 REQ 번호의 규칙은 [요구사항 입구](requirements.md)에 있다. 번호는 모든 요구사항 문서에서 하나뿐이다. 모두 결정은 났고 아직 구현하지 않았다. 구현은 클로즈드 베타 뒤다. 설계는 [게이트웨이 설계](../design-docs/gateway.md), [게이트웨이의 안전](../design-docs/gateway-safety.md), [액션 타입 표](../design-docs/gateway-actions.md)에 있다.

| ID | 요구사항 |
|---|---|
| REQ-450 | **예정(ADR-0061)** 게이트웨이는 프락시움의 구성요소이고 같은 릴리스, 같은 실행 파일의 별도 기동 모드다. 코어가 판단과 레지스트리와 기록을 맡고 게이트웨이가 집행하며 업스트림 MCP 서버의 자격 증명을 가진다. KG 조회의 MCP 인터페이스은 영구히 읽기 전용이고 게이트웨이는 다른 주소의 다른 구성요소다. |
| REQ-451 | **예정(ADR-0061)** 에이전트는 액션 타입을 툴로 보고 게이트웨이가 업스트림 툴의 호출로 바꾼다. 업스트림 툴의 설명은 에이전트에게 전달하지 않는다. 툴 목록은 실행마다 고정이고 통제는 호출할 때의 거절로 한다. |
| REQ-452 | **예정(ADR-0061)** 업스트림 툴은 등록하면 꺼져 있고 승인한 뒤에만 켜진다. 승인한 정의의 해시를 고정하고 정의가 바뀌면 끄고 다시 승인받는다. 분류(읽기, 진단, 바꾸기)는 툴의 표시가 아니라 프락시움이 정한다. |
| REQ-453 | **예정(ADR-0061)** 실행은 계약을 가진다: 실행 ID, 고정한 프로세스 정의 버전, 시작할 때 한꺼번에 부여한 허용 액션, 시작할 때 풀어 고정한 대상 객체(늘리려면 승인), 호출과 객체와 시간의 한도, 승인 규칙, 상태, 세대 번호가 있는 하네스 세션 임대. 실행의 시작은 사람이 하고 이벤트로 시작하는 것은 읽기만 하는 프로세스에 한한다. |
| REQ-454 | **예정(ADR-0061)** 바꾸는 호출은 준비, 실행, 조회의 세 번의 호출이다. 준비는 같은 (액션, 대상, 인자)에 멱등이고 실행은 의도 ID로 한 번만 실행한다. 조건이 맞지 않으면 실행은 "아직"과 맞지 않은 조건의 목록을 돌려주고 프락시움이 스스로 실행하지 않는다. 게이트웨이는 바꾸는 업스트림 호출을 다시 보내지 않는다. |
| REQ-455 | **예정(ADR-0061)** 코어는 의도의 상태(준비됨, 승인 대기, 실행 중, 끝남, 확인 결과, 모름)를 실행 대장로 영속적으로 가진다. 이어 가기 맥락을 돌려주는 읽기 툴이 있고 그것을 부르면 세대 번호가 올라 낡은 세대의 호출은 거절된다. |
| REQ-456 | **예정(ADR-0061)** 승인은 의도의 내용 해시와 조건의 증거에 묶이고 조건은 실행 직전에 다시 확인한다. 승인 시간이 지나면 거절이고 자동 승인은 없다. 승인 화면은 조건의 증거, 영향 요약, 평소와 다른 점, 자유 문장 인자의 원문을 보여 준다. |
| REQ-457 | **예정(ADR-0061)** 읽기, 진단(부작용이 있을 수 있는 확인), 바꾸기를 구분한다. 자유 형식 인자가 있는 툴은 읽기로 분류하지 않는다. 진단은 업스트림 서버와 대상별 한도가 있고 실행에 묶어 기록한다. 업스트림 응답은 리소스 링크를 지우고 크기를 제한하고 시크릿을 가려서 넘긴다. |
| REQ-458 | **예정(ADR-0061)** 업스트림 호출에 넣는 식별자는 그 툴이 다루는 시스템에서 직접 읽은 `observed` 식별자이고 정한 나이 안이며 열린 식별 후보나 충돌이 없어야 한다. 영향 범위를 쓰는 조건은 관련 링크 타입에 완전성 선언이 있어야 통과하고 모르면 영향으로 센다. 조건마다 허용 나이가 있고 낡으면 "확인 못 함"이다. |
| REQ-459 | **예정(ADR-0061)** 툴의 성공 응답을 믿지 않고 코어가 요청해 수집 쪽이 다시 읽어 확인한다(REQ-225, REQ-226 재사용). 결과는 `confirmed`, `not_yet`, `contradicted`, `unverifiable`이다. 어긋나면 자동으로 되돌리지 않고 멈춰서 상태 요약과 함께 사람에게 넘긴다. 밀어 넣은 값은 증거가 되지 못한다. |
| REQ-460 | **예정(ADR-0061)** 잠금은 대상과 그것이 직접 속한 중복 그룹과 그 그룹이 속한 그룹까지 걸고 깊이 한도와 임대 기간이 있다. 진행 중인 의도는 다른 실행의 조건 평가에서 이미 일어난 것으로 센다. |
| REQ-461 | **예정(ADR-0061)** 연결(액션과 툴의 짝)마다 신뢰 단계(그림자, 호출마다 승인, 자율)가 있다. 사람이 확인 기록을 보고 올리고, 툴의 정의가 바뀌거나 확인 결과가 어긋나면 자동으로 내려간다. |
| REQ-462 | **예정(ADR-0061)** 업스트림의 주소와 자격 증명은 게이트웨이 쪽 설정에 있고 코어의 레지스트리는 이름만 가리킨다. 게이트웨이는 허용하는 바꾸기 툴과 호출 한도의 두 번째 사본을 가지고 호출 이력을 코어 밖(조직의 로그 수집)으로 직접 내보낸다. |
| REQ-463 | **예정(ADR-0061)** 변경은 추가 전용 기록(해시 체인)이 없으면 거절한다. 인자는 해시와 가린 요약으로 기록한다. 게이트웨이는 버릴 수 없는 기록(호출 전 기록, 정지 상태)을 로컬 저널에 둔다. 죽은 게이트웨이의 저널에만 있는 결과는 대장에서 "모름"으로 남는다. |
| REQ-464 | **예정(ADR-0061)** 1차에서는 코어가 멈추면 게이트웨이도 읽기를 포함해 모두 막는다. 게이트웨이는 상태가 없고 둘 이상이며 운영 구성은 동기 복제와 장애 전환이 있는 PostgreSQL이다. 정지 스위치(전체, 실행 하나, 업스트림 서버 하나)가 있고 코어와 다른 관리자 긴급 키로도 낼 수 있다. |
| REQ-465 | **예정(ADR-0061)** 게이트웨이 정의의 종류(프로세스, 액션과 툴의 연결, 툴 승인, 조건 제거, 한도 완화, 업스트림 서버 등록)는 위험 등급의 하한이 R3이고 자동 병합과 자동 첫 적용에서 빠진다. 권한을 넓히는 리버트는 긴급 경로를 쓸 수 없다. 바꾸는 툴을 켠 설치는 셀프 승인을 거절한다. |
| REQ-466 | **예정(ADR-0061)** 바꾸는 툴의 1차는 승인 전용이다. 모든 바꾸는 호출에 사람의 승인이 필요하고 되돌릴 수 있고 지장이 없고 객체 하나에 곧바로 관측되는 속성 하나인 액션만 대상이다. "실험 기능, 기본 꺼짐"으로 내고 켤 때 조건 점검을 보여 준다. |
| REQ-467 | **예정(ADR-0061)** 프락시움이 보장하는 것과 보장하지 않는 것(우회가 열려 있을 때 힘을 잃는 것의 목록 포함)을 문서로 제공한다. 정지 스위치는 게이트웨이를 지나는 호출의 정지로 설명한다. |
| REQ-468 | **예정(ADR-0061)** 액션 타입은 인자의 정의(이름, 종류, 허용값)와 기계가 읽는 효과 선언(어느 속성이 어떻게 되는가, 관측 시점)을 가진다. 연결은 대상의 관측된 식별자, 선언한 인자, 고정값만 통과시키고 자유 문장 인자는 승인 화면에 원문으로 보인다. |
| REQ-469 | **예정(ADR-0061)** 2차(자율)는 연결별 신뢰 이력, 장애 훈련 기록, 그림자 운전에서 잘못된 확인의 비율의 측정값, 외부 보안 검토, 판단 테스트 모음의 통과 증거가 모이기 전에는 열지 않는다. 판단 코드는 입력의 순수 함수이고 입력을 기록해 재현할 수 있다. |
