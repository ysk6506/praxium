# 요구사항 — MCP 게이트웨이

게이트웨이(450~469, 520~534)와 상시 가동 에이전트가 붙는 위치(ADR-0074)에서 게이트웨이에 닿는 것(539~542, 544~546)의 요구사항이다. 목표와 REQ 번호의 규칙은 [요구사항 입구](requirements.md)에 있다. 번호는 모든 요구사항 문서에서 하나뿐이다. 모두 결정은 났고 아직 구현하지 않았다. 구현은 클로즈드 베타 뒤다. 설계는 [게이트웨이 설계](../design-docs/gateway.md), [게이트웨이의 안전](../design-docs/gateway-safety.md), [액션 타입 표](../design-docs/gateway-actions.md)에 있다.

| ID | 요구사항 |
|---|---|
| REQ-450 | **예정(ADR-0061)** 게이트웨이는 프락시움의 구성요소이고 같은 릴리스, 같은 실행 파일의 별도 기동 모드다. 코어가 판단과 레지스트리와 기록을 맡고 게이트웨이가 집행하며 업스트림 MCP 서버의 자격 증명을 가진다. KG 조회의 MCP 인터페이스는 영구히 읽기 전용이고 게이트웨이는 다른 주소의 다른 구성요소다. 이미 MCP 서버를 가진 조직이 새로 만들지 않고 그것을 업스트림으로 연결할 수 있어야 한다. |
| REQ-451 | **예정(ADR-0061)** 에이전트는 액션 타입을 툴로 보고 게이트웨이가 업스트림 툴의 호출로 바꾼다. 바꾸는 액션 툴에는 업스트림 툴의 설명이 닿지 않는다. 읽기와 진단 툴은 승인한 시점의 정의 사본(설명 포함)을 보인다. 툴 목록은 실행마다 고정이고 통제는 호출할 때의 거절로 한다. 예정(ADR-0074)에서 더한다: 같은 실행에서 툴 정의의 정규 직렬화는 바이트까지 같다(목적은 프롬프트 캐시이고 REQ-549와 같은 규칙이다). |
| REQ-452 | **예정(ADR-0061)** 업스트림 툴은 등록하면 꺼져 있고 승인한 뒤에만 켜진다. 승인한 정의의 해시를 고정하고 정의가 바뀌면 끄고 다시 승인받는다. 분류(읽기, 진단, 바꾸기)는 툴의 표시가 아니라 프락시움이 정한다. |
| REQ-453 | **예정(ADR-0061)** 실행은 계약을 가진다: 실행 ID, 고정한 프로세스 정의 버전, 시작할 때 한꺼번에 부여한 허용 액션, 시작할 때 풀어 고정한 대상 객체(늘리려면 승인), 호출과 객체와 시간의 한도, 승인 규칙, 상태, 이어받을 때 오르는 이어가기 번호. 실행의 시작은 사람이 한다. |
| REQ-454 | **예정(ADR-0061)** 바꾸는 호출은 준비, 실행, 조회의 세 번의 호출이다. 준비는 같은 (액션, 대상, 인자)에 멱등이고 실행은 의도 ID로 한 번만 실행한다. 조건이 맞지 않으면 실행은 "아직"과 맞지 않은 조건의 목록을 돌려주고 프락시움이 스스로 실행하지 않는다. 게이트웨이는 바꾸는 업스트림 호출을 다시 보내지 않는다. |
| REQ-455 | **예정(ADR-0061)** 코어는 의도의 상태(준비됨, 승인 대기, 실행 중, 끝남, 확인 결과, 모름, 거절, 만료, 취소)를 실행 대장으로 영속적으로 가진다. 확인이 정한 시간 안에 끝나지 않거나 `not_yet`이나 `unverifiable`로 남으면 사람에게 넘기고 사람이 의도를 닫는다. 이어 가기 맥락을 돌려주는 읽기 툴이 있고, "이어받겠다"고 표시해서 부를 때만 이어가기 번호가 올라 낡은 번호의 호출은 거절된다. |
| REQ-456 | **예정(ADR-0061)** 승인은 의도의 내용 해시와 조건의 증거에 묶이고 조건은 실행 직전에 다시 확인한다. 승인 시간이 지나면 만료로 거절이고 자동 승인은 없다. 승인 화면은 조건의 증거, 영향 요약, 지장의 종류를 보여 준다. |
| REQ-457 | **예정(ADR-0061)** 읽기, 진단(부작용이 있을 수 있는 확인), 바꾸기를 구분한다. 자유 형식 인자가 있는 툴은 읽기로 분류하지 않는다. 진단은 업스트림 서버와 대상별 한도가 있고 실행에 묶어 기록한다. 업스트림 응답은 리소스 링크를 지우고 크기를 제한하고 시크릿을 가려서 넘긴다. |
| REQ-458 | **예정(ADR-0061)** 업스트림 호출에 넣는 식별자는 그 툴이 다루는 시스템에서 직접 읽은 `observed` 식별자이고 정한 나이 안이며 열린 식별 후보나 충돌이 없어야 한다. 영향 범위를 쓰는 조건은 관련 링크 타입에 완전성 선언이 있어야 통과하고 모르면 영향으로 센다. 조건마다 허용 나이가 있고 나이는 읽은 때가 아니라 값 자체의 시각으로 잰다. 낡으면 "확인 못 함"이다. |
| REQ-459 | **예정(ADR-0061)** 툴의 성공 응답을 믿지 않고 코어가 요청해 수집 쪽이 다시 읽어 확인을 시도한다(REQ-225, REQ-226 재사용). 결과는 `confirmed`, `not_yet`, `contradicted`, `unverifiable`이다. 어긋나면 자동으로 되돌리지 않고 멈춰서 상태 요약과 함께 사람에게 넘긴다. 밀어 넣은 값은 증거가 되지 못한다. |
| REQ-460 | **예정(ADR-0061)** 잠금은 대상과 그것이 직접 속한 이중화 그룹과 그 그룹이 속한 그룹까지 걸고 깊이 한도와 임대 기간이 있다. 진행 중인 의도는 다른 실행의 조건 평가에서 이미 일어난 것으로 센다. |
| REQ-461 | **예정(ADR-0061)** 연결(액션과 툴의 짝)마다 신뢰 단계(그림자, 호출마다 승인, 자율)가 있다. 사람이 확인 기록을 보고 올리고, 툴의 정의가 바뀌거나 확인 결과가 어긋나면 자동으로 내려간다. |
| REQ-462 | **예정(ADR-0061)** 업스트림의 주소와 자격 증명은 게이트웨이 쪽 설정에 있고 코어의 레지스트리는 이름만 가리킨다. 게이트웨이는 허용하는 바꾸기 툴과 호출 한도의 두 번째 사본을 가지고 호출 이력을 코어 밖(조직의 로그 수집)으로 직접 내보낸다. 내보내지 못한 기록은 로컬 일지에 쌓았다가 복구되면 순서대로 보내고 밀린 사실을 운영 신호로 알린다. 1차에서는 이것으로 변경을 막지 않고, 2차에서는 밀린 시간이 한도를 넘으면 변경을 막는다. |
| REQ-463 | **예정(ADR-0061)** 변경은 추가 전용 기록(해시 체인)을 쓰지 못하면 거절한다. 인자는 해시와 가린 요약으로 기록한다. 게이트웨이는 요청 사이의 상태를 메모리에 두지 않고, 버리면 안 되는 것(호출 전 기록, 정지 상태)만 로컬 일지에 둔다. 죽은 게이트웨이의 일지에만 있는 결과는 대장에서 "모름"으로 남는다. |
| REQ-464 | **예정(ADR-0061)** 1차에서는 코어가 멈추면 게이트웨이도 읽기를 포함해 모두 막는다. 정지 스위치(전체, 실행 하나, 업스트림 서버 하나)가 있고 새 호출을 막는다. 이미 업스트림에 나간 작업은 멈추지 못한다고 문서에 밝힌다. |
| REQ-465 | **예정(ADR-0061)** 게이트웨이 정의의 종류(프로세스, 액션과 툴의 연결, 툴 승인, 조건 제거, 한도 완화, 업스트림 서버 등록)는 위험 등급의 하한이 R3이고 자동 병합과 자동 첫 적용에서 빠진다. 권한을 넓히는 리버트는 긴급 경로를 쓸 수 없다. 바꾸는 툴을 켠 설치는 셀프 승인을 거절한다. |
| REQ-466 | **예정(ADR-0061)** 바꾸는 툴의 1차는 승인 전용이다. 모든 바꾸는 호출에 사람의 승인이 필요하고, 액션 타입마다 인자, 실행 조건, 기대 효과, 가운데 멈출 수 있는지, 이전 값의 선언이 갖춰지고 검토된 확정 대상만 연다. "실험 기능, 기본 꺼짐"으로 내고 켤 때 조건 점검을 보여 준다. 1차는 단일 구성을 허용한다. |
| REQ-467 | **예정(ADR-0061)** 프락시움이 보장하는 것과 보장하지 않는 것(우회가 열려 있을 때 힘을 잃는 것의 목록 포함)을 문서로 제공한다. 정지 스위치는 게이트웨이를 지나는 새 호출의 정지로 설명한다. |
| REQ-468 | **예정(ADR-0061)** 액션 타입은 인자의 정의(이름, 종류, 허용값)와 기계가 읽는 효과 선언(어느 속성이 어떻게 되는가, 관측 시점)을 가진다. 연결은 대상의 관측된 식별자, 선언한 인자, 고정값만 통과시키고 자유 문장 인자는 승인 화면에 원문으로 보인다. |
| REQ-469 | **예정(ADR-0061)** 2차(자율)는 연결별 신뢰 이력, 장애 훈련 기록, 그림자 운전에서 잘못된 확인의 비율의 측정값, 외부 보안 검토, 판단 테스트 모음의 통과, 이중화 구성, 승인자 지정 기록이 [게이트웨이의 안전](../design-docs/gateway-safety.md) 7.2절 목록대로 갖춰지기 전에는 열지 않는다. |
| REQ-520 | **예정(ADR-0061)** 판단 코드는 입력 묶음의 순수 함수이고, 입력을 기록해 같은 판단을 재현할 수 있다. 판단 테스트 모음이 있다. |
| REQ-521 | **예정(ADR-0061)** 게이트웨이 정의 종류의 승인자 지정은 관리자 두 명이 한다. 이것은 2차의 조건이다. |
| REQ-522 | **예정(ADR-0061)** 특정 시점 복구 뒤에는 바꾸는 툴이 닫힌 채 시작하고 툴 승인을 다시 확인한다. |
| REQ-523 | **예정(ADR-0061)** 정의의 작성자와 승인자는 서로 다른 주체이고, 툴 승인자는 승인자와 겹쳐도 된다. 작성자와 승인자를 나눌 수 없는 조직은 바꾸는 툴을 쓰지 못한다. |
| REQ-524 | **예정(ADR-0061)** 프락시움이 기대는 객체는 자동 변경에서 뺀다(1차부터). 바꾸는 툴을 켠 설치는 에이전트가 바꿀 수 있는 인프라와 분리된 기반을 권고하고 2차의 조건으로 삼는다. |
| REQ-525 | **예정(ADR-0061)** 승인자별 건수, 걸린 시간, 거절률을 지표로 낸다. |
| REQ-526 | **예정(ADR-0061)** 이미 게이트웨이가 있는 조직은 프락시움 게이트웨이를 그 뒤의 MCP 서버로 둘 수 있다. 코어와 게이트웨이 사이의 판단 계약은 버전을 가진다. |
| REQ-527 | **예정(ADR-0061)** 이벤트로 자동 시작하는 실행은 읽기만 하는 프로세스에 한하고 부작용이 있을 수 있는 진단을 넣지 않는다. 일정으로 시작하는 것은 이벤트의 시작으로 본다. 티켓의 요청은 만든 사람이 시작 권한이 있는 계정에 대응하면 사람의 시작으로, 기계가 만든 티켓은 이벤트로 본다. |
| REQ-528 | **예정(ADR-0061)** 하네스는 실행이 열려 있는 동안 새 실행 토큰을 받을 수 있고 갱신은 실행에 묶인다. 승인을 기다리는 동안 살아 있는 토큰이 필요하지 않다. 의도는 토큰과 독립으로 남는다. |
| REQ-529 | **예정(ADR-0061)** 실행 중에 더하는 툴은 이미 등록하고 승인한 액션만이고, 정의 승인자 수준의 승인과 실행마다 개수 한도가 있다. |
| REQ-530 | **예정(ADR-0061)** 1차에서는 조건이 "확인 못 함"이면 실행을 거절하고 사람에게 넘긴다. 승인자가 "확인 못 함"을 넘겨 승인하는 길은 없다. |
| REQ-531 | **예정(ADR-0061)** 2차를 켜는 설치는 게이트웨이를 둘 이상 띄우고, 정족수 동기 복제와 장애 전환이 있는 PostgreSQL을 쓴다. 파일 스토어는 단일 인스턴스 전용이다. |
| REQ-532 | **예정(ADR-0061)** 관리자 긴급 키로 낸 정지는 코어가 풀 수 없고 게이트웨이마다 따로 전한다. 다시 뜬 게이트웨이는 정지 상태를 로컬 일지에서 읽는다. |
| REQ-533 | **예정(ADR-0061)** 업그레이드할 때 진행 중인 실행은 시작할 때의 정의 집합을 유지한다. |
| REQ-534 | **예정(ADR-0061)** 프락시움 자신을 고치는 운영 액션의 길은 게이트웨이에 기대지 않는다. 운영 액션과 게이트웨이의 실행 계약을 맞추는 방법은 미결이다. |
| REQ-539 | **예정(ADR-0074)** 게이트웨이는 의도의 상태 변화(승인 대기가 됨, 승인됨, 거절됨, 만료됨, 끝남, 모름이 됨)와 실행의 시작됨과 닫힘을 이벤트로 낸다. 에이전트는 서비스 계정 기준으로 자기에게 열린 실행과 의도를 목록으로 다시 찾는 읽기 툴을 가진다. |
| REQ-540 | **예정(ADR-0074)** 승인이 필요한 바꾸는 호출의 응답은 승인 대기와 의도 ID이고, MCP 툴 결과에서 `isError`가 아닌 구조화된 결과다. 호출이 받아들여져 상태가 생긴 것("아직", 승인 대기)은 성공 결과이고 처리되지 못한 것(한도 초과, 서버를 쓸 수 없음)은 `isError`다. 승인 대기와 "아직"의 응답은 `poll_after_ms`와 승인의 만료 시각을 싣는다. 하네스 세션을 닫아도 의도는 대장에 남고, 폴링으로도 상태를 알 수 있다. |
| REQ-541 | **예정(ADR-0074)** 의도의 승인 요청은 운영 액션과 정의 제안의 승인 요청과 같은 전달 경로로 승인할 수 있는 사람에게 간다. 글은 템플릿과 링크뿐이고 인자와 KG의 값을 넣지 않는다. 승인 화면에 승인 대기 목록이 있다. |
