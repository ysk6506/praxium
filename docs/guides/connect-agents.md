# 에이전트 연결하기

> **예정이에요. 이 기능은 일부만 구현됐어요.** 지금 서버의 `/mcp`는 전송과 판 처리가 되어 있고 툴은 `kg_whoami` 하나예요. KG를 읽는 툴은 아직 없어요. 이 문서는 뼈대이고, 아래 절만 먼저 적었어요. 하네스별 설정 예는 구현하면서 써요. 무엇을 정했는지는 ADR-0062, 세부는 [KG의 읽기 전용 MCP 인터페이스](../design-docs/kg-mcp.md)에 있어요.

프락시움의 KG를 에이전트가 읽도록 `POST /mcp`로 툴 다섯 개(`kg_whoami`, `kg_catalog`, `kg_find`, `kg_get`, `kg_neighbors`)를 내줄 예정이에요. 이 인터페이스는 읽기만 해요. 현실을 바꾸는 툴은 없어요. KG 조회는 MCP 규격의 세 판(2026-07-28, 2025-11-25, 2025-06-18)을 받아요. 게이트웨이(ADR-0061)는 하네스 쪽에서 2026-07-28판부터 받아요(gateway.md). 옛 판만 말하는 하네스는 KG 조회에는 붙고 게이트웨이에는 붙지 못해요.

켜는 방법: `praxium demo`, `praxium local`, `api serve -mode development`는 `/mcp`가 기본으로 켜져 있어요(`-mcp=false`로 꺼요). 운영 모드(`api serve`)는 `-mcp`를 줘야 켜져요. 브라우저에서 부를 출처가 있으면 `-mcp-allowed-origins`에 적어요(기본은 없음). 주소는 서버와 같은 주소의 `/mcp`이고 토큰은 `Authorization: Bearer` 헤더로만 받아요.

## 1. 자료는 하네스를 거쳐 모델 제공자에게 나가요

툴이 돌려준 KG의 값은 에이전트를 돌리는 하네스로 가고, 하네스는 그 값을 모델 제공자의 서버에 보내 답을 받아요. 프락시움은 이 길의 뒤쪽을 통제하지 못해요.

- **나가는 것**: 툴 호출의 결과(객체의 이름, 속성, 링크)가 모두 나가요. 결과의 글에 든 값도 포함돼요.
- **민감 등급과의 관계**: MCP로 나가는 민감 등급의 상한은 서버 설정이고 기본은 `open`이에요. 그런데 지금은 등급을 정하지 않은 속성이 모두 `open`이라서, 토큰 하나로 KG 전체가 읽혀요. 등급은 **속성의 값**만 가려요. 객체가 있다는 것, 타입, 식별자, 링크는 등급과 무관하게 나가요. 그리고 지금은 권한 부여가 없어서 등급을 올린 값은 REST와 화면에서도 모두에게 가려져요.
- **폐쇄망**: 바깥의 모델 제공자를 쓰면 폐쇄망 밖으로 자료가 나가요. 모델이 어디에서 돌아가는지 먼저 확인하세요.
- **믿을 수 없는 값**: KG의 값(사람이 적은 글자 포함)이 에이전트에게 지시처럼 읽힐 수 있어요. 서버가 값을 정리하지만 완전한 방어는 없어요. 같은 하네스에 다른 서버의 쓰기 툴이 있으면 "읽기만 하니 피해가 작다"는 말이 맞지 않아요. 쓰기 툴이 있는 하네스에는 승인 절차를 두세요.

## 2. 토큰을 다룰 때 주의할 점

- 운영 모드에서는 **토큰이 가진 역할이 `viewer` 하나뿐인 서비스 계정의 토큰**만 쓰세요(다른 역할이 있는 계정이면 토큰을 `viewer`로 좁혀 발급해요). `viewer` 말고 다른 역할이 있는 토큰이나 사람의 토큰은 `/mcp`가 HTTP 403으로 거절하고 이유를 알려 줘요. 관리자 토큰이 하네스의 설정 파일에 놓이면 셸을 쓸 수 있는 에이전트가 읽어 REST 관리 경로를 부를 수 있어서예요. `demo`, `local`, 개발 모드의 실행용 토큰은 그대로 받아요.
- 토큰(`pxm_`로 시작해요)은 설정 파일에 적지 말고 **환경 변수**로 넣으세요. `pxm_` 접두어는 비밀 검사 도구가 찾을 수 있어요.
- 토큰은 기본으로 90일 뒤에 만료돼요(ADR-0044). 만료되면 무인 에이전트는 401을 받고 멈춰요. 교체는 새 토큰을 발급(`POST /v1/tokens`)하고 하네스의 환경 변수를 바꾼 뒤 옛 토큰을 회수(`POST /v1/tokens/{token_id}:revoke`)하는 순서예요. 만료를 미리 알리는 방법은 구현하면서 이 절에 적어요.
- 서버는 평문 HTTP로 토큰을 받지 않는 구성(TLS 또는 프록시 뒤)에서만 운영 모드로 떠요([서버 운영하기](operate-the-server.md)).
- 일부 클라이언트는 401을 받으면 OAuth 탐색을 시작해요. 프락시움은 1단계에서 OAuth를 쓰지 않으므로 `/.well-known/` 아래의 탐색 경로는 JSON 404로 답해요. 옛 방식의 클라이언트는 탐색에 실패하면 `/authorize`를 브라우저로 열 수 있고, 그러면 프락시움의 웹 화면이 떠요. 로그인 화면이 아니라는 뜻이고, 토큰을 설정에 직접 넣어야 해요.

## 3. 앞으로 쓸 것

하네스별 설정 예, 새 판과 옛 판의 클라이언트에서 확인한 방법, 흔한 오류와 해결, 에이전트 평가용 과제 모음. 모두 구현하는 변경에서 써요.
