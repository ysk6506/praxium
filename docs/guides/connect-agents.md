# 에이전트 연결하기

> **예정이에요. 이 기능은 아직 구현되지 않았어요.** 지금 서버에는 `/mcp`가 없어요. 이 문서는 뼈대이고, 아래 두 절만 먼저 적었어요. 하네스별 설정 예는 구현하면서 써요. 무엇을 정했는지는 ADR-0062, 세부는 [KG의 읽기 전용 MCP 인터페이스](../design-docs/kg-mcp.md)에 있어요.

프락시움의 KG를 에이전트가 읽도록 `POST /mcp`로 툴 여섯 개(`kg_whoami`, `kg_catalog`, `kg_find`, `kg_get`, `kg_neighbors`, `kg_impact`)를 내줄 예정이에요. 이 면은 읽기만 해요. 현실을 바꾸는 툴은 없어요.

## 1. 자료는 하네스를 거쳐 모델 제공자에게 나가요

툴이 돌려준 KG의 값은 에이전트를 돌리는 하네스로 가고, 하네스는 그 값을 모델 제공자의 서버에 보내 답을 받아요. 프락시움은 이 길의 뒤쪽을 통제하지 못해요.

- **나가는 것**: 툴 호출의 결과(객체의 이름, 속성, 링크, 영향 범위)가 모두 나가요. 결과의 글에 든 값도 포함돼요.
- **민감 등급과의 관계**: MCP로 나가는 민감 등급의 상한은 서버 설정이고 기본은 `open`이에요. 그런데 지금은 등급을 정하지 않은 속성이 모두 `open`이라서, 읽기 역할 토큰 하나로 KG 전체가 읽혀요. 모델 제공자에게 보내면 안 되는 값은 정의에서 등급을 올려 두세요.
- **폐쇄망**: 바깥의 모델 제공자를 쓰면 폐쇄망 밖으로 자료가 나가요. 모델이 어디에서 돌아가는지 먼저 확인하세요.
- **믿을 수 없는 값**: KG의 값(사람이 적은 글자 포함)이 에이전트에게 지시처럼 읽힐 수 있어요. 서버가 값을 정리하지만 완전한 방어는 없어요. 같은 하네스에 다른 서버의 쓰기 툴이 있으면 "읽기만 하니 피해가 작다"는 말이 맞지 않아요. 쓰기 툴이 있는 하네스에는 승인 절차를 두세요.

## 2. 토큰을 다룰 때 주의할 점

- **읽기 역할의 서비스 계정 토큰만** 쓰세요. 관리자나 쓰기 역할의 토큰은 `/mcp`가 거절해요. 그런 토큰이 하네스의 설정 파일에 놓이면 셸을 쓸 수 있는 에이전트가 읽어 REST 관리 경로를 부를 수 있어요.
- 토큰(`pxm_`로 시작해요)은 설정 파일에 적지 말고 **환경 변수**로 넣으세요. `pxm_` 접두어는 비밀 검사 도구가 찾을 수 있어요.
- 토큰은 기본으로 90일 뒤에 만료돼요(ADR-0044). 만료되면 무인 에이전트는 401을 받고 멈춰요. 토큰의 수명과 교체 방법, 만료를 미리 알리는 방법은 구현하면서 이 절에 적어요.
- 서버는 평문 HTTP로 토큰을 받지 않는 구성(TLS 또는 프록시 뒤)에서만 운영 모드로 떠요([서버 운영하기](operate-the-server.md)).
- 일부 클라이언트는 401을 받으면 OAuth 탐색을 시작해요. 프락시움은 1단계에서 OAuth를 쓰지 않으므로 탐색 경로는 JSON 404로 답해요. 이때 클라이언트의 설정에 토큰을 직접 넣는 방식을 고르세요.

## 3. 앞으로 쓸 것

하네스별 설정 예, 새 판과 옛 판의 클라이언트에서 확인한 방법, 흔한 오류와 해결, 에이전트 평가용 과제 모음. 모두 구현하는 변경에서 써요.
