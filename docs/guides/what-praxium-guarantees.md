# 프락시움이 보장하는 것과 보장하지 않는 것

게이트웨이를 쓰는 조직이 무엇을 기대해도 되고 무엇을 스스로 지켜야 하는지 적어요(ADR-0061). 게이트웨이는 아직 구현하지 않았어요. 현재 코드는 현실 시스템을 읽기만 해요.

## 1. 보장하는 것

프락시움은 **게이트웨이를 지나는 호출**에 대해서만 보장해요.

- 에이전트가 게이트웨이로 부른 바꾸는 호출은 허용 액션, 대상, 한도, 승인 규칙을 거쳐요.
- 지나간 호출은 기록이 남아요. 기록을 쓸 수 없으면 바꾸지 않아요.
- 툴의 성공 응답을 믿지 않고 실행 뒤에 확인을 시도해요. 확인하지 못하면 "확인 못 함"으로 남기고 어긋나면 멈춰서 사람에게 넘겨요.
- 판단할 수 없으면 막아요. 프락시움이 멈추면 게이트웨이를 지나는 새 변경은 모두 막혀요.
- 업스트림 서버의 자격 증명은 에이전트와 코어에 가지 않고 게이트웨이가 가져요.
- 정지 스위치는 새 호출을 막아요. 이미 업스트림에 나간 작업은 멈추지 못해요.

## 2. 보장하지 않는 것

- 에이전트가 게이트웨이를 거치지 않고 현실 시스템에 닿는 경로(우회)를 막는 일. 우회를 막는 것은 조직의 책임이에요. 하네스의 셸처럼 MCP가 아닌 경로도 우회예요.
- 업스트림 서버와 현실 시스템 자체의 올바름.
- **코어가 침해되면** 판단, 승인, 기록을 모두 믿을 수 없어요. **게이트웨이가 침해되면** 그 게이트웨이가 가진 업스트림 서버의 자격 증명으로 서버를 직접 부를 수 있어요.
- KG가 틀리면 판단도 틀려요(식별이 잘못 합쳐진 객체, 틀린 완전성 선언).
- 실행 토큰을 가진 쪽이 누구인지 구별하지 못해요(하위 에이전트, 샌 토큰). 소지 증명은 선택 강화예요.
- 승인하는 사람의 판단.
- 자동으로 되돌리지 않아요. "되돌릴 수 있음"은 표준 모델의 표시예요.
- 응답에서 시크릿을 가리는 것은 최선의 노력이에요.
- 권한을 한꺼번에 주므로 조건을 적지 않은 액션은 실행 내내 열려 있어요.
- 프락시움이 멈췄을 때 에이전트가 하던 일의 계속. 멈추면 에이전트는 아무것도 바꾸지 못해요.
- 게이트웨이 밖에서 일어난 변경의 기록. 수집이 다음에 읽어서 알게 될 뿐이에요.
- 사람이 직접 하는 변경. 프락시움은 에이전트의 문이고 사람의 문이 아니에요.

## 3. 우회가 열려 있으면 힘을 잃는 것

에이전트나 다른 호출자가 업스트림 서버나 현실 시스템에 직접 닿을 수 있으면, 그 길에는 다음이 적용되지 않아요.

| 힘을 잃는 것 | 이유 |
|---|---|
| 게이트웨이의 거절 | 호출이 게이트웨이를 지나지 않아요 |
| 대상 고정과 잠금 | 같은 대상을 다른 경로로 바꿔도 잠금이 모르고 조건 평가에서 이미 일어난 일로 세지 않아요 |
| 실행별 호출, 객체, 시간 한도 | 한도는 게이트웨이가 세요 |
| 승인과 내용 해시의 묶음 | 승인은 게이트웨이가 집행해요 |
| 정지 스위치 | "게이트웨이를 지나는 새 호출의 정지"예요 |
| 호출 전 기록과 "기록 없이 변경 없음" | 기록은 게이트웨이가 남겨요 |
| 진행 중인 의도를 다른 실행의 조건에 넣는 계산 | 우회한 호출은 의도가 없어요 |
| 실행 뒤의 확인 | 확인은 게이트웨이를 지난 의도에 대해서만 시작해요 |
| 업스트림 툴 설명의 차단과 응답의 필터링 | 응답이 게이트웨이를 지나지 않아요 |
| 연결별 신뢰 단계 | 단계는 연결마다 있고 우회에는 연결이 없어요 |

수집이 나중에 바뀐 값을 읽으면 KG에는 반영돼요. 그러나 그것은 사후에 아는 것이고 막은 것이 아니에요.

## 4. 우회를 줄이는 일

조직이 할 일이에요. 프락시움이 대신 해 주지 않아요.

- 에이전트가 쓰는 계정과 네트워크로 업스트림 서버에 직접 닿지 못하게 해요. 업스트림 서버의 자격 증명은 게이트웨이에만 둬요.
- 다른 호출자(사람의 도구, 다른 에이전트)가 같은 업스트림을 쓰면 그 호출은 게이트웨이를 지나지 않는 우회예요. 그런 호출자가 있는지 점검해요.
- 바꾸는 툴을 켠 설치는 프락시움이 올라간 기반을 에이전트가 바꿀 수 없게 분리하는 것을 권고해요(2차에서는 조건이에요).

켤 때 보여 주는 조건 점검 화면에 "같은 업스트림을 다른 호출자도 받는가" 확인을 넣는 선택 점검을 준다는 것이 설계의 방향이에요. 방법은 아직 정하지 않았어요([미결 사항](../design-docs/gateway-safety.md)).
