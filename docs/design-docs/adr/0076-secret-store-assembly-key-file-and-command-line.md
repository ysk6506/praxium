# ADR-0076 시크릿 저장소를 디스크와 명령줄에 조립한다

## 맥락

[ADR-0071](0071-secret-store-core-and-file-adapter.md)은 코어와 파일 어댑터까지 만들었고, 실제 디스크, 마스터 키 파일의 위치, 명령줄을 "뒤의 변경"으로 남겼다. 이 변경은 [ADR-0058](0058-sources-from-db-and-api-worker-ingestion-and-editing-screens.md)의 단계 2b 가운데 그 조립이다(REQ-474, REQ-498, REQ-499). 서버를 띄우지 않고 데이터 폴더에 시크릿을 넣고 볼 수 있게 한다. 등록 권한(REQ-475), REST 경로, 수집과의 연결은 뒤의 단계다.

## 결정

1. **조립은 한 곳이다.** `cmd/praxium`의 `openSecretStore`가 파일 어댑터, 디스크, 폴더 잠금, 마스터 키 제공자, 시계, 난수를 `secrets.Service`로 묶는다. 하는 일은 넷이다: 읽기(목록, 보기. 잠금도 키도 없다), 삭제(잠금, 키 없음), 바꾸기(잠금과 키. 키는 만들지 않는다), 넣기(잠금과 키. 저장소가 비어 있고 키가 없으면 만든다). 수집 서비스가 저장소를 열 때도 이 함수를 쓴다. 난수는 `kernel.SystemBytes`다. 조립 테스트가 그것을 확인하고, `cmd/praxium`의 제품 코드가 `NewSeededBytes`와 `SeededBytes`를 쓰지 않음을 소스를 읽어 확인한다(하네스의 규칙은 바꾸지 않았다).
2. **디스크(`secretsfile.Disk`의 구현).** 파일은 0600으로 만들고 이미 있으면 실패한다. 읽을 때는 먼저 `Lstat`으로 보통 파일인지 보고(링크와 폴더는 따라가지 않고 거절), 연 뒤 같은 파일인지와 권한과 크기를 연 파일에서 다시 본다. 그룹이나 다른 사용자가 읽을 수 있으면(`mode & 0077`) 읽기를 거절하고 `chmod 600`을 말한다. 읽기 전에 크기를 보고 한도(64 MiB)까지만 읽는다. 권한 개념이 없는 운영체제(Windows)는 내장 인증의 디스크처럼 권한을 보지 않는다. 그런 운영체제에서는 권한 테스트를, 심볼릭 링크를 만들 수 없는 환경에서는 링크 테스트를 건너뛴다(테스트의 `t.Skip`이 이 결정을 가리킨다). 임시 파일, 동기화, 이름 바꾸기, 폴더 동기화는 코어의 순서대로다. 읽기만 하는 명령의 디스크는 아무것도 바꾸지 못하고 중단된 쓰기의 임시 파일도 지우지 않는다(진행 중인 쓰기의 것일 수 있다).
3. **잠금.** 바꾸는 명령은 데이터 폴더의 잠금(`LOCK`)을 잡는다. 서버가 폴더를 쥐고 있으면 `ingest run`처럼 "서버를 멈추고 다시 하라"로 실패한다. 목록과 보기는 `model show`처럼 잠금 없이 되고, 파일을 통째로 바꾸는 쓰기의 원자성이 읽는 쪽을 지킨다.
4. **마스터 키 파일의 위치.** `-secrets-key-file`이 먼저다(빈 값을 명시하면 "안 줌"이 아니라 명령줄 오류다). 없으면 사용자 설정 폴더(`os.UserConfigDir`) 아래 `praxium/keys/<데이터 폴더의 식별자>.key`이고, 설정 폴더를 얻지 못하면 키 파일을 명시하라는 오류(`secret_master_key_missing`)다. 키 파일이 데이터 폴더 안이나 그 아래를 가리키면 거절한다. 경로는 한 번만 정리하고(절대 경로로 만들고, 링크는 따라가며 `링크/..`의 `..`은 링크를 따라간 뒤에 읽는다) 그 한 가지 글자를 검사, 읽기, 만들기, 출력에 똑같이 쓴다. 검사는 글자 비교가 아니라 키 파일의 위쪽 폴더를 차례로 올라가며 `os.SameFile`로 데이터 폴더와 같은지 묻는다. 데이터 폴더와 같은 곳에 두면 폴더의 복사본이 키를 함께 가져가기 때문이다. 키 파일의 마지막 요소가 링크인 경로는 읽지 않는다(링크가 가리키는 실제 파일을 적는다). 파일을 열 때는 유닉스에서 `O_NOFOLLOW|O_NONBLOCK`을 더한다(다른 운영체제는 `Lstat` 확인만).
5. **데이터 폴더의 식별자.** [소스 편집 설계](../source-editing.md)는 식별자를 정하지 않았으므로 여기서 정한다. 키가 필요한 때 폴더에 `FOLDER_ID`가 없고 키를 만들 수 있으면(넣기) 무작위 16바이트로 `pfid-<32자리 16진수>`를 만들어, 키처럼 임시 파일에 다 쓰고 동기화한 뒤 `link`로 이름을 붙인다. 읽을 때는 보통 파일인지 보고 128바이트까지만 읽는다. 경로의 해시가 아니다. 폴더를 옮기거나 복사해도 같은 키를 찾고, 같은 경로에 폴더를 다시 만들면 다른 식별자를 얻는다. 식별자는 비밀이 아니다. 시크릿이 있는데 식별자가 없거나 깨졌으면 새로 만들지 않고, `-secrets-key-file`로 키를 지정할 수 있다는 것과 기본 키 폴더(`praxium/keys`)를 말하되 어떤 값도 싣지 않는다.
6. **키 만들기.** 넣기에서 키 파일이 없고 저장소가 비어 있을 때만 새 키를 만든다. 임시 파일에 다 쓰고 동기화한 뒤 `link`로 이름을 붙이므로 이미 있는 키를 덮지 못하고, 반쯤 쓴 키 파일을 다른 프로세스가 보지 못한다. 동시에 만들려던 쪽은 먼저 만든 키를 쓴다. 폴더 동기화가 실패하면 삼키지 않고 오류로 답한다(다시 실행하면 된다). 폴더는 0700, 파일은 0600이다. 0700은 이 명령이 만드는 폴더에만 해당하고 이미 있는 폴더의 권한은 건드리지 않는다. 저장소에 시크릿이 있는데 그것을 암호화한 키와 다른 키가 주어지면 키를 쓰는 명령(`put`, `rotate`, `retire`, `set-scope`, `set-hosts`) 모두 거절한다(`secret_master_key_mismatch`. 오류에는 두 키 id만 있다). 저장소 하나에 마스터 키가 둘이면 어느 쪽도 다 열지 못하기 때문이다. 키 파일의 권한이 느슨하면 거절한다(`secret_master_key_invalid`와 `chmod 600`). 시크릿이 있는데 키가 없으면 만들지 않고 `secret_master_key_missing`으로 "키 파일을 제자리에 두거나 `-secrets-key-file`로 지정하거나 시크릿을 지우고 다시 넣으라"고 답한다. 만든 때는 위치와 "사본을 따로 두라"를 출력한다.
7. **명령줄 `praxium secret`.** `put`(새 시크릿만. 있는 id는 충돌이고 `rotate`를 말한다), `rotate`(새 버전), `list`, `show`(메타와 키 id만), `retire`(버전), `delete`, `set-scope`, `set-hosts`. 이름을 둘로 갈라 실수로 덮는 일이 없다. 출력은 표나 `--json`(`model`의 관례). 종료 코드는 0, 1, 2. 오류는 코어의 코드(`(secret_master_key_missing)`)와 고치는 법을 말한다.
8. **값은 파일과 표준 입력으로만 받는다.** 필드마다 `-field <이름>=<파일>`이거나, `-field` 없이 표준 입력에서 종류가 정한 순서로 한 줄씩이다. 파일 끝의 줄바꿈 하나(`\n`, `\r\n`)는 값이 아니다. `-field`의 파일은 보통 파일이어야 하고 링크, 폴더, 장치, FIFO는 거절한다. 값에 NUL과 그 밖의 제어 문자(U+0000에서 U+001F, U+007F)나 맨 앞의 BOM이 있으면 `-field`로 받았든 표준 입력으로 받았든 거절하고, 오류는 문제의 종류와 필드 이름만 말한다. 인자로 값을 받는 플래그는 없다. 값을 잘못 인자로 준 경우(`-field`에 값을 적거나 남는 인자, 모르는 플래그, `-version`의 값)의 오류는 그 글자를 되풀이하지 않는 정해진 문장이다. 필드 이름은 그 종류의 진짜 필드 이름일 때만 오류에 적는다. 파일 경로도 오류에 싣지 않는다. 다른 명령의 플래그 오류는 그대로다. `-host`의 잘못된 값(접속 문자열 전체를 적은 경우)도 같다. 표준 입력이 터미널이면 화면에 값이 보이므로 거절한다(표준 라이브러리에는 화면에 찍지 않고 받는 방법이 없다. 파이프와 파일만 지원한다). `-scope`의 소스 id는 [ADR-0075](0075-definition-id-grammar-and-schema-version.md)의 문법만 본다. 그 소스가 있는지는 정의 저장소의 종류가 생긴 뒤에 본다.
9. **넣지 않은 것.** REST 경로, 열기 포트를 쓰는 수집과 어댑터와의 연결, `ingest run -credential`, 소스가 참조하는 시크릿의 삭제 금지, 감사 로그, 마스터 키의 교체, `local`과 `api serve`가 뜰 때 저장소를 여는 것, 등록 권한(REQ-475). 코어의 `Disk` 계약 가운데 이 변경이 한 것(권한, 느슨한 권한의 거절, 읽기 전 크기 한도, 폴더 잠금)과 "제품의 조립에 `NewSeededBytes`가 못 들어가게 막는 장치"는 ADR-0071의 "뒤의 변경"이다.

10. **한계(이 단계가 받아들이는 것).**
    - 기본 키 위치는 명령을 실행한 사용자의 설정 폴더다. 다른 계정으로 도는 서버나 홈이 일회용인 컨테이너는 `-secrets-key-file`을 줘야 한다.
    - 링크인 키 파일(오케스트레이터의 시크릿 볼륨)과 그룹이 읽을 수 있는 권한은 지금은 거절한다. 실제 경로를 적고 0400으로 두면 된다. 둘 다 서버가 저장소를 여는 단계에서 다시 정한다.
    - 키 파일을 데이터 폴더 안에 하드 링크로 두는 것은 "데이터 폴더 밖" 검사가 알아채지 못한다.
    - 하드 링크를 지원하지 않는 파일 시스템에서는 키 파일과 `FOLDER_ID`를 만들 수 없어 명령이 실패한다(기본 키 위치를 쓸 때는 데이터 폴더도 하드 링크를 지원해야 한다).
    - 권한 비트가 없는 파일 시스템(리눅스에 붙인 것)에서는 파일이 느슨하게 보여 읽기를 거절한다. Windows는 권한을 보지 않는다.
    - `list`와 `show`는 묶음 태그를 검증하지 않는다.
    - 같은 프로세스가 이미 `LOCK`을 쥐고 있으면 조립 함수는 실패한다. 서버 단계에는 잠금을 넘겨받는 길이 필요하다.
    - 만들기에 실패하고 남은 `.new-key-*`와 `.new-id-*` 임시 파일, 짝 없는 키 파일은 지우지 않는다.
11. **바뀐 동작.** 없는 데이터 폴더는 `put`만 만들고 나머지 명령은 "폴더가 없다"고 답한다. `set-scope`와 `set-hosts`는 바꾼 뒤의 목록을 출력한다.

## 이유

- 키를 데이터 폴더 밖에 두면 폴더의 백업이나 복사가 키를 가져가지 않는다. 무작위 식별자는 경로가 바뀌어도 키를 잇는다.
- 값을 인자로 받으면 프로세스 목록과 셸 기록에 남는다. 파일과 표준 입력은 남지 않는다.
- 터미널을 거절하는 편이 값을 화면에 보이는 것보다 낫다. 의존성을 더하지 않는다.

## 대안과 기각 사유

- **식별자를 경로의 해시로 한다.** 기각. 폴더를 옮기면 키를 잃는다.
- **`put`이 있는 id에 새 버전을 만든다.** 기각. 오타 하나가 값을 바꾼다.
- **키를 `O_EXCL`로 만들며 바로 쓴다.** 기각. 다른 프로세스가 반쯤 쓴 파일을 읽는다.
- **터미널에서 화면에 찍지 않고 받는다.** 기각. 표준 라이브러리로 되지 않고 새 모듈은 받지 않는다.

## 결과

- REQ-474를 구현과 같게 다듬고 "예정"을 뗀다(`local`의 기본 위치와 `api serve`는 서버가 저장소를 여는 단계의 일이다). "입력 폴더는 키가 있는 폴더와도 겹칠 수 없다"는 입력 폴더의 요구사항 REQ-447이 이미 적고 있어 REQ-474에서 뺀다. 새 요구사항 REQ-498(명령줄)과 REQ-499(디스크의 권한)를 더한다.
- 안내서(`operate-the-server.md`)에 시크릿 명령의 쓰는 법을, 설계 문서(`secrets-and-encryption.md`)의 "이번에 구현한 것"에 한 줄을 더한다.

## 뒤의 변경

- 명시한 키 파일의 링크 따라가기, 소유자에 따른 권한 규칙(현재 사용자는 0600 이하, root는 0640 이하), 키만 다루는 명령은 서버가 저장소를 여는 단계에서 정한다.
- 명시한 키 파일의 링크를 따라가게 할 때는 풀린 대상의 경로로 데이터 폴더 밖인지를 검사해야 한다.
- FIFO의 테스트는 빌드 조건 없이 바깥 명령 `mkfifo`(`exec.LookPath`로 찾고 없으면 건너뜀)를 쓰는 길로 더할 수 있다. `-field`의 파일이 링크나 파이프일 때의 거절을 좁힐지도 그때 정한다.
- 남은 `.new-key-*` 임시 파일과 짝 없는 키 파일의 청소는 뒤로 미룬다.
