# ADR-0038 데모 모드를 정식 기능으로 둔다

## 맥락

처음 보는 사람이 프락시움을 브라우저에서 둘러보려면 지금은 여러 단계를 거쳐야 한다. `worldgen`으로 세계 파일을 만들고, 토큰 파일을 만들고, `api serve`에 플래그를 여러 개 주고, 웹 UI의 접속 설정에 토큰을 붙여 넣는다. 첫 인상을 정하는 순간에 제품과 무관한 준비가 앞선다. 한편 이 준비물(고정된 토큰 파일, 디스크에 남는 세계 파일)은 그대로 두면 "개발용 값을 그대로 쓰는 서버"가 된다.

개발 모드 서버(ADR-0024, ADR-0027), 내장 파일 스토어(ADR-0034), 실행 파일에 담은 웹 UI(ADR-0035), 합성 세계 생성기(worldgen)가 이미 있다. 부족한 것은 이들을 한 번에 조립하는 명령 하나뿐이다.

## 결정

1. **새 명령 `praxium demo`.** 인자 없이 실행하면 합성 세계를 프로세스 안에서 만들어 KG(`dev`, 별칭 `main`)에 적재하고, 127.0.0.1의 포트(기본 8080)에서 API와 웹 UI를 낸다. 세계 파일과 토큰 파일을 디스크에 쓰지 않는다. 플래그는 `-addr`, `-data-dir`, `-scale`(기본 20000, 객체 약 7천 개와 링크 약 1만 3천 개), `-seed`(기본 1)다. 포트가 사용 중이면 세계를 만들기 전에 `-addr`로 바꾸라고 알리며 실패한다.
2. **운영 모드와 구분한다.** 데모는 개발 모드 서버(`api serve -mode development`)의 조립을 그대로 쓴다(`runServer`). 별도의 서버 코드, 별도의 인증기, 별도의 API 경로가 없다. 운영 모드(`-mode production`)는 지금처럼 실제 인증기가 없어 시작을 거부하고, 데모는 그 거부를 우회하지 않는다. 데모 서버의 주체는 `viewer` 역할 하나이므로 읽기만 된다.
3. **스토리지.** 기본은 인메모리 스토어이고 끄면 사라진다. `-data-dir <폴더>`를 주면 내장 파일 스토어를 써서 다시 실행해도 KG가 남는다. 이미 KG가 있는 폴더는 다시 적재하지 않는다. 첫 적재가 끝나지 않은 KG가 든 폴더는 폴더를 지우고 다시 시작하라는 오류로 멈춘다. Ctrl+C(또는 종료 신호)로 서버를 닫고 파일 스토어는 마지막 스냅샷을 쓴다.
4. **토큰은 실행마다 새로 만든다.** 커널의 엔트로피(`kernel.NewToken`, 16바이트, 16진수 32자)로 만들고 프로세스 안에만 둔다. 고정된 기본 토큰이나 기본 비밀번호는 없다. 터미널에 접속 주소를 한 줄로 출력하고, 토큰은 주소의 **프래그먼트**(`#` 뒤)에 있다: `http://127.0.0.1:8080/#/connect?token=<토큰>&demo=1`. 프래그먼트는 브라우저가 서버로 보내지 않으므로 서버 로그, 프록시 로그, `Referer`에 남지 않는다. 쿼리 문자열이면 서버의 접근 기록에 남는다.
5. **웹 UI의 처리.** 진입점(`main.tsx`)이 화면을 그리기 전에 `data/entry.ts`의 `applyEntry`를 부른다. 주소가 `#/connect?token=…`이면 토큰을 접속 저장소(`connection`)에 넣고, 주소를 첫 화면(`#/kg/main/types`, 데모 표시가 없으면 `#/kgs`)으로 바꾼다(`history.replaceState`라서 기록에도 토큰이 남지 않는다). 토큰 입력이 필요 없다.
6. **데모 표시.** 서버가 자신이 데모임을 알리는 기존 계약(헬스 응답의 필드 등)은 없다. 계약을 새로 설계하지 않고 가장 작은 방법을 택했다. 데모 표시를 프래그먼트(`demo=1`)에 함께 넣어 웹 UI가 기억한다. 표시는 "데모 표시가 들어온 토큰"을 저장하는 방식이라, 사용자가 다른 토큰을 입력하거나 토큰을 지우면 데모가 아닌 것으로 본다. 같은 주소의 다른 서버에 데모 표시가 남지 않는다. 데모이면 화면 맨 위에 "합성 데이터이며 실제 시스템과 연결되어 있지 않다, 운영용이 아니다"라는 안내 줄과 제품 이름 옆 배지를 보인다.
7. **시작 출력.** 영어 한 문단이다. 합성 데이터이고 실제 시스템과 연결되지 않으며 운영용이 아니라는 문장, 적재한 객체와 링크 수, 접속 주소, 데이터가 메모리에만 있는지 폴더에 남는지, 종료 방법을 낸다.
8. **바인드 주소.** 기본은 루프백이다. 루프백이 아닌 주소(`0.0.0.0`, 사설 주소 등)로 띄우면 데모 토큰은 터미널에 찍히고 평문 HTTP로 오가는 약한 보호라는 경고를 낸다. 막지는 않는다.
9. **웹 UI가 없는 빌드.** 자리표시자 빌드에서 `demo`를 실행하면 "웹 UI가 포함되지 않은 빌드이니 `scripts/build-with-web.sh`로 빌드하거나 릴리스 실행 파일을 쓰라"고 안내한다. API와 CLI는 그대로 쓸 수 있도록 이번 실행의 토큰과 `kg list`, `query find` 사용 예를 출력한다.
10. **구조.** 새 유닛과 새 의존성이 없다. `cmd.praxium`의 `demo.go`가 조립한다. `api serve`의 조립을 `runServer`로 꺼내 두 명령이 공유하고(`serverPlan`), 적재 코드는 열린 입력을 받는 `loadTruthFrom`을 더했다. `os`는 `cmd.praxium`만 쓴다는 규칙과 어떤 유닛의 `may_import`도 바뀌지 않는다. 데모 명령에 맞춘 서버 쪽 `listenFirst`(포트를 적재보다 먼저 연다)는 `api serve`의 순서(적재 뒤 연다, 잠긴 테스트가 요구한다)를 바꾸지 않는다.

### 바뀐 설정과 보호 경로

| 경로 | 바뀐 것 | 이유 |
|---|---|---|
| `AGENTS.md` | 데모 실행 예시 한 줄 | 가장 짧은 시작 절차 안내 |
| `docs/product-specs/requirements.md` | REQ-280, REQ-281 추가 | 요구사항 표의 변화 |
| `harness/config/test-lock.json` | 새 테스트의 지문(`pnpm lock-tests`가 쓴다) | 새 테스트의 잠금. 기존 항목은 바뀌지 않았다 |

규칙, 한도, 허용 목록, 잠긴 테스트는 느슨하게 하지 않았다.

## 이유

- 처음 쓰는 사람의 비용은 단계 수에 비례한다. 조립이 이미 있으니 명령 하나가 가장 싸고, 별도의 "쉬운 서버"를 만들지 않으므로 데모와 개발 모드가 갈라지지 않는다.
- 고정 토큰은 쓰기 쉽지만 "개발용 값이 운영에 남는" 사고의 원인이다. 실행마다 새 토큰이면 알려진 값이 존재하지 않는다. 프래그먼트에 넣는 것은 사용자가 토큰을 옮겨 적는 단계를 없애면서도 서버 로그에 남기지 않는 가장 작은 방법이다.
- 데모 표시를 서버 계약에 넣으면 OpenAPI 문서와 생성 코드, 적합성 테스트가 함께 바뀐다. 표시는 화면의 일이고 임시 콘솔은 곧 지울 수 있어야 하므로(TD-0007) 화면 쪽에서 끝낸다.
- 메모리 기본값은 "끄면 사라진다"는 약속을 주고 디스크에 아무것도 남기지 않는다. 남기고 싶은 사람은 폴더를 준다.

## 대안과 기각 사유

- **고정된 기본 토큰.** 쉽지만 알려진 자격 증명이 된다. 기각했다.
- **토큰을 쿼리 문자열이나 경로에 넣기.** 서버 접근 기록과 프록시 로그에 남는다. 기각했다.
- **토큰 없이 인증을 끈 데모 서버.** 인증기 없는 서버를 허용하는 것이고 루프백이 아닌 주소에서 위험하다. 기각했다.
- **서버가 `/v1`로 데모 여부를 알리기.** 계약 변경이 필요하고 삭제할 화면을 위해 영구 계약이 늘어난다. 기각했다.
- **`api serve`에 `-demo` 플래그.** 플래그 조합이 늘고 "인자 없이 실행"이라는 목적에 맞지 않는다. 기각했다.

## 결과

- 한계. 데모 토큰은 약한 보호다: 터미널에 찍히고 평문 HTTP로 오간다. 루프백 밖으로 열지 않는다. 합성 데이터이므로 노출돼도 실제 정보는 없지만 서버는 읽기 접근을 내준다.
- 한계. 프래그먼트 방식은 웹 UI가 있는 빌드에서만 쓴다. 이미 열린 주소를 다른 사람에게 보내면 토큰도 간다.
- 한계. 파일 스토어는 단일 프로세스이고(ADR-0034), 폴더가 있으면 `-scale`과 `-seed`는 무시된다(이미 적재된 KG를 그대로 쓴다).
- 임시 콘솔을 지울 때(TD-0007) 웹 쪽의 `entry.ts`와 배너도 함께 지운다. 그때 `demo`는 안내 출력과 API, CLI만 남는다.
