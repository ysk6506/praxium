# ADR-0031 Go 툴체인을 지원 중인 버전으로 올리고, 지원이 끝나기 전에 올린다

## 맥락

백엔드는 Go 1.24를 썼고 개발 환경의 툴체인은 1.24.7이었다. 이 버전은 Go 팀의 지원이 끝나 보안 수정을 더 받지 못한다. Go는 최신 두 마이너 버전만 지원한다.

`backend/go.mod`의 `go` 지시문이 CI(`.github/actions/setup`의 `go-version-file`)와 로컬 요구 버전을 함께 정한다. 하네스는 `GOTOOLCHAIN=local`로 Go를 돌리므로 설치된 Go가 지시문보다 낮으면 검사가 실패한다. 버전을 적은 곳은 `backend/go.mod`, README.md, AGENTS.md였다.

## 결정

1. `backend/go.mod`의 `go` 지시문을 지원 중인 최신 마이너의 최신 패치인 `go 1.27.4`로 올린다. README.md와 AGENTS.md의 요구 버전도 맞춘다.
2. 앞으로 사용 중인 마이너의 지원이 끝나기 전에 올린다. 새 마이너가 나오면 그다음 마이너가 나오기 전까지 올리는 것을 기준으로 한다. 올리는 변경은 `go.mod`와 버전을 적은 문서만 고치고, 새 vet이 지적한 것은 같은 변경에서 코드를 고친다.
3. 패치 버전까지 적는다. 보안 수정이 들어간 패치보다 낮은 Go로는 빌드되지 않게 한다.

## 이유

- 지원이 끝난 툴체인은 표준 라이브러리와 컴파일러의 알려진 취약점을 고치지 못한다. 공개 제품이라 사용자가 같은 Go로 빌드한다.
- 마이너를 한 번에 하나씩, 지원이 끝나기 전에 올리면 변경이 작고 리버트하기 쉽다. 늦게 올릴수록 한 번에 건너는 폭이 커진다.
- 하네스에는 Go 버전을 따로 고정한 설정이 없고 `go.mod`가 하나뿐인 기준이라, 올릴 곳이 적고 어긋나기 어렵다.

## 대안과 버린 이유

- 마이너만 적기(`go 1.27`): 첫 패치(1.27.0)로도 통과해 보안 수정이 빠진 Go로 빌드될 수 있다.
- 지원이 끝난 뒤에 올리기: 그동안 수정되지 않은 취약점이 남는다.
- 하네스에 버전 고정 설정 추가: 기준이 둘이 되어 어긋날 수 있다. `go.mod`가 기준이다.

## 결과

- 개발 환경의 네트워크 제약으로 공식 배포본을 내려받을 수 없어, 이번에는 태그의 소스를 받아 기존 Go로 부트스트랩해 빌드한 툴체인으로 검증했다. 일반 환경에서는 공식 배포본을 쓰면 된다.
- 1.27.4에서 `go build`, `go vet`, `go test`는 코드 변경 없이 통과했다.
- 기여자는 Go 1.27.4 이상이 필요하다.
