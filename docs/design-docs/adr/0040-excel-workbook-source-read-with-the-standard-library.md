# ADR-0040 엑셀 워크북을 표준 라이브러리로 읽는 소스와 살펴보기 명령

## 맥락

수집(`praxium ingest run`)은 CSV와 JSON Lines만 읽었다(ADR-0033). 제품 책임자가 첫 실제 데이터를 엑셀로 넣어 볼 예정이고, 현실의 엑셀은 표가 아니다. 머리글 위에 제목 줄이 있고, 분류 컬럼이 병합 셀로 묶여 있고, 머리글이 두 줄이고, 중간에 빈 행과 소계 행이 끼고, 자산 번호가 숫자 셀로 저장되고, 수식과 오류 셀이 섞인다. 이것을 넣었을 때 무엇이 들어갔고 무엇이 왜 안 들어갔는지를 출력만 보고 알 수 있어야 한다. 매핑을 쓰기 전에 파일을 파악하는 수단도 필요하다(설계 문서의 "매핑을 만드는 사람을 돕는 API", 프로파일과 미리 보기).

## 결정

**1. 서드파티 의존성 0.** .xlsx는 ZIP 안의 XML이므로 `archive/zip`과 `encoding/xml`로 읽는다. 엑셀 라이브러리를 추가하지 않는다. 새 외부 모듈이 없어서 `third_party`와 모듈 표는 바뀌지 않는다.

**2. 유닛.**

| 유닛 | 하는 일 |
|---|---|
| `adapter.xlsx` (`backend/internal/xlsx`) | 워크북 바이트를 `ingest.Workbook`(시트, 셀, 병합 범위, 숨김)으로 읽는다. 안전 한도와 지원하지 않는 파일의 오류를 가진다. 테스트가 쓰는 작은 작성기(`Book`)도 같은 유닛에 있고 제품은 부르지 않는다 |
| `core.ingest` | 워크북 모델과 포트(`WorkbookReader`), 데이터셋의 시트 옵션, 시트를 행으로 만드는 단계, 파일의 프로파일(`Inspect`)을 가진다. 파일도 어댑터도 모른다 |
| `cmd.praxium` | `ingest run`이 읽기 어댑터를 연결하고, `ingest inspect`를 더한다 |

파일 내용은 지금처럼 `Capture`의 바이트로 들어온다. ZIP은 임의 접근이 필요하지만 바이트 조각을 `bytes.Reader`로 열면 되므로 파일 열기 포트(`Opener`)는 바꾸지 않았다. 기존 유닛의 `may_import`는 넓히지 않았다. `adapter.ingestcheck`의 `test_may_import`에 `adapter.xlsx`를 더했다(테스트 파일만).

**3. 읽는 범위.** 워크북의 시트 목록(상태: 보임, 숨김, 완전히 숨김), 공유 문자열(여러 글꼴의 조각은 이어 붙이고 한자와 한글의 발음 표기는 뺀다)과 인라인 문자열, 숫자, 불리언, 오류 셀, 날짜, 수식 셀의 저장된 값, 병합 범위, 숨긴 시트와 행과 열. 값을 글로 바꾸는 규칙은 결정적이다.

| 셀 | 글 |
|---|---|
| 정수 | `.0` 없이: `10001` |
| 큰 수와 지수 표기로 저장된 수 | 지수 없이 자릿수 그대로: `1.23456789012346E+019`는 `12345678901234600000` |
| 글(앞자리 0이 있는 것 포함) | 그대로: `00123` |
| 불리언 | `true`, `false` |
| 날짜 | 셀 스타일의 숫자 서식으로 판별한다. 1900과 1904 날짜 체계를 처리한다. 날짜는 `2026-03-14`, 시각이 있으면 `2026-03-14T09:30:00Z`(워크북에는 시간대가 없다), 시각만이면 `09:30:00`. 초로 반올림한다 |
| 오류 셀(`#N/A`) | 값이 없다. 문제로 보고한다 |
| 수식 | 파일에 저장된 계산 값. 값이 없으면(계산된 적 없는 파일) 값이 없고 문제로 보고한다 |

숫자가 날짜인지는 서식 코드를 읽어 정한다(내장 서식 번호 표, 그리고 따옴표와 역슬래시와 괄호를 뺀 뒤 `y`, `d`, `h`, `s`, 시각이 없는 `m`의 유무). 날짜가 아닌 숫자 서식(퍼센트, 지수, 통화)은 숫자로 둔다. 시간 속성(`vt.time`)에 날짜만 있는 글(`2026-03-14`)이 오면 그날 0시(UTC)로 읽는다. 이것은 `core.ingest`의 값 변환에 더한 한 가지 규칙이다.

**4. 읽지 않는 것, 따라가지 않는 것.** 옛 .xls(바이너리), 암호가 걸린 파일, 깨진 ZIP, .xlsb, .ods, ZIP이지만 워크북이 아닌 것은 무엇이 문제인지 말하는 오류로 거절한다(수집은 그 데이터셋 이름과 함께 실패한다). 파일 이름이 아니라 내용으로 판별한다(`.csv`라는 이름의 .xls도 .xls라고 답한다). 매크로 파일(.xlsm)은 데이터만 읽는다. 매크로 부분은 열지 않고 실행하지 않는다. 외부 링크와 외부 데이터 연결과 외부를 가리키는 관계(`TargetMode="External"`)는 열지 않는다. 읽는 것은 바이트뿐이고 네트워크 접근이 없다. 수식은 다시 계산하지 않는다. 차트 시트는 목록에만 있고 읽지 않는다.

**5. 안전 한도.** 넘으면 수집을 실패시키고 어느 한도인지와 올리는 방법을 알린다. 한도는 소스 정의의 `limits`로 바꾼다.

| 한도 | 기본값 | 막는 것 |
|---|---|---|
| `max_uncompressed_bytes` | 256 MiB | 압축 폭탄. 읽을 부분이 선언한 크기를 먼저 보고(압축을 풀기 전에 거절), 풀면서 센다 |
| `max_rows_per_sheet` | 200,000 | 값이 있는 셀의 행 번호 |
| `max_columns_per_sheet` | 1,024 | 값이 있는 셀의 열 번호 |
| `max_cell_chars` | 32,767 | 셀 한 칸의 글자 수(엑셀 자신의 한도) |
| `max_shared_strings` | 2,000,000 | 공유 문자열의 수 |

파일 크기의 한도(20 MB)는 지금처럼 파일 소스 어댑터가 가진다.

**6. 데이터셋의 시트 옵션.** 데이터셋의 파서가 `xlsx`이면 `sheet` 객체를 둘 수 있다. 모두 기본값이 있어서 단순한 표는 옵션 없이 읽는다. 기존 CSV와 JSON Lines 정의는 그대로 동작하고, 그 데이터셋에 `sheet`를 쓰면 정의 검사가 거절한다.

| 옵션 | 뜻 | 기본 |
|---|---|---|
| `name` / `index` | 시트의 이름, 또는 순번(1부터). 하나만 쓴다 | 첫 시트 |
| `header_row` | 머리글 행 번호 | 1 |
| `header_rows` | 머리글의 행 수. 둘 이상이면 행마다 정규화한 글을 공백으로 이어 컬럼 이름으로 쓴다(`Spec`과 `CPU`는 `Spec CPU`). 병합된 머리글 칸은 병합 범위의 모든 열에 같은 글이 있는 것으로 본다 | 1 |
| `range` | 데이터 범위, 시작 셀과 끝 셀(`A5:F200`). 범위의 열이 읽는 열이다. 범위는 머리글 아래여야 한다 | 머리글 아래부터 끝까지, 모든 열 |
| `merged_cells` | `first_only`(값은 병합 범위의 첫 셀에만) 또는 `fill`(범위의 모든 셀이 첫 셀의 값) | `first_only` |
| `stop_after_blank_rows` | 빈 행이 연속 N개이면 그 뒤는 데이터의 끝이다(뒤의 비고 같은 것). 빈 행은 늘 건너뛴다 | 0(끝으로 보지 않는다) |
| `skip_hidden_rows` | 숨긴 행을 뺀다 | 읽는다(보고에 개수가 나온다) |

머리글 이름의 별칭은 기존 컬럼의 `paths`가 한다(CSV와 같다). 머리글과 `paths`는 비교 전에 정규화한다: 앞뒤 공백을 없애고 줄바꿈과 연속 공백(줄바꿈 없는 공백 문자 포함)을 공백 하나로 바꾼다. 그래서 칸 안에서 줄을 바꿔 쓴 `랙\n위치 `는 `랙 위치`다. `merged_cells`의 기본을 `first_only`로 둔 것은 파일에 있는 그대로를 읽고, 병합을 채울지는 정의가 밝히게 하기 위해서다. 채우지 않아 식별자가 비는 행은 문제에 셀 위치와 함께 나온다.

**7. 행 집계와 문제 보고.** 행 집계는 그대로다(받은 행 = 읽은 행 + 읽지 못한 행, 읽은 행 = 사용됨 + 규칙이 걸러 냄 + 문제 + 안 쓰임). 받은 행은 데이터 범위의 빈 행이 아닌 행이다. 건너뛴 행은 합계에 들어가지 않고 이유별로 센다(`blank_row`, `hidden_row`, `after_end`). 문제에는 시트 이름과 위치(`Where`)가 붙는다: 셀이 원인이면 셀 주소(`'서버 목록'!F6`, 식별자 칸이 빈 행은 그 칸), 행이 원인이면 읽는 열의 범위(`'서버 목록'!A5:F5`). 시트 이름에 글자와 숫자와 밑줄 외의 것이 있으면 엑셀처럼 작은따옴표로 감싼다. 값이 없는 셀(오류 셀, 계산된 적 없는 수식)은 읽는 컬럼에서만 `cell_error`, `formula_without_value` 문제로 보고하고, 행은 그대로 읽는다(값 없이). 시트가 없거나 읽을 컬럼의 머리글이 없으면 그 데이터셋의 형태가 바뀐 것(`shape_changed`)이고 다른 데이터셋은 계속 수집한다. 원본 레코드의 위치는 내용이 같으면 최신 위치로 고친다(내용이 같으므로 변경으로 세지 않는다). 보고에는 시트, 시트의 상태, 읽은 숨긴 행과 숨긴 열의 수, 건너뛴 행의 수가 나온다.

**8. 살펴보기 명령.** `praxium ingest inspect -input <파일> [-sheet 이름|번호] [-header-row N] [-header-rows N] [-rows N] [-format csv|jsonl|xlsx] [-o table|json]`는 CSV, JSON Lines, 엑셀을 읽어 프로파일을 낸다. 필드 이름은 설계 문서를 따른다: 컬럼마다 `name`, `value_type`, `empty_ratio`(빈 값 비율), `distinct_count`(고유 값 수), `top_values`(빈출 값), `shape`(값의 형태), 표마다 `sample_rows`. 엑셀이면 시트 목록(`state`, `used_range`, `rows`, `columns`, 숨긴 행과 열의 수, 병합 범위의 수)과 추정한 머리글 행(`header_row`, 지정하지 않았으면 `header_guessed`)이 더해진다. 머리글 행은 처음 30행 가운데 셀 수가 가장 넓은 행만큼(절반 이상) 있고 모두 글이며 서로 다른 첫 행으로 추정한다(한 칸짜리 제목 줄은 후보가 아니다). 읽기만 하고, 파일을 쓰거나 매핑을 적용하지 않는다. 매핑 제안(`suggest`)은 이 결정의 범위 밖이다.

**9. 실제 도구의 파일과의 호환(확인한 것).** openpyxl 3.1.5와 LibreOffice 24.2.7.2로 같은 내용(한글 시트 이름과 값, 글, 앞자리 0 글, 숫자, 큰 수, 날짜, 병합 셀, 수식, 오류, 빈 행, 숨긴 시트, 숨긴 행과 열)의 파일을 만들어 읽어 보고 저장 방식의 차이를 테스트 작성기의 옵션으로 재현했다.

| 차이 | openpyxl | LibreOffice | 처리 |
|---|---|---|---|
| 문자열 | 인라인 문자열(`t="inlineStr"`), 공유 문자열 파일 없음 | 공유 문자열, 글꼴이 다른 조각(`<r>`)으로 쪼개짐(한글과 영문 글꼴), `xml:space="preserve"` | 둘 다 읽고 조각을 이어 붙인다 |
| 관계의 대상 | 절대 경로 `/xl/worksheets/sheet1.xml` | 상대 경로 | 둘 다 풀어서 찾는다. 시트는 파일 이름이 아니라 관계 ID로 찾는다 |
| 숫자 글 | `t="n"`, `1.234567890123457e+19` | `1.23456789012346E+019`(지수 3자리, 15자리) | 자릿수를 그대로 평면 십진수로 바꾼다. 도구가 쓰면서 잃은 자릿수는 되살릴 수 없다(`12345678901234567890`은 두 도구에서 `...570000`과 `...600000`이 된다) |
| 수식 | `<f>`와 빈 `<v></v>`. 계산된 값이 없다 | `<f aca="false">`와 저장된 값, 불리언 수식의 `TRUE()`, 오류 수식의 `t="e"` | 값이 없는 수식은 문제로 보고하고 저장된 값은 쓴다 |
| 불리언 속성 | `hidden="1"`, `date1904="1"` | `hidden="true"`와 `"false"`, `date1904="false"` | `1`과 `true`를 같게 읽는다 |
| 날짜 서식 | 사용자 정의 `yyyy-mm-dd` | `yyyy\-mm\-dd`(역슬래시), 서식 코드가 `General`인 사용자 정의 번호 164와 166 | 역슬래시와 따옴표와 괄호를 벗겨서 판별한다. `General`은 날짜가 아니다 |
| 시각 | `46096.39583333334` | `46096.3958333333`(15자리) | 초로 반올림해서 둘 다 `09:30:00`이 된다 |
| 네임스페이스 | 각 `<sheet>`에 `xmlns:r`을 따로 선언, 접두사 없음 | 루트에 선언 | 요소와 속성을 지역 이름으로 읽는다(접두사가 붙은 파일은 테스트 작성기로 재현) |
| 병합 | 가려진 셀이 없다 | 가려진 셀이 값 없는 `<c r="C6" s="6"/>`로 있다 | 값 없는 셀은 저장하지 않는다 |
| 숨김 | `<cols><col hidden="1" min max/>`, `<row hidden="1">` | 모든 행에 `hidden="false"`, 숨긴 시트는 `state="hidden"` | 열은 범위로 둔다 |
| 빈 행 | `<row r="6"></row>` | 셀이 없는 행은 아예 없다 | 셀이 없는 행은 저장하지 않고 번호 사이의 틈으로 센다 |
| 글자 | 한글을 숫자 문자 참조(`&#51228;`)로 | UTF-8 그대로 | 둘 다 같은 글이 된다 |

엑셀 자신의 파일은 이 환경에서 만들 수 없어서 직접 확인하지 못했다. 엑셀이 쓰는 공통 형식(공유 문자열, `_xHHHH_` 이스케이프, 병합, 숨김, 날짜 서식, 접두사가 붙은 요소, 매크로 파일의 내용 유형)은 작성기로 재현해 테스트한다.

## 이유

- 서드파티 라이브러리는 의존성과 라이선스와 공급망을 늘리고, 읽을 범위는 셀 값과 스타일과 병합 정도라 표준 라이브러리로 충분하다. 읽는 코드가 작아서 안전 한도(압축 풀기, 행, 열, 셀 길이)를 우리가 정할 수 있다.
- 워크북을 `core.ingest`의 모델(`Workbook`)로 바꿔 넘기면 시트를 행으로 만드는 일(머리글, 범위, 병합, 빈 행)은 순수한 계산이라서 어댑터 없이 테스트하고, 읽기 어댑터는 ZIP과 XML만 안다.
- 문제의 위치가 셀 주소여야 엑셀을 여는 사람이 바로 그 칸을 찾는다. 줄 번호(`Line`)만으로는 시트와 열을 알 수 없다.
- 프로파일은 설계가 이미 정한 매핑 도우미의 첫 구현이다. 파일을 보고 머리글 행과 컬럼과 값의 모양을 안 다음에 소스 정의를 쓰게 한다.

## 대안과 버린 이유

- 서드파티 엑셀 라이브러리: 의존성 추가는 승인되지 않았고, 한도와 읽지 않을 것(매크로, 외부 링크)을 우리가 통제하기 어렵다.
- 엑셀을 CSV로 바꿔 읽기: 변환 도구가 필요하고, 병합, 숨김, 날짜, 셀 위치가 사라진다.
- 외부 도구(LibreOffice)로 변환: 실행 파일 하나로 쓰는 처음 써 보기와 맞지 않고, 외부 프로세스를 띄우게 된다.
- 병합을 항상 채우기: 파일에 없는 값을 말없이 만든다. 정의가 밝히게 했다.
- 파일 열기 포트에 `io.ReaderAt`와 크기를 넘기는 통로를 더하기: 파일을 이미 바이트로 읽어서 `bytes.Reader`로 충분하다. 20 MB 한도 안이다.

## 결과

- `praxium ingest run`이 `parser: xlsx` 데이터셋을 읽고(같은 워크북을 여러 데이터셋이 가리켜도 한 번만 읽는다), `praxium ingest inspect`가 새로 생겼다. 샘플 정의는 `backend/internal/ingestcheck/samples-xlsx/`에 있다(기존 `testdata` 폴더에 두면 그 폴더를 읽는 잠긴 테스트의 지문이 바뀌어서 따로 뒀다). 테스트용 .xlsx는 커밋하지 않고 테스트 안에서 작성기로 만든다.
- 요구사항 REQ-284~288. 합격 테스트는 합성한 세계를 워크북 하나(시트 다섯 개)로 만들어 수집하면 CSV와 JSON Lines로 수집한 KG와 그래프 해시가 같고 다시 수집해도 변경이 없음을 확인한다.
- 보호 경로 변경: `harness/config/architecture.yaml`(새 유닛 `adapter.xlsx`의 등록, `adapter.ingestcheck`의 `test_may_import`에 `adapter.xlsx`), `harness/config/coverage-floor.json`(새 유닛의 하한), `harness/config/test-lock.json`(새 테스트의 잠금), `docs/product-specs/requirements.md`, `AGENTS.md`(실행 예). 기존 유닛의 `may_import`와 한도는 바꾸지 않았다.
- 한계: 값이 없는 수식의 값을 다시 계산하지 않는다. 엑셀의 표(Table) 객체, 피벗, 필터 상태, 셀 서식(색)은 읽지 않는다. 암호가 걸린 파일은 거절만 하고 풀지 않는다. 시각은 초 단위이고 시간대가 없다. 숨긴 시트를 읽으면 보고에 숨김이라고 나온다. 매핑 제안(`suggest`)과 미리 보기의 나머지는 남아 있다.
