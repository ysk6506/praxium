# ADR-0003 리포지토리에는 공개된 사실만 둔다 — 내부에서 들은 사실, 실제 데이터, 시크릿은 넣지 않는다

## 맥락
이 리포지토리는 공개돼 있다. 프락시움은 현실 시스템에 연결하는 제품이라, 테라리움보다 내부 사실과 실제 데이터에 가까이 있다. 한 번 올라간 것은 수정해도 이력에 남는다.

## 결정
1. **내부에서 들은 사실을 적지 않는다.** 어느 조직이 무엇을 개발·검증·운영하는지, 내부 시스템의 이름·구조·규모·제조사, 조직과 절차가 그것이다. 코드, 문서, 결정 기록, 풀 리퀘스트, 이슈, 커밋 메시지 모두에 해당한다. 필요하면 요구사항의 표현으로 바꿔 적는다("소스가 수천 개의 장비를 제공한다" 대신 "객체 수만 개까지 수집한다").
2. **실제 데이터를 넣지 않는다.** 테스트와 샘플은 가상의 값만 쓴다. 현실 소스의 구조를 모방할 때도 컬럼 이름과 중복 구조만 따르고 값은 가상으로 만든다.
3. **시크릿을 넣지 않는다.** 주소, 계정, 토큰, 인증서는 리포지토리 밖(환경 변수나 시크릿 매니저)에 두고, 설정에는 그것을 가리키는 이름만 적는다. 프락시움은 입력받은 시크릿을 반환하지 않고 로그에 남기지 않는다.
4. **누가 말했는지는 "제품 책임자"까지만 적는다.** 사람의 이름과 메일 주소를 적지 않는다. 테스트의 샘플 사용자는 가상의 이름을 쓴다.
5. **리포지토리를 비공개로 바꿔도 2와 3은 그대로다.** 1은 그때 다시 정한다.

## 이유
- 공개 리포지토리의 이력은 삭제할 수 없다고 봐야 한다.
- 제품이 현실에 가까울수록 실수의 비용이 크다. 규칙이 처음부터 있어야 습관이 된다.

## 버린 대안
- **비공개로 시작하고 규칙은 나중에**: 리포지토리의 공개 여부는 제품 책임자가 정한다. 규칙은 어느 쪽에서도 필요하다.
- **기계가 걸러 주기를 기다리기**: 시크릿의 형식은 탐지해도 "이것이 내부 사실인가"는 판별하지 못한다.

## 결과
AGENTS.md의 절대 규칙에 한 줄을 넣었다.
