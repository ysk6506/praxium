# ADR-0003 저장소에는 공개된 사실만 둔다 — 내부에서 들은 사실, 실제 데이터, 비밀 값은 넣지 않는다

## 맥락
이 저장소는 공개돼 있다. 프락시움은 현실 시스템에 연결하는 제품이라, 테라리움보다 내부 사실과 실제 데이터에 가까이 있다. 한 번 올라간 것은 고쳐도 이력에 남는다.

## 결정
1. **내부에서 들은 사실을 적지 않는다.** 어느 조직이 무엇을 개발·검증·운영하는지, 내부 시스템의 이름·구조·규모·제조사, 조직과 절차가 그것이다. 코드, 문서, 결정 기록, 풀 리퀘스트, 이슈, 커밋 메시지 모두에 해당한다. 필요하면 요구의 말로 바꿔 적는다("소스가 수천 개의 장비를 준다" 대신 "객체 수만 개까지 받는다").
2. **실제 데이터를 넣지 않는다.** 시험과 견본은 지어낸 것만 쓴다. 현실 소스의 생김새를 본뜰 때도 열 이름과 겹침 구조만 본뜨고 값은 지어낸다.
3. **비밀 값을 넣지 않는다.** 주소, 계정, 토큰, 인증서는 저장소 밖(환경 변수나 비밀 저장소)에 두고, 설정에는 그것을 가리키는 이름만 적는다. 프락시움은 받은 비밀 값을 되돌려 주지 않고 로그에 찍지 않는다.
4. **누가 말했는지는 "제품 책임자"까지만 적는다.** 사람의 이름과 메일 주소를 적지 않는다. 시험의 견본 사용자는 지어낸 이름을 쓴다.
5. **저장소를 비공개로 바꿔도 2와 3은 그대로다.** 1은 그때 다시 정한다.

## 이유
- 공개 저장소의 이력은 지울 수 없다고 봐야 한다.
- 제품이 현실에 가까울수록 실수의 값이 크다. 규칙이 처음부터 있어야 습관이 된다.

## 버린 길
- **비공개로 시작하고 규칙은 나중에**: 저장소의 공개 여부는 제품 책임자가 정한다. 규칙은 어느 쪽에서도 필요하다.
- **기계가 걸러 주기를 기다리기**: 비밀 값의 모양은 걸러도 "이것이 내부 사실인가"는 가리지 못한다.

## 결과
AGENTS.md의 절대 규칙에 한 줄을 넣었다.
