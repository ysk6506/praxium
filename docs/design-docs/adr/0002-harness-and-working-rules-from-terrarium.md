# ADR-0002 구조와 하네스는 테라리움의 것을 가져온다 — 기계가 강제하는 규칙, 짧은 지도, 스스로 낡았음을 아는 문서

## 맥락
제품 책임자는 프락시움의 프로젝트 구조를 테라리움과 같게 잡으라고 했다. 테라리움의 구조는 OpenAI의 하네스 엔지니어링 글(https://openai.com/ko-KR/index/harness-engineering/)에서 왔다: 코드를 쓰는 것은 에이전트이고, 사람이 할 일은 에이전트가 길을 잃지 않는 환경을 만드는 것이다. 테라리움은 이 구조로 결정 기록 190여 개와 요구사항 120여 개를 쌓는 동안 배운 것이 있다.

## 결정
1. **구조는 테라리움과 같다.**

   | 자리 | 무엇 |
   |---|---|
   | `AGENTS.md` | 지도. 120줄 이하. 깊이는 링크로 |
   | `ARCHITECTURE.md` | 단위와 의존 방향 |
   | `docs/product-specs/requirements.md` | 목표와 요구사항(`REQ-NNN`)의 단일 출처 |
   | `docs/design-docs/` | 설계 문서, 제품 설계 한 장, 용어집 |
   | `docs/design-docs/adr/` | 결정 기록. 봉인되어 본문을 고치지 않는다 |
   | `docs/exec-plans/` | 계획과 기술 부채 장부 |
   | `docs/generated/` | 하네스가 만드는 것(결정 목록, 품질 등급표) |
   | `docs/verified/` | 문서 확인 기록. (문서, 대상)마다 파일 하나 |
   | `docs/archive/` | 더 고치지 않는 문서. 검사하지 않는다 |
   | `harness/` | 구조 검사와 그 설정. 보호 경로 |
   | `packages/core/` | 플랫폼을 모르는 코어. 단위는 폴더 |
   | `.github/` | CI. 필수 검사는 `gate` 하나 |

2. **하네스는 테라리움의 한 시점(커밋 3a8a83d)을 복사한다.** 검사는 열이다: 구조(의존 방향, 공개 경계, 허용한 패키지, 시계와 난수), 문서, 부채, 검사 끄기, 시험 잠금, 요구사항 추적, 화면의 말, 품질 등급표, 보호 경로, 커버리지. 제3자 라이선스 검사는 구조 검사에 실려 돈다.
3. **가져오지 않은 것.** 테라리움 제품에 묶인 것은 뺐다: 화면 도우미 검사, UX 측정과 그 CI 조각, 시험 조각 합계 검사. UX 측정은 첫 화면이 생길 때 가져온다(TD-0002).
4. **요구사항 번호.** 하네스의 시험이 가리키는 프로세스 요구사항(REQ-020~025)은 테라리움과 같은 번호와 같은 뜻으로 둔다. 하네스를 다시 맞출 때 시험을 고치지 않기 위해서다.
5. **테라리움이 겪고 고친 것은 처음부터 고친 채로 시작한다.**
   - 문서의 확인 상태는 문서 앞부분이 아니라 (문서, 대상)마다의 기록 파일에 둔다. 병렬 변경이 부딪히지 않는다.
   - 하네스가 만드는 파일(결정 목록, 품질 등급표, 색인의 문서 목록)은 변경마다 커밋하지 않는다. 정리 작업이 만든다.
   - 따라가기는 한 방향이다: 목표 → 요구사항 → 설계 → 계획. 두 문서가 서로를 따라가지 않는다.
   - 시험과 커버리지는 한 번에 돌린다. 문서만 바뀐 변경은 가벼운 CI 경로를 탄다.
   - 계획은 날짜가 아니라 순서로 관리한다.
   - 같은 주제의 결정 기록을 하루에 둘 넘게 쓰게 되면 멈추고 전체를 다시 본다.
   - 화면의 말은 현업에서 쓰는 말을 쓰고 지어내지 않는다. 한 가지 뜻에 한 가지 말을 쓴다.
6. **기술.** TypeScript 하나, pnpm 작업 공간, Biome, Vitest. 코어는 Node를 모른다. 새 의존성은 결정 기록과 구조 계약에 등록해야 들어온다.
7. **합치기.** main에는 풀 리퀘스트로만 들어가고, `gate`가 초록일 때만 합친다. 보호 경로를 바꾸는 변경은 같은 변경에 봉인된 결정 기록이 있어야 한다.

## 이유
- 구조가 같으면 테라리움에서 일하던 사람과 에이전트가 프락시움에서 길을 다시 배우지 않는다.
- 하네스의 검사마다 "정말 위반을 잡는가"를 보는 시험이 있다. 다시 쓰는 것보다 가져오는 것이 안전하다.
- 테라리움이 뒤늦게 고친 것(문서 충돌, 생성물 충돌, 서로 따라가는 문서)을 처음부터 피한다.

## 버린 길
- **하네스를 두 저장소가 함께 쓰는 패키지로 빼기**: 옳은 방향이지만 지금 하면 두 제품의 일이 그 패키지를 기다리게 된다. 복사하고 부채로 적는다(TD-0001).
- **구조만 가져오고 검사는 필요할 때 더하기**: 검사가 없는 동안 쌓인 것은 나중에 검사를 켤 때 한꺼번에 빨갛게 된다.
- **테라리움의 결정 기록을 그대로 옮기기**: 190여 개의 대부분은 테라리움 제품의 결정이다. 여기에는 지금 유효한 규칙만 한 장으로 적는다.

## 결과
구조와 하네스, 바탕 부품(`kernel`), CI를 들였다. 구조 검사와 시험이 통과한다.
