# ADR-0002 구조와 하네스는 테라리움의 것을 가져온다 — 기계가 강제하는 규칙, 짧은 지도, 스스로 오래됐음을 감지하는 문서

## 맥락
제품 책임자는 프락시움의 프로젝트 구조를 테라리움과 같게 잡으라고 했다. 테라리움의 구조는 OpenAI의 하네스 엔지니어링 글(https://openai.com/ko-KR/index/harness-engineering/)에서 왔다: 코드를 작성하는 것은 에이전트이고, 사람이 할 일은 에이전트가 방향을 잃지 않는 환경을 만드는 것이다. 테라리움은 이 구조로 결정 기록 190여 개와 요구사항 120여 개를 쌓는 동안 배운 것이 있다.

## 결정
1. **구조는 테라리움과 같다.**

   | 경로 | 내용 |
   |---|---|
   | `AGENTS.md` | 지도. 120줄 이하. 상세 내용은 링크로 |
   | `ARCHITECTURE.md` | 유닛과 의존 방향 |
   | `docs/product-specs/requirements.md` | 목표와 요구사항(`REQ-NNN`)의 단일 출처 |
   | `docs/design-docs/` | 설계 문서, 제품 설계 한 장, 용어집 |
   | `docs/design-docs/adr/` | 결정 기록. 확정되어 본문을 수정하지 않는다 |
   | `docs/exec-plans/` | 계획과 기술 부채 대장 |
   | `docs/generated/` | 하네스가 생성하는 것(결정 목록, 품질 등급표) |
   | `docs/verified/` | 문서 확인 기록. (문서, 대상)마다 파일 하나 |
   | `docs/archive/` | 더 이상 수정하지 않는 문서. 검사하지 않는다 |
   | `harness/` | 구조 검사와 그 설정. 보호 경로 |
   | `packages/core/` | 플랫폼에 의존하지 않는 코어. 유닛은 폴더 |
   | `.github/` | CI. 필수 검사는 `gate` 하나 |

2. **하네스는 테라리움의 한 시점(커밋 3a8a83d)을 복사한다.** 검사는 10종이다: 구조(의존 방향, 공개 경계, 허용한 패키지, 시계와 난수), 문서, 부채, 검사 무시, 테스트 잠금, 요구사항 추적, 화면 용어, 품질 등급표, 보호 경로, 커버리지. 제3자 라이선스 검사는 구조 검사에 포함되어 실행된다.
3. **가져오지 않은 것.** 테라리움 제품에 종속된 것은 제외했다: 화면 헬퍼 검사, UX 측정과 그 CI 구성, 테스트 분할 합계 검사. UX 측정은 첫 화면이 생길 때 가져온다(TD-0002).
4. **요구사항 번호.** 하네스의 테스트가 가리키는 프로세스 요구사항(REQ-020~025)은 테라리움과 같은 번호와 같은 의미로 둔다. 하네스를 다시 동기화할 때 테스트를 수정하지 않기 위해서다.
5. **테라리움이 겪고 수정한 것은 처음부터 수정한 상태로 시작한다.**
   - 문서의 확인 상태는 문서 앞부분이 아니라 (문서, 대상)마다의 기록 파일에 둔다. 병렬 변경이 충돌하지 않는다.
   - 하네스가 생성하는 파일(결정 목록, 품질 등급표, 색인의 문서 목록)은 변경마다 커밋하지 않는다. 정리 작업이 생성한다.
   - 참조는 한 방향이다: 목표 → 요구사항 → 설계 → 계획. 두 문서가 서로를 따르지 않는다.
   - 테스트와 커버리지는 한 번에 실행한다. 문서만 바뀐 변경은 가벼운 CI 경로를 거친다.
   - 계획은 날짜가 아니라 순서로 관리한다.
   - 같은 주제의 결정 기록을 하루에 둘 넘게 작성하게 되면 멈추고 전체를 다시 본다.
   - 화면의 용어는 현업에서 쓰는 용어를 사용하고 새로 만들지 않는다. 한 가지 의미에 한 가지 용어를 사용한다.
6. **기술.** TypeScript 하나, pnpm 워크스페이스, Biome, Vitest. 코어는 Node에 의존하지 않는다. 새 의존성은 결정 기록과 구조 계약에 등록해야 추가할 수 있다.
7. **병합.** main에는 풀 리퀘스트로만 반영하고, `gate`가 통과할 때만 병합한다. 보호 경로를 바꾸는 변경은 같은 변경에 확정된 결정 기록이 있어야 한다.

## 이유
- 구조가 같으면 테라리움에서 일하던 사람과 에이전트가 프락시움에서 구조를 다시 배우지 않는다.
- 하네스의 검사마다 "정말 위반을 감지하는가"를 검증하는 테스트가 있다. 다시 작성하는 것보다 가져오는 것이 안전하다.
- 테라리움이 뒤늦게 수정한 것(문서 충돌, 생성물 충돌, 서로를 따르는 문서)을 처음부터 피한다.

## 버린 대안
- **하네스를 두 리포지토리가 공유하는 패키지로 분리하기**: 옳은 방향이지만 지금 하면 두 제품의 작업이 그 패키지에 의존하게 된다. 복사하고 부채로 적는다(TD-0001).
- **구조만 가져오고 검사는 필요할 때 추가하기**: 검사가 없는 동안 쌓인 것은 나중에 검사를 활성화할 때 한꺼번에 실패한다.
- **테라리움의 결정 기록을 그대로 옮기기**: 190여 개의 대부분은 테라리움 제품의 결정이다. 여기에는 지금 유효한 규칙만 한 장으로 적는다.

## 결과
구조와 하네스, 공통 기반 코드(`kernel`), CI를 도입했다. 구조 검사와 테스트가 통과한다.
