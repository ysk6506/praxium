# ADR-0050 조직 속성을 오버레이로 모델에 더한다

## 맥락

자산 대장에는 표준에 없는 컬럼("관리 부서", "도입 연도")이 있고, 조직은 그것을 표준 타입의 속성으로 받고 싶어 한다. ADR-0007은 이것을 `org` 층의 오버레이로 하기로 했지만 코드에는 길이 없다. 속성은 타입 정의 안에만 있고, 표준 타입에 속성만 더하는 방법이 없다. 그냥 더하면 세 가지가 깨진다.

- **이름.** 속성 이름은 한 타입의 유효 속성(자기, 조상, 특성) 안에서 겹치면 레지스트리 전체가 실패한다. 표준이 나중에 같은 이름을 더하면 조직의 모델을 가진 배포는 시작하지 못한다.
- **번호.** 속성이 없는 번호는 "지금 쓰는 최댓값 + 1"을 받는다. 조직의 번호가 표준의 다음 버전이 쓸 번호와 겹치면 시작이 실패하거나 행의 값이 다른 속성으로 읽힌다.
- **해시.** 표준만 있을 때의 모델 해시는 지금 KG의 버전 ID에 기록돼 있어서 바뀌면 안 된다.

이 결정은 모델 유닛(`backend/internal/model`)만 다룬다. 정의의 저장, 명령줄, 수집·조회·API·웹은 뒤의 변경이다.

## 결정

1. **오버레이.** 표준 객체 타입이나 표준 특성 하나에 조직의 속성을 더하는 정의 항목(`type_overlay`)이다. 항목 ID는 `ov.`와 대상 ID이고 대상 하나에 항목 하나다. 속성만 더한다. 새 타입, 링크 타입, 열거 값 더하기, 식별 키는 하지 않는다. 특성에도 더할 수 있다(그 특성을 가진 모든 타입이 갖는다). 본문은 `schema_version` 1이고 모르는 필드를 거절한다. 사람이 쓰는 파일은 `praxium-org-model`이고 대상을 이름으로, 값 타입을 짧은 이름으로 쓰며 ID와 번호는 생략할 수 있다. 파일은 완전한 상태를 말하므로 저장된 속성이 파일에 없으면 호환성을 깨는 변경이다.
2. **이름 공간.** `Property.Namespace`(비어 있으면 소유자의 이름 공간)를 더한다. 조직 속성의 이름은 `org.snake_case`(64자 이하), ID는 `pr.org.`로 시작한다. 표준 속성의 이름은 점을 가질 수 없으므로 표준이 어떤 이름을 더해도 겹치지 않는다. 같은 타입 계통 안에서 조직 이름끼리 겹치는 것은 지금의 `checkPropertyNames` 규칙이 막는다.
3. **번호 공간.** 표준과 `sys`의 속성 번호는 99999 이하, 조직(`org`, `ext`)은 100000 이상이다. 번호가 없는 속성은 자기 범위의 다음 번호를 받는다. 오버레이는 번호가 채워진 것만 받고, 번호는 저장소가 처음 저장할 때 발급한다(번호가 없는 파일을 발급 함수로 채우는 순수 함수까지가 이 변경이다). 형식과 범위 검사만 모델이 하고 원장은 저장소의 일이다. 표준 데이터 테스트가 "표준 속성 이름에 점이 없다"와 "표준 번호는 100000 미만"을 잠근다. 타입과 링크 타입의 번호는 이번에 건드리지 않는다.
4. **속성이 받는 것.** `id`, `attr_no`, `name`, `aliases`, `value_type`, `unit`, `enum_values`, `change_class`(`static`, `slow`), `sensitivity`, `status`, `display_names`, `description`. 값 종류는 평평한 파일 칸으로 받을 수 있는 것(문자열, 정수, 수, 불리언, 시간, 열거, 수량과 그 위의 이름 붙은 값 타입)이다. `required`, `scope_key`, `history_kind`, `dynamic`, 후속(`superseded_by`)은 이유를 알리고 거절한다. 한도는 본문 256KiB, 파일 1MiB, 대상 하나에 속성 100개, 전체 1000개, 열거 값 100개(각 64자), 표시 이름 100자, 설명 1000자다.
5. **합치기.** `ComposeOverlays`는 표준 정의에 오버레이를 합친 새 정의를 만들고(입력을 바꾸지 않는다) 보통의 `NewRegistry`가 검사한다(`ComposeRegistry`가 둘을 잇는다). 대상이 없거나 `sys`이거나 표준이 아니면 거절한다. 대상이 `deprecated`이거나 짧은 이름이 같은 타입의 표준 속성과 같거나 비슷한 것은 경고만 한다(`OverlayWarnings`).
6. **삭제하지 않는다.** 조직 속성은 `deprecated`로 숨기고, 조직 속성은 후속 없이 `deprecated`일 수 있다(표준 속성은 지금처럼 후속이 필요하다). 번호와 이름은 계속 예약된다. 행이 번호로 속성을 가리키고 과거 버전을 읽는 방법이 지금의 정의 하나뿐이라서, 지우면 과거 버전의 속성이 이름 없이 나온다. 이것이 ADR-0007 17번의 "삭제는 어디서도 사용되지 않을 때만"을 조직 속성에는 "삭제하지 않는다"로 좁힌다(`kg-model.md` 13.4). 정의 세트마다 지난 버전을 읽을 수 있게 되면 삭제를 다시 정한다.
7. **변경 분류.** `ClassifyOverlay`가 이전과 다음을 속성의 ID로 맞춰 추가, 호환되는 변경, 호환성을 깨는 변경으로 나눈다. 호환되는 변경은 표시 이름, 설명, 별칭, 열거 값 더하기, 민감 등급 올리기, 상태 변경, 옛 이름을 별칭으로 남기는 이름 바꾸기다. 호환성을 깨는 변경은 속성 빠짐, 값 종류·단위·변경 속도·번호 변경, 열거 값 빼기, 민감 등급 낮추기, 옛 이름을 남기지 않는 이름 바꾸기, 대상 변경이고 "새 속성을 더하고, 채우고, 옛것을 물러나게 한다"는 안내를 붙인다.
8. **해시.** 속성의 이름 공간은 값이 있을 때만 모델 해시에 넣어서 조직 속성이 없는 표준 모델의 해시는 그대로다. 표시 이름은 이름과 같은 라벨이라 해시에서 뺀다. 그래서 이름을 바꿔도 모델 해시와 행의 해시가 그대로다. 항목의 내용 해시와 정의 세트의 해시는 모델이 계산하지 않고 정의 저장소(`core.definitions`)의 `RevisionHash`와 `SetHash`가 계산한다. 모델이 보장하는 것은 같은 오버레이는 언제나 같은 본문 바이트가 된다는 것이다. `Overlay.Body`가 저장소의 정규화 형식(키를 바이트 순서로, 공백 없이)으로 쓰고, 속성은 ID 순서로, 별칭과 열거 값은 글자 순서로 놓는다. 라벨(이름, 표시 이름, 설명)도 본문에 있으므로 이름을 바꾸면 새 리비전이 된다. 항목이 없는 세트의 해시를 표준 레지스트리의 해시로 두는 일은 `SetHash`의 기준 해시로 `Registry.Hash`를 넘겨 부르는 쪽(조립하는 쪽)이 한다. `core.model`과 `core.definitions`는 서로 import하지 않는다.

## 이유

- 이름 공간을 이름에 점으로 넣으면 충돌 방지가 규칙이 아니라 형식이 된다. 표준이 쓰지 않을 접두사를 영원히 지키는 규칙이 필요 없다(`org_`는 이미 표준 속성이 쓴다).
- 번호 공간을 나누면 행 형식이 바뀌지 않고, 표준이 올라가도 조직의 번호는 그대로다. 정수 열에 충분히 들어가고, 표준이 10만 번을 넘을 일은 설계상 없어서 테스트가 막는다.
- 속성만 하면 첫 사용자가 필요한 "내 컬럼을 받을 자리"가 되고, 새 타입의 비용(식별 키, 층 상속, 바인딩, 유사 타입 방지)을 미룬다. 형식은 `kind`와 대상의 `kind`를 열어 두어 타입 항목이 같은 저장소에 들어올 수 있다.
- 분류 함수가 있으면 첫 쓰기 경로(명령줄)도 나중의 제안도 같은 규칙으로 호환성을 깨는 변경을 막는다.

## 대안과 기각 사유

- **접두사(`x_`, `u_`).** 점이 없어 이름 자르기가 쉽지만 접두사를 표준이 쓰지 않는다는 규칙을 영원히 지켜야 한다.
- **접두사 없음.** 표준이 같은 이름을 더하면 조직의 모델을 가진 배포가 시작하지 못한다.
- **"최댓값 + 1" 번호.** 표준이 올라가면 겹친다. 음수 번호나 별도 열은 행 형식을 바꾼다.
- **쓰이지 않으면 삭제.** 이력 행과 지난 KG 버전이 번호를 가질 수 있는데 과거 버전을 읽는 방법이 지금의 정의 하나뿐이다.
- **새 타입과 열거 값 더하기를 함께.** 속성의 몇 배의 비용이고 열거 값은 영향 계산과 매핑 검사를 얽는다.

## 결과

- 저장, 명령줄, 수집·조회·API·웹은 이 모델을 쓰도록 뒤의 변경에서 연결한다. 이 변경은 어느 쪽에도 닿지 않아서 동작이 바뀌지 않는다.
- 조직 속성을 더하면 모델 해시와 정의 세트 해시가 바뀌고 `graph_hash`는 바뀌지 않는다. 표준 모델만 있는 저장소는 지금의 해시를 그대로 쓴다.
- 조직 속성이 쌓이면 번호 범위(100000 이상)가 타입과 링크 타입에도 필요하다. 지금은 속성만 나눴다.
