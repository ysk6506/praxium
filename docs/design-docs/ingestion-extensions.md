# 수집 확장

[현실 데이터 수집](ingestion.md)과 [파이프라인](pipeline.md)에 이어지는 보충 문서예요(ADR-0008, ADR-0010). 여기서 추가한 기능은 모두 `/v1`의 자원으로 제공해요([자원 (3)](rest-api-resources-additions.md)).

## 1. 푸시 수집
- **풀(pull) 방식이 기본이고 푸시 수집은 수집 방식 `stream`의 한 형태예요**(이미 있어요).
- 푸시 경로는 소스마다 정의로 열어요(기본은 닫힘). 서비스 계정으로 인증하고 그 계정의 역할은 `ingester`예요. `ingester`는 범위에 속한 소스에 푸시 수집만 해요(수집 엔벨로프 전송). 읽기를 포함해 그 밖의 것은 아무것도 할 수 없어요(ADR-0012).
- 같은 것을 여러 번 보내도 한 번만 반영돼요(보낸 쪽의 이벤트 ID). 이 약속은 **중복 제거 기간 안에서** 성립해요. 기간은 소스마다 설정하고 기본은 7일이에요(`dedupe_window`, 계약에 적어요). 기간이 지난 재전송은 키와 내용 해시가 차단해요.
- 순서는 `source_time`으로 판단해요. 이것은 수집 순서(`ingest_seq`)를 소스의 시각으로 정한다는 의미가 아니라, 같은 속성에 이미 반영된 값보다 이른 값이 덮어쓰지 못하게 하는 지연 도착 값 처리 규칙이에요([파이프라인](pipeline.md) 2.4).
- 푸시한 것도 같은 실행기와 안전장치와 행 집계를 거쳐요. 보류된 스트림에서는 쌓여 있다가 해제될 때 `ingest_seq`를 부여받아요.
- 푸시 수집만 하는 소스는 누락된 것을 알 수 없어요. 스냅샷과의 정합성 대조를 함께 두기를 권하고, 없으면 완전함을 선언하지 못해요.
- 단계: 수집 확장 단계, 알파 안.

## 2. 지정 재수집(targeted refresh)
객체 하나나 몇 개를 지정하면 그 객체의 속성을 전달하는 피드들의 소스에서 **그 객체의 데이터만** 지금 다시 읽어 같은 경로로 적용해요. 비동기 작업(operation)으로 실행되고, 응답에 무엇이 바뀌었는지와 속성마다의 `source_time`과 적용된 변경 번호가 실려요.
- 프리셋이 "키 기반 단건 읽기"를 할 수 있는지 선언해요(`keyed_read`). 못 하는 소스는 가장 좁은 범위의 읽기로 대신하거나 "이 소스는 지원하지 않는다"고 응답해요. 속성마다 어느 소스가 다시 읽혔고 어느 것이 읽히지 않았는지 적혀요.
- 소스 보호의 한도 안에서 실행돼요. 주체마다 한도가 있고 스케줄 실행보다 우선순위가 높아요. **스케줄을 기아 상태로 만들지 않아요.** 소스의 속도 상한 중 일부를 스케줄 몫으로 남기고, 주체별 한도와 몫의 값은 기본값 표에 가정으로 둬요.
- MCP의 읽기 인터페이스에도 제공해요. 작업을 만들지만 소스에서 읽기만 하고 현실에는 쓰지 않아서 "KG의 MCP는 읽기만 한다"와 맞아요(작업은 프락시움 안의 일이에요). 누가 호출할 수 있는지는 권한 설계의 역할과 범위를 따라요.
- 소스 안에서 시크릿을 복호화하는 일은 트라이얼 수집과 같은 규칙이에요([수집 설계](ingestion.md) 3.2).
- **삭제를 만들지 않아요.** 그 객체가 소스에 없다는 응답은 "없음을 관측함"으로 기록하고, 폐기는 일반 규칙이 처리해요.
- 스트림 소스의 속성은 다시 읽을 것이 없어서 "이 시각 뒤의 값이 올 때까지 대기"로 응답해요.
- **키 기반 단건 읽기는 가능한 한 자동으로 얻어요**(사용자가 소스마다 따로 등록하지 않아요). 프리셋에 들어 있고, SQL 어댑터는 데이터셋의 키 컬럼(식별에 이미 선언돼 있어요)에 조건을 붙여 자동으로 만들어요. 파일 소스는 그 파일을 다시 읽어 그 행만 사용해요. HTTP JSON 어댑터는 목록 요청에 필터 인자가 선언돼 있으면 그것을 쓰고, 단건 조회 경로가 따로 있으면 사용자가 경로 템플릿 한 줄을 추가할 수 있어요(없어도 돼요). 어느 것도 없으면 가장 좁은 범위의 읽기로 대신하고 그 비용을 소스의 화면과 응답에 보여 줘요. 소스를 만들 때 "단건 재수집이 되나"를 임의로 만든 키가 아닌 실제 한 건으로 테스트해 볼 수 있는 경로가 있어요.
- 단계: 알파(HTTP JSON과 SQL 어댑터의 키 기반 읽기부터). MCP의 읽기 인터페이스에도 제공해요.

## 3. 기대와 대조
질의하는 측이 "이 객체의 이 속성이 이 값이어야 한다"와 기준 시각(액션을 실행한 시각)을 주면, 응답은 속성마다 이 4가지 중 하나예요(ADR-0010, `kg-queries.md`).

| 값 | 의미 |
|---|---|
| `confirmed` | 기준 시각 뒤에 소스에서 관측한 값이 기대와 같아요 |
| `not_yet` | 기준 시각 뒤에 관측한 값이 아직 없어요 |
| `contradicted` | 뒤에 관측한 값이 기대와 달라요 |
| `unverifiable` | 다시 읽을 수 없는 소스예요 |

대기 한도를 줄 수 있어요. 영향 범위처럼 이웃으로 전파되는 것의 확인은 같은 변경 번호를 `min_seq`로 주고 질의하면 돼요.

**확인의 근거는 소스에서 관측한 것이어야 해요.** 액션을 실행한 쪽이 "내가 이렇게 바꿨다"고 푸시한 값은 근거 종류가 `declared`이고 `observed`가 아니에요. 대조는 `observed`만으로 `confirmed`를 반환해요. 액션을 실행한 쪽의 주장만으로 스스로를 확인하지 못해요.

프락시움은 실제 시스템에 쓰지 않아요(ADR-0001). 재수집은 읽기예요. 액션의 실행은 프락시움 밖의 일이고, 이 결정은 그 뒤의 확인에 필요한 KG 측 기반만 정해요(엔드투엔드(E2E) 프로세스는 구체화하지 않아요).

## 4. 매핑을 만드는 사람을 돕는 API
화면의 형태는 클로즈드 베타의 일이고 여기서는 화면이 의존할 API만 정해요. 이 API는 원본을 보여 주므로 읽기 권한을 따져요: 샘플과 통계와 미리 보기는 그 데이터셋이 값을 전달하는 타입의 읽기 권한을 함께 요구하고 감사에 남겨요. `open`이 아닌 컬럼의 빈출 값은 제공하지 않아요. 브랜치에만 있는 새 소스에는 `branch_id`를 줘서 호출해요.
1. **스키마만 보고 매핑하지 않아요.** 데이터셋을 볼 때 컬럼의 이름과 값 타입과 함께 샘플 행, 컬럼별 통계(빈 값 비율, 고유 값 수, 빈출 값, 값의 형태)를 줘요. 샘플과 통계는 민감 등급과 읽기 권한을 따라요. 파일의 프로파일은 명령 `praxium ingest inspect`로 먼저 구현했어요(CSV, JSON Lines, 엑셀. 필드 이름은 위 이름 그대로 `empty_ratio`, `distinct_count`, `top_values`, `shape`, `sample_rows`예요. [ADR-0040](adr/0040-excel-workbook-source-read-with-the-standard-library.md)).
2. **매핑 제안(`suggest`).** 데이터셋과 객체 타입을 주면 컬럼과 속성의 조합을 이유와 함께 제안해요: 이름의 유사도, 값 타입 일치 여부, 값의 형태(식별자 패턴, 단위), 같은 프리셋이나 같은 타입의 다른 피드가 쓴 조합. 식별에 쓸 컬럼의 후보도 제안해요(값이 고유하고 비어 있지 않은 것, 기존 식별자와 일치하는 비율). 제안은 고정된 규칙으로만 만들고(같은 입력이면 같은 응답) 자동으로 적용하지 않아요. 사람이 수락한 것만 브랜치에 기록돼요. 이름의 유사도를 계산하는 규칙은 `suggest`를 구현하는 변경이 확정해요(착수를 막지 않아요). 단계는 알파 2예요.
3. **타입 기준으로 보기.** 객체 타입 하나에서 속성마다 "어느 피드가 값을 전달하나, 비어 있나, 얼마나 채워졌나, 배치인가 스트림인가"를 봐요(타입의 피드 목록, 이미 있어요). 비어 있는 속성에서 시작해 값을 전달할 수 있는 데이터셋의 후보를 찾는 경로를 추가해요.
4. **미리 보기.** 저장하기 전에 샘플 행 몇 개가 어떤 객체와 링크가 되는지(식별 결과가 기존 객체에 연결되는지 새로 생성되는지, 타입이 맞지 않아 탈락하는 값)를 보여 줘요. 전체에 실행한 결과의 차이는 브랜치의 드라이 런이 보여 줘요.
5. 프리셋이 있는 소스는 기본 피드가 들어 있어 매핑 없이 시작해요.

## 5. 테이블로 바로 변환되지 않는 소스 데이터: 문서, 트리, 행
1. 원본 데이터셋에 **파싱** 단계를 둬요. 어댑터가 수집한 것은 행의 집합이 아닐 수 있어요(문서 하나, 텍스트 덩어리). (가) **파서**가 문서를 **트리**(이름이 있는 노드와 값, 순서가 있는 목록)로 만들고, (나) **행 선택**이 트리에서 "무엇이 한 행인가"와 "그 행의 컬럼은 어느 노드인가"를 경로로 지정해 데이터셋(테이블)을 만들어요. 위쪽 노드의 값을 아래 행에 내려 붙일 수 있어요(장비의 이름을 그 아래 인터페이스 행마다). 그 뒤는 일반 데이터셋과 같아요.
2. **파서는 제품에 포함된 고정 목록이에요**(사용자 코드는 없어요): JSON과 JSON Lines, XML, CSV와 구분자 텍스트, 고정 너비 텍스트, 키=값과 섹션이 있는 설정 텍스트, YAML, **들여쓰기로 계층을 이루는 설정 텍스트**(네트워크 장비의 설정처럼 행과 들여쓰기로 된 것을 계층 그대로 트리로 만들어요), **라인 템플릿으로 읽기**(정렬된 텍스트 테이블이나 명령의 출력처럼 형식이 정해진 텍스트를 이름 붙은 캡처 그룹과 상태 전이로 된 템플릿으로 읽어요). 새 파서는 결정 기록으로 추가해요.
3. **라인 템플릿은 데이터예요.** 프리셋처럼 버전이 있고 합성 샘플로 실행하는 테스트가 있어야 제품에 포함돼요. 조직이 자기 템플릿을 `org` 네임스페이스에 만들 수 있고 브랜치와 제안을 거쳐요. 템플릿의 문법은 고정돼 있어요(정규식 캡처, 상태, 행을 출력하는 시점, 위 값 채워 넣기). 무한 반복이 생기지 않게 행마다 한 번만 읽고 정규식은 백트래킹이 폭발하지 않는 것만 써요.
4. **맞지 않는 것을 숨기지 않아요.** 파서가 읽지 못한 행과 템플릿에 맞지 않는 행은 버리지 않고 세요(행 집계의 "읽지 못함" 항목. [파이프라인](pipeline.md) 7절). 그 비율에 기대 조건을 적용할 수 있고 샘플을 볼 수 있어요(샘플은 읽기 권한을 따라요). 트리의 구조가 바뀌면(없던 노드, 사라진 노드) 수신한 스키마가 바뀐 것으로 다뤄요.
5. **만드는 사람을 돕는 API.** 샘플 문서를 올리면 파서 후보와 트리를 보여 주고, 트리에서 노드를 선택하면 경로가 만들어져요. 라인 템플릿은 샘플 행에서 캡처할 곳을 선택하면 초안이 나와요. 결과 테이블을 그 자리에서 미리 봐요(4절과 같은 방식).
6. **범위 밖**: 사람이 쓴 자유 서식의 텍스트, 그림, 스캔 문서에서 의미를 추출하는 일은 제품이 하지 않아요. 외부 에이전트가 추출해 푸시할 수 있고 그 값의 근거는 `declared`예요.
7. **의존성**: 파서는 표준 라이브러리로 구현해요. YAML만 표준 라이브러리에 없으므로 사용하는 부분 집합을 직접 파싱하거나 허용 라이선스의 라이브러리 하나를 이유와 함께 도입해요(구현하는 변경이 정하고 결정 기록에 남겨요).
8. 단계: JSON, XML, CSV, 키=값, 들여쓰기 설정 텍스트는 알파의 수직 슬라이스 하나 다음(수집 확장 단계). 라인 템플릿과 YAML도 알파 2예요(용도가 정해진 것).
9. **정제한 데이터셋을 타입에 매핑하는 것은 이미 돼요.** 정제 데이터셋은 여러 원본이나 다른 정제 데이터셋을 입력으로 받아(소스가 달라도 돼요) 조인, 유니언, 선택, 집계, 중복 제거를 한 결과이고, 피드는 원본이든 정제든 데이터셋에 붙어요. 정제를 여러 단계로 연결할 수 있고 순환은 차단해요. 계보는 속성, 피드, 정제의 연산, 원본 컬럼, 소스까지 이어져요.

## 6. 미결 사항
- 푸시 수집의 한 번에 보내는 양. 이벤트 ID를 기억하는 기간은 정해졌어요(7일).
- 지정 재수집의 주체별 한도 값과 스케줄에 남기는 몫(기본값 표에 가정으로 두고 측정해서 수정해요).
- 이름의 유사도 규칙(`suggest`를 구현하는 변경이 확정해요).

## 7. 관련
ADR-0008, ADR-0010. 요구사항: REQ-224(푸시 수집), REQ-225(지정 재수집), REQ-226(기대와 대조), REQ-227(매핑을 돕는 API), REQ-228(문서, 트리, 행).
