# 끊긴 프로세스를 이어 가기

하네스 세션이 중간에 끊긴 에이전트를 다시 불렀을 때, 프락시움이 이어 갈 맥락을 어떻게 주는지를 정한 설계예요. 결정은 ADR-0074의 첫 항에 있어요. **이 문서는 아직 구현하지 않은 설계(예정)예요.** 게이트웨이는 코드가 없어요. 예시의 이름과 숫자는 지어낸 것이에요. 큰 그림(이벤트, 승인 대기, 참조, 자격 증명)은 [상시 가동 에이전트와 프락시움](agent-integration.md)에 있어요. 이 문서에서 "실행"은 게이트웨이의 실행([게이트웨이 설계](gateway.md) 5절)이고, 에이전트가 한 번 깨어 일하는 구간은 "하네스 세션"이에요.

## 1. 프락시움이 맡는 것과 맡지 않는 것

게이트웨이를 지난 호출의 상태는 대장이 진실이라 에이전트가 베껴 둘 필요가 없어요. 계획, 판단의 이유, 사용자와의 약속은 에이전트의 작업 노트에 둬요. 프락시움은 그것을 맡지 않아요.

위 문장은 한계가 둘 있어요. 첫째, 죽은 게이트웨이의 일지에만 있는 결과는 "모름"이에요(REQ-463). 둘째, 대장을 시점 복구로 되돌리면 대장의 기록도 되돌아가요. 시점 복구는 미결이에요([게이트웨이의 안전](gateway-safety.md) 9절). 그래서 "에이전트가 무엇을 잊어도 현실에 한 일을 모두 안다"고는 약속하지 않아요.

## 2. 차례

1. 끊김. 하네스 세션이 중간에 끊겨요. 대장에는 의도와 실행의 상태가 남아 있어요.
2. 다시 호출. 이벤트로 깬 새 하네스 세션이나 사람이 다시 부른 세션이 시작해요. 세션을 재개했든 새로 열었든 같아요.
3. 열린 실행 찾기. 실행 ID가 있으면 그대로 쓰고, 잃었으면 서비스 계정 기준으로 열린 실행과 의도를 목록으로 읽어요(REQ-539).
4. 맥락 읽기. 맥락 읽기 툴을 **한 번** 불러요(REQ-455, REQ-550). 이어 가려면 그 호출에 "이어받겠다"를 표시해요. 표시하면 이어가기 번호가 새로 올라요. 표시가 없으면 읽기만 하고 번호는 그대로예요.
5. 이어서 호출. 맥락의 "다음에 할 수 있는 것"에 따라 준비나 실행을 이어가기 번호와 함께 불러요. 낡은 번호의 호출은 거절돼요.

이미 있는 것은 읽기 툴 하나가 돌려주는 넷(이 실행이 무엇인지, 끝난 것, 진행 중이거나 모르는 것, 남은 것)과 "이어받겠다"고 표시할 때만 오르는 이어가기 번호예요(REQ-455, 게이트웨이 설계 7절). 이 설계가 더하는 것은 목록으로 다시 찾는 읽기(REQ-539)와 아래 성질이에요(REQ-550).

## 3. 맥락이 갖출 성질

| 성질 | 뜻 |
|---|---|
| 한 번의 읽기 | 멈춘 이유(3.1절)와 다음에 할 수 있는 것까지 한 번의 호출로 읽혀요 |
| 대장의 사실만 | 에이전트가 한 말이나 추론은 싣지 않아요. 소스의 값은 구조에서 갈라 싣거나 참조로 가리켜요. 모델의 요약도 싣지 않아요 |
| 요약이 먼저 | 요약이 앞에 오고 크기에 상한이 있어요. 상한을 넘을 때의 규칙은 4절이에요. 상한의 값은 게이트웨이의 구현이 정해요 |
| 결정적 | 3.2절 |
| 누가 읽어도 같음 | 같은 서비스 계정이면 세션이 달라도 같은 맥락이에요(이어받음 표시와 번호는 게이트웨이 설계 7절대로) |

### 3.1 멈춘 이유

멈춘 이유는 미리 정해 둔 몇 가지가 아니라 **대장의 상태에서 나오는 이유**예요. 적어도 다음을 구분해요.

| 이유 | 뜻 |
|---|---|
| 승인 대기 | 사람의 승인을 기다려요 |
| 승인 거절, 승인 만료 | 의도가 닫혔어요. 다시 하려면 새로 준비해요 |
| 조건 불충족("아직") | 승인과 무관하게 조건이 아직 안 맞아요 |
| 한도 | 호출 수, 거절 수(REQ-546), 시간의 한도를 넘었어요 |
| 결과를 모름 | 호출의 결과를 몰라 사람에게 넘겼어요 |
| 정지 스위치 | 정지 스위치가 걸렸어요 |
| 낡은 이어가기 번호 | 다른 세션이 이어받았어요(5절) |
| 오류 | 호출이 처리되지 못했어요 |
| 실행이 닫힘 | 실행이 끝남, 돌려줌, 중단으로 닫혔어요(5절) |

값의 이름은 게이트웨이의 구현이 정해요.

### 3.2 결정적이라는 뜻

맥락 읽기는 조건을 **다시 평가하지 않아요**. 다시 평가하는 것은 조회예요(게이트웨이 설계 6절). 맥락은 대장에 기록된 마지막 평가와 그 시각을 실어요. 시각은 절대 시각만 싣고 "남은 시간" 같은 상대 값은 싣지 않아요. 그래서 대장의 상태가 같으면 응답이 바이트까지 같아요.

## 4. 상한을 넘을 때

- 열린 것(승인 대기, 진행 중, 모름)은 자르지 않아요.
- 끝난 것을 오래된 것부터 줄이고, 줄인 수와 잘렸다는 표시를 실어요.
- 줄인 것의 자세한 내용은 의도 ID로 조회(게이트웨이 설계 6절의 조회)해서 읽어요.
- 열린 것만으로 상한을 넘는 경우는 정하지 않았어요(6절).

## 5. 실패 경우

| 경우 | 프락시움의 응답 | 에이전트가 할 일 |
|---|---|---|
| 실행이 그 사이 닫힘 | 닫힌 실행의 맥락 읽기는 정상으로 답해요. 상태는 닫힘이고 닫힌 이유가 있고 "다음에 할 수 있는 것"은 비어 있어요. 닫힌 실행에 "이어받겠다"를 표시하면 거절해요. 목록으로 다시 찾는 읽기(REQ-539)는 열린 것에 더해 최근에 닫힌 실행(기간은 가정)을 닫힌 이유와 함께 내요 | 이어 가지 않고 끝내요 |
| 다른 세션이 이미 이어받음 | 낡은 번호의 호출은 "다른 세션이 이어받았다"를 뜻하는 코드로 거절해요. 이 거절도 거절 수의 한도(REQ-546)에 세요 | 그 거절을 받은 세션은 다시 이어받지 말고 끝내요. 번호를 번갈아 빼앗는 일은 한도에서 멈춰요 |
| 승인이 만료되거나 거절됨 | 맥락의 멈춘 이유에 나와요. 그 의도는 닫혔어요 | 다시 하려면 새로 준비해요 |
| 맥락이 상한을 넘음 | 4절의 규칙대로 줄이고 잘렸다고 표시해요 | 줄인 것은 의도 ID로 조회해요 |
| 실행 ID를 잃음 | 서비스 계정 기준의 목록(REQ-539)이 열린 실행과 의도를 내요 | 목록에서 찾아 맥락을 읽어요 |

## 6. 미결

| 미결 | 정하는 때 |
|---|---|
| 열린 것만으로 상한을 넘을 때의 응답(실행마다 열린 의도 수의 한도와 함께 정해요) | 게이트웨이의 구현 |
| 멈춘 이유의 값의 이름, 낡은 번호의 거절 코드의 이름 | 게이트웨이의 구현 |
| 맥락 크기의 상한, 최근에 닫힌 실행을 목록에 남기는 기간의 값 | 클로즈드 베타에서 측정해서 |
| 시작된 실행을 에이전트가 처음 아는 방법 | 프로세스 정의의 설계([게이트웨이의 안전](gateway-safety.md) 9절) |

## 7. 검증

| 무엇 | 확인하는 방법 | 요구사항 |
|---|---|---|
| 같은 상태에서 같은 응답 | 같은 대장의 상태에서 두 번 읽으면 바이트까지 같고, 읽는 시각이 달라도 같다 | REQ-550 |
| 대장의 사실만 | 에이전트의 말이 없고, 소스의 값은 구조에서 갈라 있다 | REQ-550 |
| 상한 | 상한을 넘으면 열린 것은 남고 끝난 것이 오래된 것부터 줄며 잘림이 표시된다 | REQ-550 |
| 이어받음 표시 | 표시한 호출만 번호가 오르고, 낡은 번호는 거절되며 거절 수에 센다 | REQ-455, REQ-545, REQ-546 |
| 닫힌 실행 | 맥락 읽기는 정상이고 "이어받겠다"는 거절된다. 목록에 닫힌 이유와 함께 나온다 | REQ-539, REQ-550 |

## 8. 관련 결정과 요구사항

[ADR-0074](adr/0074-where-always-on-agents-attach.md), [ADR-0061](adr/0061-gateway-as-a-praxium-component-approval-first.md). 요구사항은 REQ-455, REQ-463, REQ-539, REQ-545, REQ-546, REQ-550이에요(모두 예정).
