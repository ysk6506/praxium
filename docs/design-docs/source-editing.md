# 정의의 쓰기, 시크릿, 경로, 화면

[ADR-0058](adr/0058-sources-from-db-and-api-worker-ingestion-and-editing-screens.md)의 자세한 내용 가운데 소스와 매핑을 편집하는 길이에요. **이 문서는 아직 구현하지 않은 설계(예정)예요.** 소스 정의의 모양은 [소스와 어댑터](sources-and-adapters.md)에, 수집을 돌리는 쪽은 [수집 서비스와 실행](ingestion-service.md)에 있어요. 정의 오류의 구조화, 시크릿 저장소, 화면의 쓰기 기반, 쓰지 않고 차이를 내는 길은 별도의 변경이 이미 구현하고 있어요. 화면을 이 저장소에서 만든다는 것은 [ADR-0069](adr/0069-screens-live-in-this-repo-and-stay-replaceable.md)가 정했어요. 예시의 이름과 주소는 지어낸 것이에요.

## 1. 정의 저장소의 종류 둘과 직접 적용

### 1.1 항목의 종류
정의 저장소([정의 설계](definitions.md) 3-1)에 항목의 종류 둘을 더해요.

| 종류 | 문서 | 이름 |
|---|---|---|
| `source` | 소스 정의 문서 하나 | 소스 id |
| `mapping` | 매핑 문서 하나(정제, 피드, 링크 정의) | 매핑 id. 소스 id와 무관해요 |

[정의 설계](definitions.md)는 피드와 링크 정의를 종류별 항목으로 두는 모양이에요. 이 설계는 **문서 하나가 항목 하나**로 시작해요. 문서 안의 모든 것에 겹치지 않는 id가 있어서 나중에 기계적으로 쪼갤 수 있어요. 쪼개도 읽기 계약은 그대로예요(2절).

### 1.2 직접 적용
쓰기는 소스 전용 경로가 아니라 **정의 항목의 일반 경로**(`POST /v1/definition-items:apply`) 하나예요. 브랜치가 생기면 같은 본문이 브랜치의 항목 쓰기가 되고, `:apply`는 직접 적용이 허용된 배포에서 "브랜치를 열고 셀프 승인하고 병합"을 한 번에 하는 지름길로 남아요. [ADR-0014](adr/0014-definitions-branches-revert.md)의 브랜치, 제안, 병합을 거치지 않으므로 직접 적용은 `local`과 개발 모드, 그리고 문을 연 운영 모드의 서버에서만 돼요(5절).

**본문**은 계획된 일괄 쓰기(브랜치의 `items:batch`)의 낱말로 정해요. 같은 이름의 스키마를 브랜치의 일괄 쓰기가 쓰게 해요. 필드의 이름은 구현할 때 계약에서 확정해요.

| 내용 | 뜻 |
|---|---|
| 항목의 목록 | 한 요청에 여러 항목이에요 |
| 항목마다 하는 일 | 이번에는 쓰기뿐이에요 |
| 있던 항목 / 새 항목 | 있던 항목은 `item_id`, 새 항목은 `kind`(`source`, `mapping`)와 이름이에요 |
| `body` | 문서 전체예요. 부분 쓰기는 받지 않아요 |
| 항목마다의 기대값 | 읽기 응답이 준 `ETag`(`If-Match`와 같은 뜻)이고 새 항목은 없음이에요 |
| `message` | 전체의 메시지예요 |

- 서버는 저장하기 전에 **합친 결과**(KG의 모든 소스와 매핑)를 컴파일하고 깨지면 거절해요. 컬럼을 지운 소스와 그것을 읽던 매핑을 한 번에 고칠 수 있고, 머리 정의 세트는 언제나 컴파일돼요.
- 다른 항목만 바뀌어 머리 세트가 달라진 경우 서버가 머리를 다시 읽고 한 번 더 해요. 항목의 기대값이 어긋나면 412예요.
- `:validate`는 저장하지 않고 합친 결과를 검사해 오류의 목록을 줘요. 아무것도 바꾸지 않고 바깥에 닿지 않으므로 **읽는 권한**으로 돼요.
- 소스에 `"disabled": true`를 둬서 실행을 막아요. 삭제는 이번에 없어요.
- 서버는 실행을 시작할 때의 정의 세트로 끝까지 돌고 실행 기록에 세트 번호를 남겨요([수집 서비스와 실행](ingestion-service.md) 4.1).

### 1.3 내용에 따른 능력
저장하는 사람이 가져야 할 능력이 **항목의 내용**에 따라 달라요.

| 저장의 내용 | 필요한 능력 |
|---|---|
| 소스를 새로 만든다, 또는 `connection`의 주소, 스킴, 포트, 시크릿 참조, TLS 설정을 바꾼다 | `edit_definitions`에 더해 `run_sources` |
| 그 밖(데이터셋, 컬럼, 매핑) | `edit_definitions`만 |

`edit_definitions`만으로 접속 주소를 바꿀 수 있으면, 편집자가 인증 없는 소스를 아무 내부 주소로 저장하고 저장된 소스의 소스 탐색으로 응답의 표본을 볼 수 있어요. `local`의 화면용 토큰은 둘 다 가져서 달라지는 것이 없어요.

### 1.4 값처럼 보이는 것의 거절
리비전은 지워지지 않아서 머리글, 질의, SQL에 적은 값이 영원히 남아요. 저장할 때 **확실한 것만** 거절해요.

- 머리글의 거절 목록(`Authorization` 등. [소스와 어댑터](sources-and-adapters.md) 8절)
- `password`, `token`, `api_key`, `secret` 꼴의 `이름=값`
- 주소 속의 계정(`https://user:pass@…`)
- 개인 키의 머리줄

`ca_pem`(인증서)은 통과시켜요. 거절하지 못하는 것(값처럼 안 보이는 값)은 시크릿 참조를 쓰라는 안내와 한계로 적어요.

### 1.5 파일과의 왕복
- 가져오기는 저장 경로 그대로예요(파일의 문서를 항목으로 저장). 내보내기는 읽기 경로예요.
- 명령줄의 `ingest run -source -mapping`은 데이터 폴더가 있으면 그 문서들을 저장소에 직접 적용한 뒤 그 소스를 받아요. 옛 매핑 파일(id 없음)을 적용할 때의 매핑 id는 `-source`의 id에서 정해진 규칙으로 만들어요(다시 실행하면 같은 항목이 바뀌어요). 피드 id가 다른 문서의 것과 겹치면 어느 문서의 무엇과 겹치는지를 말해요.
- 가져온 정의가 없는 시크릿을 가리켜도 저장은 돼요. 실행과 점검이 "이 시크릿을 넣으라"로 답해요(저장을 막으면 가져오기의 순서가 꼬여요).

## 2. 정의의 읽기와 오류

### 2.1 읽기
문서의 읽기는 정의 항목으로 해요: 항목 하나와 그 리비전 이력(`GET /v1/definition-items/{item_id}`, 이미 계획된 경로)과 종류로 거른 목록이에요. 목록의 경로는 구현할 때 정해요(미결). **`/v1/mappings`는 열지 않아요.** 문서에서 뽑아 내는 `/v1/feeds`와 `/v1/refinements`(피드와 정제의 id가 KG 안에서 겹치지 않으므로 가능해요)는 뒤에 열어요. 그러면 나중에 문서를 항목으로 쪼개도 읽기 계약이 그대로예요. 소스의 읽기 `/v1/sources`는 계획된 자원이라 이번에 열어요.

### 2.2 정의의 오류
별도의 변경이 구조화하고 있어요. 소스와 매핑의 검사가 `[{pointer, code, params, message}]`의 목록을 내고 서로 무관한 오류는 한 번에 모두 내요. `params`에는 후보 목록을 실어서 지금 문장이 주는 도움을 화면도 줘요. 코드의 목록은 `GET /v1/catalog/error-codes`로 내고, 화면의 한국어 사전이 그 목록을 다 덮는지를 `data` 계층의 테스트로 봐요. 모르는 코드는 영어 문장을 보여요. 문장이 테스트에 잠겨 있어서(REQ-327, REQ-389) 그 변경이 건별로 승인을 받아요. 문장 자체는 바꾸지 않고, 첫 오류에서 멈추던 것이 모두 모으게 바뀌는 데서 오는 기대의 변화만 받아요.

## 3. 시크릿
시크릿의 저장, 키, 권한의 규칙은 [시크릿과 암호화](secrets-and-encryption.md)가 정해요(이 설계가 그 문서를 고쳤어요). 이 절은 소스와 이어지는 점만 적어요.

- **참조와 자리표시자.** 정의의 참조는 `{"secret_id": "…"}`이에요. 시크릿 id는 사람이 정하고 id의 문법을 따라요. 자리표시자 `{{credential.<필드>}}`는 인증 설정의 값 자리에서만, 글자 치환이 아니라 값 단위로 바뀌어요. 주소(경로, 질의)에는 둘 수 없어요. 키를 질의 인자로 받는 API는 이번에 못 붙여요.
- **종류와 필드.** 시크릿은 종류(지금은 `password`: `username`, `password` / `token`: `token`)와 이름 붙은 필드를 가져요.
- **묶기.** 시크릿은 `scope`(소스 id의 목록, 보통 하나)와 `allowed_hosts`(호스트와 포트의 목록)를 가져요. 복호화할 때 한 곳에서 (1) 참조한 소스가 범위 안인가 (2) 접속하려는 주소가 목록 안인가를 확인해요. 소스 화면에서 그 자리에서 등록하면 둘이 자동으로 채워져요. 범위와 주소 목록을 바꾸는 일은 등록과 교체와 같은 권한이 필요하고 감사에 남아요.
- **포트 셋.** 쓰기, 복호화, 메타예요. REST 어댑터의 조립에는 복호화가 없는 것만 줘요(구조 테스트). 복호화하는 것은 워커의 수집 부분과 그 부분이 부르는 점검과 소스 탐색뿐이에요.
- **마스터 키.** 대칭 키 파일 하나예요. 위치는 5절의 표에 있어요. 키가 없으면(폴더를 다른 기계로 옮긴 경우) "시크릿을 다시 넣으라"고 답해요. KG의 해시 키는 시크릿 저장소에 두지 않으므로 이 경우에도 수집은 돼요([수집 서비스와 실행](ingestion-service.md) 9절).
- 값은 쓰기 전용이에요. 목록은 이름, 종류, 만든 때, 버전, 묶인 소스와 주소만 보여 줘요. 소스가 참조하는 시크릿은 삭제할 수 없고 폐기의 단위는 버전이에요.
- 명령줄은 저장소 없이 한 번 실행할 때 `ingest run -credential <시크릿 이름>.<필드>=<파일>`로 받아요(예정). 값을 인자로 받지 않아요.

## 4. REST 경로
**예정**이에요. 지금 서버에는 이 경로가 없고 `backend/internal/contract/planned/routes.json`에 예정으로 있어요. 자원의 상세는 [자원 (1)](rest-api-resources-data.md) 3절과 4절에 더해요.

| 경로 | 뜻 | 능력 |
|---|---|---|
| `GET /v1/adapters` | 어댑터와 설정의 필드, 인증과 쪽 나누기의 종류, 낼 수 있는 능력 | 인증된 누구나 |
| `GET /v1/sources`, `GET /v1/sources/{source_id}` | 정의, 리비전, 데이터셋별 `capabilities`, `last_sync_run` | 읽기 |
| `GET /v1/definition-items/{item_id}` | 정의 항목 하나와 리비전 이력. 종류로 거른 목록의 경로는 미결 | 읽기 |
| `POST /v1/definition-items:validate` | 저장하지 않고 합친 결과를 검사 | 읽기 |
| `POST /v1/definition-items:apply` | 여러 항목을 한 세트로 직접 적용(1.2) | `edit_definitions`(내용에 따라 `run_sources`) |
| `POST /v1/definition-items:preview` | 서버가 가진 레코드로 계산만 하는 미리 보기(8절) | 읽기 |
| `POST /v1/sources/{source_id}:check`, `:introspect` | 저장된 소스의 점검과 소스 탐색 | `inspect_sources` |
| `POST /v1/sources:check`, `POST /v1/sources:introspect` | 저장하지 않은 정의, 또는 주소나 참조가 머리와 다른 정의로 | `run_sources` |
| `POST /v1/sync-runs`, `GET /v1/sync-runs`, `GET /v1/sync-runs/{run_id}` | 시작(202), 목록, 기록 | `run_sources`, 읽기 |
| `GET /v1/sync-runs/{run_id}/samples` | 실행의 문제 표본 | `inspect_sources` |
| `POST /v1/sync-runs/{run_id}:cancel`, `:confirm`, `:discard` | 취소, 확인, 버리기 | `run_sources`(확인과 버리기는 `confirm_guards`) |
| `GET /v1/secrets`, `POST /v1/secrets`, `POST /v1/secrets/{secret_id}/versions`, `POST /v1/secrets/{secret_id}/versions/{version}:retire`, `DELETE /v1/secrets/{secret_id}` | 시크릿 | `operator`, `admin` |

- **작업 자원(`/v1/jobs`)은 이번에 열지 않아요.** 실행 자원이 진행과 취소를 겸하고, 점검, 소스 탐색, 미리 보기는 시간 한도가 있는 동기 요청이에요. 시간 한도를 넘기는 경우가 생기면 그때 정해요(미결).
- 저장하지 않은 정의나 주소가 머리와 다른 정의로 접속하는 경로(`sources:check`, `sources:introspect`)와 시작, 취소는 `run_sources`예요. 저장된 소스의 점검과 소스 탐색은 `inspect_sources`예요. 소스 탐색의 표본은 이름이 `password`, `secret`, `token`, `key`로 보이는 필드를 가려서 보여요.
- 자원마다 `meta.allowed_actions`를 내요. 화면이 "역할이 없으면 보이지 않는다"를 서버의 판단으로 해요.
- 시크릿의 등록 경로는 멱등 키 저장소에 본문 해시를 두지 않아요. 점검, 소스 탐색, 미리 보기의 응답(값의 표본)은 보관하지 않아요.
- 새 문제 코드: 수집을 쓸 수 없는 서버, 직접 적용이 꺼짐, 시크릿이 쓰이는 중, 값처럼 보이는 것, 받기가 이미 돌고 있음, 확인을 기다리는 실행이 있음(같은 소스만).
- 같은 일을 하는 계획된 이름(`:introspect:check`, `:pause:resume` 등)은 바로잡았어요. 계약의 경로 이름은 `:액션` 하나예요.

## 5. 역할, 토큰, 모드, 플래그, 감사

### 5.1 능력과 역할
| 능력 | 하는 일 |
|---|---|
| `edit_definitions` | 정의의 저장(`:apply`) |
| `inspect_sources` | 저장된 소스의 점검과 소스 탐색, 문제 표본 읽기 |
| `run_sources` | 저장하지 않은 정의나 주소가 머리와 다른 정의로 하는 접속(점검, 소스 탐색), 실행과 취소 |
| `confirm_guards`(이미 있어요) | 확인 대기의 확인과 버리기 |
| 시크릿의 등록과 교체 | `operator`나 `admin` |

실행의 목록과 건수는 읽기 역할이면 봐요. 문제 표본은 `inspect_sources`만 봐요. 시크릿의 등록과 교체는 "그 소스를 범위에 가진 `operator`"여야 하지만 범위를 가진 권한 부여가 아직 없어서 **그 조건은 지키지 못해요.** `operator`나 `admin`이면 모든 소스의 시크릿에 쓸 수 있어요.

### 5.2 토큰
- **`local`의 토큰은 둘이에요.** 화면용(`viewer`, `editor`, `operator`, `admin`)과 에이전트용(`viewer` 하나. `/mcp`가 받는 것은 이것뿐이에요). 화면용 토큰은 서버가 루프백에 묶였을 때만 내요(다른 주소면 `viewer`로만 떠요).
- `demo`는 `viewer`예요.

### 5.3 운영 모드의 문
이 기능 묶음 전체(정의의 직접 적용, 시크릿, 접속, 실행)를 `-source-ingestion`으로 켜요. 기본은 꺼짐이고, 꺼져 있으면 읽기 경로만 답해요.

| 플래그 | 뜻 | `local` | 개발 모드 | 운영 모드 |
|---|---|---|---|---|
| `-source-ingestion` | 기능 전체 | 켜짐 | 켜짐 | 꺼짐 |
| `-secrets-key-file` | 마스터 키의 위치 | 설정 폴더(자동) | 명시 | 명시 |
| `-source-inbox` | 파일 소스가 읽는 받는 폴더 | 자료 폴더 밖의 정해진 자리 | 명시 | 명시 |
| `-allow-insecure-sources` | `http` 소스 | 꺼짐(루프백은 됨) | 꺼짐 | 꺼짐 |
| `-allow-unverified-source-tls` | TLS 확인을 끈 소스 | 꺼짐 | 꺼짐 | 꺼짐 |
| `-source-deny-hosts` | 거절 목록에 더하기 | | | |

모든 이름은 예정이에요. `local`의 마스터 키 위치는 사용자의 설정 폴더 아래, 자료 폴더의 식별자로 이름 붙인 파일이에요. 마스터 키는 시크릿을 처음 넣을 때 만들어요. 설정 폴더를 얻지 못하는 환경(컨테이너, 홈이 없는 계정)에서는 키 파일을 명시하라는 오류로 답해요. 받는 폴더는 키가 있는 폴더와도 겹칠 수 없어요. 운영 모드에서 화면(`-web`)의 기본값은 지금 코드대로 켜짐이에요([ADR-0069](adr/0069-screens-live-in-this-repo-and-stay-replaceable.md)).

### 5.4 감사 로그
인증 쪽의 `audit: true` 구조화 로그와 같은 방식이에요. 남기는 것: 시크릿의 등록, 새 버전, 폐기, 복호화해 쓴 일(누가 시켰나, 어느 소스, 어느 주소, 목적), 실행의 시작, 취소, 확인, 버리기, 정의의 저장, 소스를 새로 만들거나 접속을 바꾼 저장, 시크릿의 범위와 허용 주소의 변경.

## 6. 화면

### 6.1 기반
화면보다 먼저 별도의 변경이 만들어요: 생성기가 머리글 인자를 다룸, 변경용 훅(진행, 성공, 실패, 중복 제출 방지), 다시 읽기(실행 상태의 조회), 폼 부품(필드와 오류 연결, 여러 줄 입력, 목록 편집, 확인 대화상자, 저장 결과 알림, 떠날 때의 경고), 412와 409의 한국어 문구, 한글 조합 중의 Enter. **편집기의 논리(폼과 JSON의 왕복)는 `data` 계층의 순수 함수**로 두고 속성 테스트로 잠가요. 임의의 유효한 문서를 폼 모델로 바꿨다가 되돌리면 같은 문서여야 해요.

폼과 JSON 두 보기의 규칙:
- 폼은 타입이 있는 모델이 아니라 **JSON 문서의 트리를 직접 고쳐요.** 서버가 모르는 필드를 거절하므로 "서버는 알고 폼은 모르는 필드"를 지키려는 거예요.
- 서버가 채우는 기본값(`kind`, `receive_mode`, `collector`)을 폼이 다시 써 넣지 않아요(내용이 같은데 리비전이 늘어요). 비운 칸은 빈 글자가 아니라 키를 없애요.
- JSON이 깨진 상태에서는 폼으로 넘어가지 못하고 어디가 깨졌는지 보여요. 큰 정수는 글로 다뤄요.
- 검사 결과는 검사한 그 문서에만 맞아요. 문서가 바뀌면 지워요.
- 저장하지 않은 편집은 세션 저장소에 두되 **시크릿 값은 빼요.**

번들 예산: 검사가 모든 `.js`를 더하므로 늦게 불러와도 합은 줄지 않아요. 방향은 처음 불러오는 묶음의 예산을 그대로 두고 전체의 상한을 따로 두는 거예요. 첫 화면이 빨리 뜬다는 예산의 뜻을 지키는 변경이지 수치를 올려 통과시키는 것이 아니에요. 재 본 값과 함께 화면 기반의 결정 기록이 정해요(미결).

### 6.2 화면 일곱
| 화면 | 하는 일 |
|---|---|
| 1. 빈 폴더의 첫 화면 | KG가 비었을 때 "소스 더하기"와 연습용 소스의 안내 |
| 2. 소스 목록 | 이름, 종류, 받는 방식, 상태 구역(지금은 "쓰지 않음" 여부. 스트림의 상태가 나중에 들어와요)과 마지막 실행 구역(상태, 때, 문제 수)을 따로 |
| 3. 소스 편집 | 종류별 접속 폼, 접속할 주소를 먼저 보임, 시크릿을 고르거나 그 자리에서 등록(값은 정의의 초안과 다른 입력으로 받아 곧바로 보내고 주소와 저장소에 두지 않아요. `type="password"`와 자동 완성 끔), 점검의 결과를 항목별로, 소스 탐색으로 데이터셋의 컬럼과 자연 키를 채움(기본 키를 후보로, 고른 컬럼이 표본에서 겹치는지 바로 보임), 데이터셋마다 "받는 방식: 전체 읽기"와 능력 |
| 4. 매핑 편집 | 피드(데이터셋 → 객체 타입, 이 수집에서 쓸 수 있는 식별 키만, 컬럼 → 속성), 정제, 링크 정의(허용되는 링크 타입만, 다른 소스의 피드도 고를 수 있음, 키 컬럼, 속성). 피드의 순서가 값의 우선순위에 쓰이므로 목록의 순서 바꾸기가 뜻을 바꾼다는 것을 보임. "JSON으로 보기"는 같은 문서의 다른 보기 |
| 5. 미리 보기 결과 | 표본이 어떤 객체와 링크가 되는지, 문제 목록, "표본 밖일 수 있음"과 "표본에서는 확인하지 못함"의 구분 |
| 6. 실행과 결과 | "수집 실행"과 "확인 뒤 적용", 진행 단계, 확인을 기다리는 실행의 차이 요약과 "적용"과 "버리기", 데이터셋별 건수, 문제 목록, "바뀐 것이 없어 새 버전이 없다"와 "닫히기를 기다리는 객체 N개"의 설명, 실행 이력, KG 화면으로 가는 링크 |
| 7. 시크릿 | 목록(메타만), 교체, 쓰는 소스 |

- 소스에서 온 값(표본, 문제 문장, 컬럼 이름)은 **글로만** 그려요(`WEB041`). 스크립트가 들어와도 저장소의 토큰을 읽지 못하게 하려는 거예요.
- 두 탭에서 같은 정의를 고쳤을 때(412)와 기다리는 실행이 있는 소스(409)에 한국어 문구가 있어요.
- 낱말은 [용어집](glossary.md)을 따라요: 소스, 데이터셋, 피드, 매핑, 링크 정의, 정제, 소스 탐색, 점검, 시크릿, 문제 목록, 미리 보기, 확인 뒤 적용, 받는 폴더, 연습용 소스.
- 화면의 모양(색, 글꼴, 여백)은 임시예요. 오래 남는 것은 동작, 데이터 계산(`src/data`), 부품의 구조, 접근성이에요([웹 UI 규칙](web-ui-rules.md)).

## 7. 접속 경로의 권한
[소스와 어댑터](sources-and-adapters.md) 8절의 위험(소스를 등록할 수 있는 사람은 서버가 닿는 내부 주소에 GET을 보낼 수 있다)을 권한으로 줄이는 표예요.

| 일 | 능력 | 이유 |
|---|---|---|
| 소스의 새로 만들기와 주소 변경 | `edit_definitions` + `run_sources`(1.3) | 저장으로 주소를 바꾸면 저장된 소스의 길로 붙을 수 있어서요 |
| 저장된 소스의 점검과 소스 탐색 | `inspect_sources` | 머리의 주소로만 가요 |
| 저장하지 않은 정의의 점검과 소스 탐색 | `run_sources` | 주소가 머리와 달라요 |
| 시크릿의 쓰임 | 복호화에서 소스와 주소를 한 곳에서 확인 | 시크릿이 다른 소스와 다른 주소로 가지 않아요 |

## 8. 미리 보기의 두 갈래
- **소스에 닿는 것**(표본을 받아 오는 일)은 소스 탐색(`sources:introspect`)의 일이에요. 받아 온 표본은 서버가 잠깐 기억해요(메모리, 짧은 수명, 표본의 손잡이를 돌려줘요).
- **`definition-items:preview`**는 서버가 이미 가진 레코드(저장된 원본 레코드나 방금 받아 온 표본)로 계산만 해요. 시크릿도 바깥 요청도 없고 읽는 권한으로 돼요. 이미 받은 소스의 매핑을 고칠 때는 [수집 서비스와 실행](ingestion-service.md) 4절의 다시 계산에서 적용을 뺀 **정확한 미리 보기**가 돼요.
- 표본이 일부일 때 결과를 구분해요: 표본 밖일 수 있는 것("대상 없음", "붙을 대상이 없는 값")은 문제가 아니라 "표본 밖일 수 있음"으로 세고, 자연 키의 겹침과 차수는 "표본에서는 확인하지 못함"이라고 써요. 표본을 어떻게 뽑았는지 적고, 기존 KG와의 합치기는 보여 주지 않는다고 밝혀요. PostgreSQL의 `table` 데이터셋은 시작 쪽 표본이 가리키는 키로 끝 쪽을 읽어 링크의 표본을 맞춰요.
- 동기 요청이고 서버 쪽 시간 한도(60초)가 있어요. 표본은 데이터셋마다 앞의 N개(기본 200, 최대 1,000)예요. 응답은 멱등 키 저장소에 보관하지 않아요.
- 이 미리 보기는 용어집의 "드라이 런"(브랜치의 정의로 후보 KG를 만들어 차이를 보는 일)과 "트라이얼 수집"(브랜치의 새 소스를 읽기 전용으로 수집하는 일)과 달라요. 브랜치와 관계가 없어요.

## 9. 검증
- 단계마다 그 단계가 연 길의 끝에서 끝까지를 넣어요(REST는 전체).
- 새 경로의 계약 검사(`API*`), `planned/routes.json`과의 일치, 생성한 호출 코드(`WEB010`~`WEB013`)를 봐요.
- 구조와 수명, HTTP, PostgreSQL, 시크릿의 검증 목록은 구현 단계의 결정 기록이 정해요. 시크릿은 다른 소스의 시크릿을 참조한 정의와 허용 목록 밖의 주소로 가는 점검의 거절, 키 파일이 없을 때와 다른 키일 때의 문장, 머리글과 SQL에 값을 적은 정의의 저장 거절, 멱등 키로 다시 보냈을 때 표본이 다시 나오지 않는지, 조립에서 복호화에 닿는 경로가 없는지를 포함해요.
- 화면은 이 환경의 브라우저로 흐름을 따라가며 사람이 확인해요. 저장소의 의존성으로 넣지 않는 손 확인이고 무엇을 볼지의 목록을 적어요. 문서만 받은 독립된 검증자가 빈 폴더에서 `local`을 띄우는 것부터 해 봐요(연습용 소스를 써요).
- 보안 검토 둘: 접속 경로를 REST로 열기 전(어댑터, 시크릿, 정의의 쓰기, 저장으로 주소를 바꾸는 경로, 확인 때의 다시 계산)과 릴리스 전(화면 포함).

## 10. 알려진 한계와 미결
- 시크릿의 등록 권한에 "그 소스를 범위에 가진"을 지키지 못해요(5.1).
- 자료 폴더에는 소스의 자료가 평문으로 있어요. 자료 폴더는 소스의 자료와 같은 등급으로 다뤄요.
- 미결: 작업 자원이 필요해지는 때(4절), 번들의 전체 상한(6.1), 플래그의 이름 확정.
