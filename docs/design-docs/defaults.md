# 기본값 표

이 문서는 설계 문서들이 "가정"이라고만 적던 숫자를 제품이 싣는 **기본값**으로 정해 한곳에 둔 거예요. 모두 설정이에요(버전이 있는 설정, ADR-0017). 클로즈드 베타에서 합성 세계와 실제 소스로 측정해서 고쳐요. 다른 문서는 값을 되풀이할 수 있지만 이 문서를 가리켜요. 표에 없는 숫자는 그대로 "가정"이에요.

## 1. 단계와 규모

단계는 알파 1(뼈대와 한 줄, 임시 콘솔), 알파 2(넓히기), 클로즈드 베타, 오픈 베타(프로덕션에 나갈 수 있는 수준), 정식이에요. 설계 문서의 "언제 만드나"는 이 단계로 말해요.

| 단계 | 규모와 모양 |
|---|---|
| 알파 1, 알파 2 | 객체와 링크 100만 개 수준에서 모든 기능이 돈다. PostgreSQL 하나와 실행 파일 하나(역할 넷을 한 프로세스에)로 충분하다 |
| 클로즈드 베타 | 한 KG에 수천만 개(설계의 여유는 수억, 엔진은 1억까지 측정했다). 이때 측정한다(지어낸 3천만 객체와 분포 프로파일로 맞춘 생성기, 영향 범위의 응답, 적용의 속도, 투영의 메모리, 저장의 늘어남) |
| 오픈 베타 | 프로덕션에 나갈 수 있는 수준: 비밀 값과 암호화, 자신의 관측성과 운영, 에이전트 시대의 정의 버전, 저장소의 운영 수준이 구현돼 있다 |

구조는 처음부터 수천만 개를 보고 짓는다(변경 시퀀스, 현재와 이력의 나눔, 투영과 질의 엔진의 경계, 포트). 알파에서 줄이는 것은 구조가 아니라 어댑터의 수와 배포의 모양이다. 요구사항의 숫자(영향 범위 1초와 수 초, 수천만 개)는 그대로 요구이고 클로즈드 베타에서 측정해서 확인한다.

## 2. 저장소와 기록: 무엇을 언제 만드나

| 자리 | 알파 | 클로즈드 베타 | 무엇으로 |
|---|---|---|---|
| 진실(정의, KG, 적용된 변경의 기록) | PostgreSQL | PostgreSQL | |
| 수집 변경 로그 | PostgreSQL 어댑터 | 메시지 기록 저장소 어댑터를 더한다 | Kafka 규약을 말하는 것. 규약에 맞추고 특정 배포판에 묶이지 않는다. 라이선스는 허용 목록 |
| 이어서 받는 소스로서의 메시지 주제 | 만든다(흐름의 첫 어댑터) | | 같은 규약 |
| 콜드 스토리지 | 없음(보존 기한 안에서 PostgreSQL에) | 만든다 | S3 규약을 말하는 객체 저장소와 열 단위의 열린 파일 형식 |
| 분석용 저장소 | 없음 | 측정해서 필요하면 | 그때 정한다 |
| 밖으로 내는 변경 알림 | 번호로 가져가는 API와 사건의 길 | 메시지 주제로 내보내기를 더한다 | 같은 규약 |

결정은 "규약에 맞춘다"이다. 제품의 이름을 고르는 것이 아니라 어느 규약의 어댑터를 만드는지를 정한다.

## 3. 수집

| 무엇 | 기본값 |
|---|---|
| 소스마다 동시 요청 | 1 |
| 소스마다 요청의 속도 | 초당 5 |
| 다시 하기 | 3번, 물러나는 간격을 늘려 가며 |
| 인증 실패 | 바로 끊고 알린다(다시 하지 않는다) |
| 잇달아 실패하면 일정을 멈춤 | 5번 |
| 배치: 한 번에 사라지면 멈춤 | (10% 이상이면서 5건 이상) 또는 500건 이상 |
| 배치: 받은 기록 수가 지난번보다 줄면 덜 받은 것으로 봄 | 30% 이상 |
| 안 보여서 물러나게 함 | 온전한 수집 3번 잇달아, 그리고 처음 안 보인 때부터 24시간 이상 |
| 흐름: 붙잡는 임계값 | 5분 동안 그 공급의 객체의 5% 이상(그리고 50건 이상)이 지워지거나, 받은 모양이 바뀜 |
| 낡음의 판정 | 기대 주기의 2배. 흐름은 지연 5분 |
| "붙을 곳이 없는 값"의 대기 | 24시간 |
| 시계 사건의 간격 | 1분 |
| 흐름에서 KG 버전을 확정하는 주기 | 1시간(바뀐 것이 있을 때) |
| 변경 배치의 크기 | 1만 행 또는 2초 가운데 먼저 |
| 푸시 수집의 "한 번만 반영"이 서는 겹침 거르는 기간 | 7일(소스마다 설정) |
| 지정 재수집 | 주체마다 분에 60건. 일정에는 소스 속도 상한의 절반 이상을 남긴다 |
| 완전성 선언이 저절로 멈추는 임계값 | 기대 수와 받은 수가 1% 넘게 어긋난 수집이 잇달아 2번 |

## 4. 보관

| 무엇 | 기본값 |
|---|---|
| 원본 레코드의 보관 | 90일(닫힌 구간에만 건다. 그 뒤는 콜드 스토리지로. 없으면 삭제) |
| `volatile`만 대는 흐름의 원본 줄 보관 | 3일 |
| 경량 변경 레코드 보관 | 7일 |
| 물러난 객체가 옛 ID로 되살아나는 기간(강한 키로 맞지 않았을 때) | 30일 |
| 지나간 KG 이력의 보관 | 1년. 고정된 버전은 지우지 않음 |
| 지표의 보관 | 촘촘한 값 30일, 뭉친 값 13달 |
| 감사 로그의 보관 | 3년 |

## 5. 질의, 권한, 정의

| 무엇 | 기본값 |
|---|---|
| 권한 정보 사본의 나이 상한 / 계정을 끄거나 토큰을 거둔 것이 퍼지는 시간 | 15분 / 30초 |
| `query_answers`(질의의 답에 기대는 물음)를 다시 따지는 주기 | 15분 |
| 투영을 통째로 다시 짓는 임계값 | 바뀐 객체와 링크가 KG의 20% |
| 조각(투영과 엔진)의 단위와 크기 | 자리의 하위 나무, 노드 100만까지 |
| 오버레이를 합치는 때 | 조각의 5%를 넘거나 10분 |
| 영향 범위의 최소 절단 차수 | 2 |
| 역량 질문 패턴의 깊이 / 한 걸음의 갈래 | 8걸음 / 1천 |
| 사전 정의 질의의 한 쪽 | 100(최대 1천) |
| 긴급 리버트를 할 수 있는 기간 / 사후 검토의 기한 | 7일 / 3일 |
| 메이저 버전(API)을 물리는 기간 | 12달 |

## 6. 값이 아직 없는 것
아래는 설계가 정해졌지만 값은 정해지지 않은 것이에요. 값을 지어내지 않아요. 구현하는 변경이 측정해서 정하고 이 표를 고쳐요(가정). 노출됨이 번지는 깊이는 설정이 없어요(끝까지 번져요).

| 무엇 | 어디 |
|---|---|
| 주체마다 열린 브랜치 수, 줄에 선 제안 수, 하루 제안 수, 드라이 런의 계산 예산, 트라이얼 수집의 저장량, 활동 없는 초안의 자동 닫기 기한 | definitions-at-agent-scale.md 9절 |
| 자동 병합의 "차이가 작은 한도", 최근 되돌림 비율의 기준 | 같은 문서 6절 |
| 문장, 잠금 대기, 놀고 있는 시간의 한도(역할마다), 정족수, `max_staleness`(소스에서 본 값이 얼마나 낡아도 되나) | postgres-operations.md |
| 붙은 메시지 기록 저장소가 끊겼을 때 수집기가 쌓는 한도 | postgres-operations.md |
| 푸시 수집의 한 번에 보내는 양 | ingestion-extensions.md |
| 구조 물음의 색인 크기의 어림(지어낸 100만에서 잴 것) | competency-questions.md |

## 7. 읽는 법

- 문서에서는 "기본값(설정)"이라고 적고, 클로즈드 베타에서 측정해서 고친다고 밝힌다.
- 이 표의 값을 바꾸면 이 문서를 먼저 고치고, 되풀이한 문서를 맞춘다.
