# 용어집

이 용어집의 표가 사전의 단일 출처다. 문서 용어 검사(`WORD003`)가 이 표를 직접 읽는다(ADR-0029). 제품 용어는 이 문서에, 개발과 운영에서 널리 쓰는 일반 용어는 [일반 용어집](glossary-general.md)에 둔다. 두 문서의 표는 열이 같다.

## 쓰는 법

1. **현장에서 통용되는 표준 용어를 쓴다.** 개발자와 인프라 엔지니어가 업무와 문서에서 실제로 쓰는 말이다. 그중 쉽고 널리 쓰이는 말을 고른다. 새 말을 지어내지 않는다.
2. **영어가 관행인 말은 영어로 쓴다.** API, ETag, KG, SSE, OIDC, CI, upsert가 그렇다. 우리말이 자연스러운 말(객체, 링크, 속성, 요구사항, 결정 기록)은 우리말로 쓴다.
3. **한 가지 뜻에 한 가지 용어.** 뜻이 여럿인 고유어(길, 묶음, 자리, 칸, 쪽 등)를 용어로 쓰지 않는다. 뜻마다 표준 용어를 따로 쓴다. 일반 용어집의 "뜻이 갈리는 말" 표를 따른다.
4. **옛 표기는 표의 "옛 표기" 열에 적는다.** 문서에 옛 표기가 돌아오면 검사가 알린다. 뜻이 여럿인 말은 열에 적지 않고 그 말이 든 합성어(`읽는 자리`, `쪽 넘김`)만 적는다. 표준 용어는 금지하지 않는다.
5. **처음 나올 때 영어를 병기한다.** 문서마다 첫 등장에 `리스(lease)`처럼 적고 이후는 한글만 쓴다.
6. **비유 동사와 고유어 수사를 쓰지 않는다.** 장애가 나다, 포함하다, 8종처럼 기술 동사와 숫자를 쓴다.
7. **타입의 이름은 영어다.** 객체 타입, 링크 타입, 액션 타입, 속성의 이름은 영어로 짓는다(ADR-0007). 화면에서 한국어로 보일 이름은 데이터로 따로 둔다.
8. **문체.** 설계 문서는 해요체, 결정 기록과 요구사항과 안내서는 한다체다. 한 문서 안에서 섞지 않는다. 화면의 버튼은 다음에 일어날 일을 말하고, 숫자에는 단위를 붙인다. 화면은 다른 리포지토리가 만들고, API는 글이 아니라 코드와 값을 준다(ADR-0016).

표의 열은 표준 용어, 옛 표기(쓰지 않음), 뜻, 영어 대응이다. 영어 대응은 코드와 스키마의 이름과 문서의 용어를 잇는다.

## 제품의 말

### 모델의 말
| 표준 용어 | 옛 표기(쓰지 않음) | 뜻 | 영어 대응 |
|---|---|---|---|
| **객체 / 객체 타입** | 개체, 엔티티 | 세계에 있는 것 하나(서버, VM, 스위치)와 그 종류 | object / object type |
| **링크 / 링크 타입** | 관계 종류, 관계 타입, 관계 잇기, 관계 정의, 라벨·관계 | 객체 사이를 잇는 것과 그 종류 | link / link type |

### KG와 모델
| 표준 용어 | 옛 표기(쓰지 않음) | 뜻 | 영어 대응 |
|---|---|---|---|
| **지식 그래프(KG)** | 운영 세계, 프로덕션 세계, 디지털 트윈 | 실제 IT 인프라를 객체와 링크로 구축한 그래프. | knowledge graph |
| **KG** | 토폴로지, 온톨로지 | 지식 그래프의 약어. 데이터를 가리킬 때는 KG라고 쓴다 | KG |
| **확정 버전 (KG 버전)** | 봉한 버전, 봉한 자리 | 변경 시퀀스 위에 확정해 이름을 붙인 KG의 한 시점. 바뀌지 않는다. 차이 비교와 감사는 확정 버전 사이에서 한다. KG를 가리켜 스냅샷이라고 하지 않는다 | sealed (immutable) version |
| **변경 배치** | 변경 묶음 | KG에 한꺼번에 적용되는 변경들. 적용할 때마다 번호(`change_seq`)가 하나씩 오른다 | change batch (`change_batch`) |
| **변경 시퀀스** | 변경의 이어짐 | KG를 이루는, 번호가 매겨진 변경의 추가 전용 나열. KG는 이것을 적용한 결과다 | change sequence |
| **표준 모델** | 기본 스키마 | 제품에 들어 있는 객체 타입, 링크 타입, 액션 타입의 목록. 9개 층에 걸친다(10번째 층 `system`은 프락시움 자신의 컴포넌트인 `sys` 타입이 놓이는 곳이고, 표준 모델의 데이터 파일과 따로 제품이 싣는다) | standard model |
| **링크 의미** | 링크의 뜻, 링크 뜻 | 링크 타입마다 고정 목록(11가지)에서 하나 고르는 의미. 영향이 어떻게 전파되는지를 정한다 | link semantics (`semantics`) |
| **채널** |  | 객체의 상태를 가르는 6종: `service`, `power`, `cooling`, `network`, `storage`, `management`. 채널마다 `up`, `down`, `unknown` | channel |
| **이중화 그룹** | 이중화 묶음 | 구성원 중 몇 개가 정상이어야 하는지(`min_alive`)를 가진 객체 | redundancy group (`RedundancyGroup`) |
| **근거 종류** |  | 값이 어디서 왔는지의 4종: 설정에서 읽음, 수집한 순간에 그렇게 보임, 사람이나 문서가 적음, 규칙이 파생함. 근거 등급과는 다른 축이다 | evidence kind |
| **식별 키** |  | 객체가 같은 것임을 알아보는 속성이나 바깥 식별자의 모음 | identity key |
| **값 타입** |  | 속성의 자료형에 붙는 이름(IPv4 주소, 일련번호 등). 검증과 정규화를 가진다 | value type |
| **E2E(엔드투엔드) 프로세스** |  | 요청 접수부터 완료까지, 여러 조직과 시스템을 거치는 업무의 전체 흐름. 각 문서에서 처음 나올 때 한 번 풀어 쓴다 | end-to-end process |

### 수집
| 표준 용어 | 옛 표기(쓰지 않음) | 뜻 | 영어 대응 |
|---|---|---|---|
| **소스** |  | 데이터를 읽어 오는 현실 시스템이나 파일 | source |
| **어댑터** |  | 프로토콜 하나를 다루는, 제품에 들어 있는 코드 | adapter |
| **프리셋** | 레시피 | 소스 제품 하나에 맞춘 데이터: 허용된 요청의 목록과 기본 매핑 | preset |
| **원본 레코드** | 원본 기록, 로우 데이터 | 소스에서 받은 그대로 보관한 레코드 한 건 | raw record (`raw_record`) |
| **데이터셋** |  | 원본 레코드를 행과 컬럼으로 본 표, 그리고 정제의 결과 | dataset |
| **정제** | 전처리 | 고정 목록의 연산으로 데이터셋을 다듬는 일 | refine |
| **피드** | 공급 | 데이터셋 하나에서 객체 타입 하나로 가는 매핑 하나. 자기가 매핑한 속성만 소유한다 | feed |
| **매핑** |  | 데이터셋의 컬럼을 객체 타입의 속성에 잇는 정의 | mapping |
| **링크 정의** | 관계 규칙 | 객체 사이를 잇는 조건을 적은 정의 | link definition |
| **기대 조건** |  | 데이터셋과 피드에 붙이는 고정 종류의 데이터 검사. 어기면 멈추거나(`fail`) 문제 목록에 올린다(`warn`) | expectation |
| **동기화** | 싱크 | 소스에서 받아 KG의 새 버전까지 가는 실행 한 번 | sync |
| **수집 엔벨로프** | 수집 봉투, 인제스트 포맷 | 제품 밖의 수집기가 원본 레코드를 프락시움에 보낼 때 쓰는 공개된 형식 | ingest envelope |
| **수집기** |  | 소스를 읽어 원본 레코드를 본체로 보내는 역할. 소스가 있는 망에 따로 기동하거나, 소스 담당자가 수집 엔벨로프로 직접 만든다 | collector |
| **안전장치** |  | 적용 전에 멈추게 하는 검사 | guardrail |
| **보류된 스트림** | 붙잡힌 흐름 | 안전장치가 걸려 적용만 멈춘 스트림. 수집은 멈추지 않고, 운영 역할이 해제하거나 폐기한다 | held stream |
| **적용** |  | 후보를 KG의 새 버전으로 공개하는 일 | apply |

### 정의의 버전과 브랜치
| 표준 용어 | 옛 표기(쓰지 않음) | 뜻 | 영어 대응 |
|---|---|---|---|
| **리비전** |  | 정의의 항목이 바뀔 때마다 새로 붙는 번호 있는 내용(`item_revision`). 사용자에게는 `리비전 7`로 보인다. KG 버전과 구분한다 | revision |
| **정의** | 컨피그 | 버전 관리되는 구성 데이터: 타입, 소스, 프리셋, 정제, 피드, 식별 규칙, 링크 정의, 기대 조건, 일정, 안전장치의 값 | definition |
| **정의 세트** | 정의 묶음 | 어느 항목이 어느 리비전인가의 전체 목록. 내용 해시를 가지고 `D-142`처럼 번호로 부른다 | definition set (`definition_set`) |
| **소속** | 항목의 자리, 딸린 자리 | 정의의 항목이 딸린 곳(소스, 객체 타입, 출발 타입 등). 수정 권한과 승인의 범위를 가르는 기준이다 | scope target |
| **브랜치** | 변경안 | 운영에 영향 없이 정의를 수정해 보는 작업 공간. 여럿이 동시에 열 수 있다 | branch |
| **제안** |  | 브랜치를 운영 정의에 반영해 달라는 요청(변경 요청에 해당) | proposal |
| **병합** |  | 제안을 검사와 승인을 거쳐 운영 정의로 한꺼번에 합치는 일 | merge |
| **차단 사유** | 막는 까닭 | 제안이 병합되지 못하는 이유(충돌, 오래됨, 검사 실패, 모자란 승인 등). 상태가 아니라 그때그때 파생한다 | blocking reason |
| **마이그레이션** | 옮김 | 호환되지 않는 변경에 함께 적는 것: 어느 속성이 어느 속성으로, 어떤 변환으로 가는지와 식별 이력의 처리 | migration |
| **드라이 런** | 후보 실행, 후보 빌드 | 수집해 둔 원본 레코드와 브랜치의 정의로 후보 KG를 만들어 지금 버전과의 차이를 보는 일. 운영에 영향이 없다. API 이름은 `candidate-runs` | dry run |
| **트라이얼 수집** | 시험 수집 | 새 소스를 더하는 브랜치에서 하는 읽기 전용 수집. 브랜치에 딸린 스테이징 영역에 담긴다 | trial ingest (`trial-ingests`) |

### 질의와 운영
| 표준 용어 | 옛 표기(쓰지 않음) | 뜻 | 영어 대응 |
|---|---|---|---|
| **KG 질의** | KG에 묻기 | KG에서 사전 정의 질의로 객체, 경로, 영향 범위를 읽는 일. 문서 [KG 질의](kg-queries.md)의 제목이기도 하다 | KG query |
| **영향 범위** | 블라스트 레이디어스 | 어떤 객체에 장애가 났을 때 장애나 위험이 미치는 객체들 | blast radius |
| **프로젝션** | 투영 | KG 버전 하나에서 만든, 영향 범위 계산용 메모리 안의 그래프. 다시 만들 수 있다 | projection |
| **변경 알림** |  | KG의 새 버전에서 바뀐 것을 다른 시스템에 알리는 경로 | change notification |
| **신선도** |  | 그 데이터를 마지막으로 온전히 수집한 때로부터 지난 시간 | freshness |
| **문제 목록** | 에러 리스트 | 수집하는 중에 해결하지 못한 것(충돌, 잇지 못한 링크, 틀린 값)과 알림의 목록. 규칙으로 푼다 | issue list |
| **헬스 상태** | 건강 | 소스, 피드, 타입 같은 자원이 지금 제대로 동작하는지를 나타내는 6종: `healthy`, `degraded`, `failing`, `paused`, `unknown`, `affected_upstream` | health |
| **목표** |  | 피드, 타입, 속성에 붙이는 약속(신선도, 온전함, 유효성, 수집량). 못 지킨 비율을 센다 | objective (SLO) |
| **역량 질문** |  | 이 KG가 답할 수 있어야 하는 질문. 고정 패턴으로 적는 정의다 | competency question |
| **충족률** |  | 역량 질문이 요구하는 것을 다 채운 대상 객체 수 ÷ 대상 객체 수 | fulfillment ratio |

### 프락시움 자신의 운영
| 표준 용어 | 옛 표기(쓰지 않음) | 뜻 | 영어 대응 |
|---|---|---|---|
| **이벤트 코드** | 사건 코드 | 로그, 오류, 알림에 붙는 안정된 코드. 의미, 심각도, 살펴볼 것, 실행할 수 있는 운영 액션이 딸린다 | event code |
| **운영 액션** | 운영 행위 | 프락시움을 운영하려고 API로 하는, 정해진 목록의 작업(소스 멈추기, 워커 비우기 등) | ops action |
| **진단** |  | 지금 무엇이 이상 상태이고, 이유가 무엇이고, 근거 신호와 실행할 수 있는 운영 액션이 무엇인지를 구조로 답하는 것(`diagnose`) | diagnosis |
| **점검 모드** | 유지보수 모드 | 수정 요청을 받지 않고 읽기만 답하는 상태 | maintenance mode |

### 시크릿, 정의를 쓰는 에이전트, 임시 콘솔
| 표준 용어 | 옛 표기(쓰지 않음) | 뜻 | 영어 대응 |
|---|---|---|---|
| **시크릿** | 비밀 값, 크리덴셜 | 소스의 연동 정보(계정, 토큰, 인증서, 연결 문자열) 같은 것. 쓰기 전용이고 정의에는 참조만 들어간다 | secret |
| **마스터 키** | 으뜸 열쇠 | 데이터 키를 래핑하는 키. 리포지토리 밖에 둔다 | master key (KEK) |
| **엔벨로프 암호화** | 봉투 암호화 | 시크릿마다 데이터 키로 암호화하고 데이터 키를 마스터 키로 래핑하는 방식 | envelope encryption |
| **위험 등급** | 위험의 등급 | 제안의 후보 차이에서 계산하는 R0~R3. R3는 언제나 사람이 본다 | risk grade |
| **자동 병합** |  | 정책이 허락한 낮은 등급의 병합. 승인이 아니다. 기본은 꺼짐 | auto merge |
| **재수집** | 새로고침, 다시 받기 | 객체를 지정해 그 객체의 데이터만 소스에서 지금 다시 읽는 일 | re-ingest (targeted refresh) |
| **기대와 대조** | 기대와 견주기 | 기대하는 값과 기준 시각으로 소스에서 본 값을 대조하는 일. 4종: `confirmed`, `not_yet`, `contradicted`, `unverifiable` | expectation check |
| **파서 / 라인 템플릿** | 해석기, 줄 틀 | 문서를 트리로 만드는 제품 내장 고정 목록 / 정해진 꼴의 글을 행으로 읽는 데이터 | parser / line template |
| **분포 프로파일** | 모양 카드 | KG의 연결 수 분포, 깊이, 그룹 크기, 사이트 간 교차 비율. 합성 세계 생성기를 맞추는 데 쓴다 | shape profile |
| **시스템 KG** |  | 프락시움 자신의 컴포넌트를 담는 별도의 KG(네임스페이스 `sys`) | system KG |
| **임시 콘솔** |  | 클로즈드 베타까지 기능을 눌러 보는, 지울 수 있는 테스트용 화면. 제품의 화면이 아니다 | temporary console |

### 저장, 적용, 질의
| 표준 용어 | 옛 표기(쓰지 않음) | 뜻 | 영어 대응 |
|---|---|---|---|
| **경량 변경 레코드** | 가벼운 변경의 줄 | `volatile` 속성이 바뀔 때 이력 없이 쓰는 짧은 레코드(객체, 속성, 새 값의 표지, `change_seq`). 프로젝션과 알림이 따른다. 링크는 `volatile`이 될 수 없다 | light change record (`light_change`) |
| **세대** |  | 시점 복구를 할 때마다 오르는 번호. 응답의 `as_of`와 커서에 실린다 | generation |
| **읽기 워터마크** | 읽는 자리 | 큰 적용이 쪼개져도 읽는 쪽이 반쯤 반영된 배치를 보지 않게, 배치가 끝날 때만 오르는 번호(`readable_through`) | read watermark |
| **소스 커서** | 읽은 자리 | 소스에서 어디까지 읽었는지를 가리키는 위치(`source_cursor`) | source cursor |
| **타입 번호** |  | 등록부가 타입, 링크 타입, 속성마다 내주는 바뀌지 않는 작은 정수(`type_no` 등). 이름은 바꿀 수 있다 | type number |
| **보류된 항목** | 붙잡힌 항목 | 첫 적용의 확인을 기다리는 동안 아직 앞 버전으로 동작하는 피드와 타입(`held_items`) | held items |
| **청크** | 쪽마다 | 프로젝션과 엔진을 나누는 단위(스테이징 영역의 하위 트리). 청크마다 병합하고 버전을 바꾼다 | chunk |
| **직접 노출 / 상속된 노출** | 물려받은 노출 | `exposed_direct`(자기의 이중화를 잃음)와 `exposed_inherited`(의존하는 것이 노출됨). 끝까지 전파된다 | direct / inherited exposure |

### 권한
| 표준 용어 | 옛 표기(쓰지 않음) | 뜻 | 영어 대응 |
|---|---|---|---|
| **권한 부여** |  | 누구(사람이나 그룹) × 역할 × 범위 하나. 권한은 여기서만 온다 | grant |
| **역할** |  | 제품에 든 고정 목록 8종: `viewer`, `editor`, `approver`, `operator`, `model_steward`, `auditor`, `admin`, `ingester`(소스에 푸시 수집만 하고 읽기도 없다) | role |
| **범위** |  | 권한 부여가 미치는 곳. 전체, 객체 타입(층, 네임스페이스), 소스, 민감 등급의 한도 | scope |
| **범위 한정 위임** | 범위 있는 관리 | 자기 범위 안에서 `viewer`와 `editor`를 부여하고 회수하는 권한(`delegate`). `admin`만 붙인다 | scoped delegation |
| **셀프 승인** | 혼자 승인 | 설정 `solo_approval`. 자기가 수정한 것을 자기가 승인한다. 기본은 꺼짐이고 켜면 감사 로그에 표시가 남는다 | self-approval |
| **담당자** | 주인 도메인, 도메인 주인 | 소스, 타입, 정의의 항목에 붙는 사람이나 그룹. 권한이 아니라 연락처다 | owner contact |
