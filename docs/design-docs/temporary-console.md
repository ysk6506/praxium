# 임시 콘솔

제품의 화면은 다른 리포지토리가 만들어요(ADR-0016). 그런데 제품 책임자는 프런트엔드 리포지토리를 당장 만들지 않기로 했어요. 클로즈드 베타까지 브라우저로 제품을 써 볼 수 있게, **나중에 삭제할 수 있는 임시 화면**을 이 리포지토리의 `apps/web`에 둬요. 처음에는 빌드 없는 정적 파일로 정했지만, 표와 페이지네이션과 키보드 조작을 손으로 짜는 것이 더 오래 걸려서 React 앱으로 바꿨어요(ADR-0035가 ADR-0016의 9번을 고쳤어요). 이 문서는 지금의 모양과 삭제하기 쉽게 지키는 규칙, 화면 목록, 삭제 조건을 적어요.

## 1. 목적과 다루는 질문
- 임시 콘솔의 성격(2절), 삭제하기 쉽게 지키는 규칙(3절), 배치와 제공 방식(4절).
- 화면 목록(5절), 접속과 토큰(6절), 하지 않는 것(7절), 삭제 조건과 순서(8절).

## 2. 임시 콘솔의 성격과 범위
| 임시 콘솔은 | 임시 콘솔이 아닌 것 |
|---|---|
| 제품 책임자가 기능을 눌러 보는 **임시** 화면이에요 | 제품의 화면이 아니에요. UX와 UI는 클로즈드 베타에서 프런트엔드 리포지토리가 제대로 설계해요 |
| 공개된 `/v1` API의 사용자 하나예요 | 백엔드의 일부가 아니에요. 백엔드는 이것 없이 빌드되고 테스트돼요 |
| API를 쓰는 예시예요 | API를 화면에 맞추는 이유가 아니에요 |
| 알파의 테스트를 편하게 해요 | 알파의 기준이 아니에요. 기준은 "모든 기능이 API와 CLI로 된다"예요 |

```
 브라우저 ──(1) 정적 파일 ──▶ [praxium api serve] ── 실행 파일에 담긴 웹 UI(adapter.webui)를 /v1 밖에서 내요
    │                          │
    └──(2) 공개된 /v1 만 호출(Authorization: Bearer) ─▶ 일반 API 경로(콘솔 전용 경로는 없어요)
```

## 3. 삭제하기 쉽게 지키는 규칙
| # | 규칙 | 어긋나면 |
|---|---|---|
| 1 | **한 폴더(`apps/web`)와 임베드 패키지(`backend/internal/webui`)에만 있어요.** 백엔드는 `apps/web`을 가리키지 않아요(`WEB031`). 임베드 폴더에는 자리표시자 페이지만 커밋하고 실제 빌드는 `.gitignore`로 빼요(`WEB030`, `WEB032`) | 백엔드를 고쳐야 지울 수 있어요 |
| 2 | **공개된 `/v1`만 써요.** 콘솔 전용 경로와 서버 측의 화면 처리를 만들지 않아요. API 호출 코드는 계약에서 생성하고 계약과 다르면 검사가 실패해요(`WEB010`~`WEB013`) | 콘솔을 지워도 그 경로가 계약에 남아요 |
| 3 | **의존성은 최소로, 허용 목록 안에서만 써요.** 런타임은 `react`, `react-dom`, `@base-ui/react`뿐이고 새 패키지는 결정 기록과 의존성 표가 있어야 해요(`WEB001`). 라우터, 상태, 데이터 조회, 아이콘, 테이블 라이브러리는 쓰지 않아요 | 지울 때 흔적과 라이선스 고지가 남아요 |
| 4 | **계층은 위로만 의존해요.** `api`, `data`, `ui`, `screens`. Base UI는 `ui`에서만 import해요(`ARCH020`). 색은 토큰 파일 하나에만 쓰고(`WEB020`, `WEB021`) 화면은 토큰 이름만 써요 | 화면 하나를 고칠 때마다 다른 곳이 깨져요 |
| 5 | **외부 주소를 부르지 않아요.** 글꼴, 스크립트, 이미지를 내려받지 않아요. 응답의 `Content-Security-Policy`가 같은 출처만 허용해요 | 폐쇄망에서 깨져요 |
| 6 | **화면 코드(`screens`)는 테스트 잠금과 요구사항 추적에서 빠져요.** `api`, `data`, `ui`는 다른 코드처럼 잠가요(ADR-0035) | 화면을 보고 바꿀 때마다 잠금을 고쳐야 해요 |

## 4. 배치와 제공 방식
- **폴더.** `apps/web/src`의 `api`(생성한 호출 코드), `data`(조회와 상태), `ui`(컴포넌트와 토큰), `screens`(화면)와 진입점 파일이에요. 설정은 `apps/web/config`예요.
- **빌드와 실행.** `scripts/build-with-web.sh`(`pnpm web:build`)가 웹 빌드, 임베드 폴더로 복사, Go 빌드를 한 번에 해요. `praxium api serve`가 `/v1` 밖의 GET과 HEAD에 웹 UI를 내고, `-web=false`면 API만 내요. 화면이 없는 빌드는 그 사실을 알리는 페이지를 내요. 개발 중에는 `pnpm --filter @praxium/web dev`가 `/v1`을 `127.0.0.1:8080`으로 넘겨요.
- **주소.** 화면의 주소는 `#` 뒤에 있어요(`#/kg/main/types/PhysicalServer`). 서버는 정적 파일과 `index.html`만 내요. `/v1`은 절대 화면으로 대체하지 않아요.
- **같은 출처.** 화면과 API가 같은 주소에서 나오므로 CORS 허용이 필요 없어요.
- **글과 모양.** 문구는 한국어이고 시스템 글꼴을 써요(한국어 글꼴이 앞). 어두운 모드는 시스템 설정을 따르고 모든 조작은 키보드로 돼요.

## 5. 화면 목록
기능을 눌러 볼 만큼이에요. 모두 읽기예요. 객체 테이블의 속성 컬럼은 `queries:find`가 속성을 주지 않아서 행마다 `queries:get`을 불러요(동시 6개).

| 화면 | 보이는 것 | 호출하는 API |
|---|---|---|
| 접속 설정 | 접속 방식 셋의 설명, 개발용 토큰의 입력과 삭제. 토큰은 브라우저에 저장하고 호출마다 실어요 | 없음 |
| KG 목록 | 읽을 수 있는 KG의 목록(별칭, 이름, KG ID, 역할, 상태) | `GET /v1/kgs` |
| 객체 타입 | 타입 목록과 타입별 객체 수. 이름이나 설명으로 검색하고, "객체가 있는 타입만" 토글과 타입, 계층, 객체 수 컬럼의 정렬이 있어요 | `GET /v1/object-types`, `POST /v1/kgs/{kg}/queries:find`(요약) |
| 객체 테이블 | 타입별 객체, 식별자, 고른 속성 컬럼, 페이지 크기와 이전·다음. 하위 타입(이 타입을 상속해 더 구체적으로 정의한 타입)의 객체는 이 테이블에 없고 그 타입을 선택해서 봐요 | `POST /v1/kgs/{kg}/queries:find`, `GET /v1/object-types/{type_id}`, `POST /v1/kgs/{kg}/queries:get` |
| 객체 상세 | 속성, 식별자, 근거 등급(사실, 가정, 알 수 없음)과 출처 | `POST /v1/kgs/{kg}/queries:get` |
| 이웃 | 링크 타입과 방향별 목록, 이웃으로 이동 | `POST /v1/kgs/{kg}/queries:neighbors` |

로딩, 빈 상태, 오류 상태를 모두 보여 줘요. 오류는 API가 준 `code`를 한국어 문장과 해야 할 일로 바꾸고, 서버가 `params`에 싣는 원인(필드, 메시지)과 찾지 못한 대상(KG, 객체, 객체 타입)을 바로 보여 줘요. 코드, 상태, 추적 ID는 "자세히" 안에 접어 둬요. 모르는 주소는 "페이지를 찾을 수 없습니다"와 돌아갈 링크를 보여 줘요. 그래프 그림은 없어요. 경로는 [REST API의 자원 문서](rest-api-resources-data.md)와 OpenAPI 문서의 것이에요.

## 6. 접속과 토큰
개발용 인증(`api serve -mode development`의 고정 토큰, ADR-0024)에 맞춰 접속 설정 화면에 토큰을 붙여 넣어요. 토큰은 브라우저의 `localStorage`에 저장하고(저장소를 쓸 수 없으면 그 탭에서만 쓰고) `Authorization: Bearer`로 실어요. 서버에 세션은 없어요. 개발용 인증이 실제 인증(TD-0010)으로 바뀌면 이 화면을 로그인 흐름으로 바꿔요. API가 준 값은 텍스트로만 그려요. HTML로 해석하지 않아요.

접속 방식은 셋이에요(ADR-0038, ADR-0042). 접속 설정 화면이 같은 설명을 보여 줘요.

| 방식 | 들어오는 길 | 화면에 보이는 것 |
|---|---|---|
| 데모 | `praxium demo`가 출력하는 주소의 `#` 뒤(`#/connect?token=…&demo=1`) | 맨 위의 데모 안내 줄과 "데모" 배지 |
| 로컬 모드 | 서버가 출력하는 주소의 `#` 뒤(`#/connect?token=…&mode=local`) | "로컬 모드: 이 컴퓨터에서 혼자 쓰는 용도이며 운영용이 아닙니다" 줄과 "로컬" 배지 |
| 개발용 토큰 직접 입력 | 접속 설정에 `-dev-token-file`로 지정한 토큰을 붙여 넣어요 | 표시 없음 |

데모와 로컬 모드에서는 입력이 필요 없어요. 화면은 주소의 토큰을 저장하고 주소를 첫 화면으로 바꿔요. 이것은 처음 열 때뿐 아니라 열려 있는 탭에 새 주소를 붙여 넣을 때도 해요(`#`만 바뀌어도 페이지가 다시 로드되지 않으므로 `hashchange`를 봐요). 새 토큰을 받으면 이전 토큰으로 읽은 화면과 데이터를 비워요. 프래그먼트는 서버로 가지 않아서 서버 로그에 남지 않아요. 접속 표시는 그 토큰에 묶어 저장해서, 다른 토큰을 입력하거나 토큰을 지우면 함께 사라져요. 인증 오류의 안내는 방식에 맞춰요. 데모와 로컬 모드는 "서버를 다시 시작하면 접속 링크가 바뀝니다. 터미널에 출력된 새 주소를 여십시오.", 직접 입력은 토큰을 다시 입력하라고 해요.

### 주소에 담기는 상태
화면의 상태는 `#` 뒤의 쿼리에 있어서 뒤로 가기, 새로 고침, 링크 공유에서 유지돼요. 기본값은 쓰지 않아요.

| 화면 | 쿼리 |
|---|---|
| 객체 테이블 | `page`, `cursor`(그 페이지의 시작), `size`(페이지당 개수), `cols`(고른 컬럼) |
| 객체 타입 | `q`(검색어), `all=1`(객체가 없는 타입도), `sort`와 `dir` |
| 객체 상세 | `tab` |

모르는 `tab` 값은 첫 탭으로 가고 주소를 고쳐 써요. 페이지 이동은 뒤로 가기 항목을 만들어요. 커서는 앞으로만 가서 이전 페이지의 커서는 탭에 저장하고, 링크로 바로 연 페이지에서는 "이전"이 꺼지고 "처음"이 있어요. 화면을 옮기면 맨 위에서 열고 뒤로 가면 이전 위치로 돌아가요.

## 7. 하지 않는 것
- 쓰기. 정의 편집, 권한 부여, 운영 액션은 CLI나 API로 해요. 시크릿은 다루지 않아요.
- 콘솔 전용 경로, 집계 경로, 서버 측의 화면 처리.
- 그래프 그림, 영향 범위, 헬스 상태, 브랜치와 제안 화면. 필요해지면 화면을 추가해요.
- UX 측정과 디자인의 다듬기. 제품의 화면은 프런트엔드 리포지토리가 설계해요.

## 8. 삭제 조건과 순서 (TD-0007)
**삭제 조건.** 둘 중 먼저 충족되는 쪽이에요: 프런트엔드 리포지토리가 구축되어 알파의 테스트 화면이 거기에 생겼을 때, 클로즈드 베타가 끝났을 때. 더 쓸 만하다는 이유로 미루지 않아요. 미루려면 조건을 바꾸는 결정 기록이 있어야 해요.

**삭제 순서.** 한 변경에서 해요.
| 순서 | 하는 일 | 확인 |
|---|---|---|
| 1 | `apps/web`을 삭제해요 | 폴더 밖에 콘솔의 파일이 없어요 |
| 2 | `backend/internal/webui`, `Config.UI`와 `-web` 플래그, `scripts/build-with-web.sh`를 삭제해요 | 서버가 `/v1`만 내요 |
| 3 | 구조 계약의 `web.*`, `adapter.webui`, `harness/config/web.yaml`, `harness/src/checks/web.ts`, 허용 패키지를 삭제하고 `ci.yml`의 웹 단계와 라이선스 고지에서 패키지를 빼요 | 검사가 그대로 통과해요 |
| 4 | 문서와 대장을 정리해요 | ARCHITECTURE.md와 AGENTS.md의 예외 문장과 의존성 표의 행, 이 문서와 REQ-209와 REQ-275~279를 폐기(retired) 처리하고, TD-0007을 닫아요 |

콘솔이 호출하던 API는 그대로예요. 계약이기 때문이에요.

## 9. 알파의 기준과의 관계
콘솔은 알파 1에 구축하고 제품 책임자가 거기서부터 눌러 봐요. 알파의 기준은 그대로예요. **모든 기능이 API와 CLI로 돼요**(ADR-0016, REQ-147). 콘솔에 없다고 기능이 없는 것이 아니고, 콘솔에 있다고 기능이 완료된 것도 아니에요. 기능의 완료는 API의 계약과 테스트가 정해요.

## 10. 알려진 한계와 미결 사항
- 화면은 합성 세계와 실제 서버를 브라우저로 직접 보고 확인해요. 화면의 자동 테스트는 없어요(3절 6번).
- 제품이 정한 닫힌 값(계층, 신선도, KG 상태 등)은 `src/data`의 표시 이름 사전에서 한국어로 보이고 원래 값은 툴팁이에요. 속성 이름과 값, 타입 이름은 모델의 데이터라서 영어 그대로예요.
- 객체 테이블의 속성 컬럼은 행마다 한 번씩 더 불러요. 목록 응답이 속성을 줄 수 있게 되면 `data` 계층의 함수 하나만 바꿔요.
- 개발용 토큰은 브라우저에 저장돼요. 프로덕션 모드에서 화면을 낼지는 제품 책임자가 정해요(지금은 `-web=false`로 꺼요).

## 11. 관련 결정과 요구사항
- ADR-0042(접속 방식, 주소에 담는 상태, 오류 표시, 표시 이름), ADR-0038(데모 모드), ADR-0035(웹 UI의 위치, 기술, 검사, 의존성), ADR-0016(화면은 다른 리포지토리, 이 문서는 그 예외), ADR-0024(개발용 인증), ADR-0027(KG를 읽는 경로).
- REQ-209 임시 콘솔의 성격과 삭제 조건. REQ-275~279 웹 UI의 제공, 생성한 API 계층, 계층과 토큰 규칙, 화면의 데이터 동작, 백엔드의 독립. REQ-296~299 웹 UI의 접속 방식, 주소에 담는 상태, 오류 원인, 표시 이름. REQ-147 모든 기능이 API와 CLI로 돼요.
- 함께 읽을 문서: [REST API 설계](rest-api.md), [자원과 경로: KG·관측·역량 질문·권한·기반](rest-api-resources-graph.md).
